# Как проверить через интерфейс

Войдите **администратором**.

| Что проверить | Куда нажать | Что должно появиться |
| --- | --- | --- |
| **Распознавание PDF** | Главная → **Распознавание PDF** → **Распознать пробный PDF** | «Текст готов» и строка `PRX - PDF recognition is working.` |
| **OCR скана** | На странице **Распознавание PDF** выберите свой тестовый PDF-скан | Текст со скана. Для Tesseract нужны также `pdftoppm` и языки `rus`, `eng` |
| **Воркер без PDF** | Главная → **Монитор воркеров** → **Проверить воркер** | Задача `echo` завершилась; в её карточке видно имя воркера |
| **Старый документооборот** | Главная → **Документооборот** → **Входящие документы** → **Принять пробное письмо** | Обновите страницу: у письма появится ссылка на карточку в реестре. В **Сроках и маршрутах** появится назначение. ИИ-разбор запускается из карточки и требует настроенной локальной LLM |

Пробный PDF и пробное письмо содержат готовый текстовый слой: файлы искать
не надо, но эти два теста **не проверяют OCR сканов**. Ключ интеграции для UI не нужен.

## Если нет раздела «Документооборот»

Это выключенный по умолчанию тестовый режим. **Bootstrap не правим.**

1. В корневом `.env` поставьте `PRX_DOCFLOW_ENABLED=1`. Если воркер на другом
   хосте, укажите `1` и в его `workers/.env`. Оставьте `WORKER_CHANNELS=` пустым;
   если список задан явно, добавьте `doc.normalize,doc.analyze` (и `document.extract`
   для нового PDF-сервиса). Старый `doc.draft` не добавляйте.
2. Примените миграции `bin/console db:migrate` и перезапустите PHP и воркер.
   В Docker: `docker compose --profile workers up -d --build php worker`,
   затем `docker compose exec php bin/console db:migrate`.
3. Обновите главную. Там будут четыре ссылки: `/inbox`, `/documents`, `/analysis`, `/sla`.

Чтобы отключить, поставьте `0` и снова перезапустите процессы (в Docker —
пересоздайте их с обновлённым `.env`). Маршруты и каналы отключатся; таблицы,
файлы и старые задания не удалятся. **Используйте только тестовые документы.**
«Ответы на письма» и удалённое VLM-демо не включаются.

## Если проверка застряла

- **Долго «В очереди»** — откройте монитор и запустите `echo`. Если он тоже
  ждёт, проверьте, что воркер запущен и подключён к той же БД или HTTP-очереди.
- **`echo` готов, PDF ждёт** — проверьте `document.extract` в `WORKER_CHANNELS`.
- **PDF взят, но возникла ошибка** — в карточке задачи видны стадия и код.
  Даже PG-воркеру нужны адрес сайта (`APP_URL` или `PRX120_API_BASE`) и тот же `WORKER_API_TOKEN`,
  что на PHP: он скачивает PDF и сохраняет текст через PHP.

Технические подробности: [контракт API и OCR](integrations/document-extractions.md),
[проверки на стенде](VALIDATION.md).

### Если в журнале `ConnectError` или `worker_endpoint_unavailable`

Если попытка уже была, очередь работает: сбой между Python и PHP, а не в OCR.
На `portal.toolforge.ru` проверьте `APP_URL=https://portal.toolforge.ru`. В обоих
`.env` уберите старые переопределения на `localhost:8080`, если PHP там не слушает.
Затем из `workers/` запустите `.venv/bin/python -m prx_workers --check-site`.
`OK` означает, что PHP принял служебный токен; `401/403` — проверяйте токен и
прокси, `404` — адрес/версию сайта или флаг старого контура, `ConnectError` —
доступность адреса из процесса воркера. После перезапуска запустите **новый**
пробный PDF: задачи с исчерпанными попытками сами не начнутся заново.
