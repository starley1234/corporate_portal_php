# nj580 → «Организация как ядро продукта»: онтология и план развития

*Рабочий документ (2026-09-20). Основание: ОГРН/ОГРНИП/ИНН как универсальный ключ.*

## Зачем

Документы — «точка входа»: пользователь вводит ОГРН → сервис знает организацию →
все модули (документы, 3D, будущие: договоры, отчётность, тендеры) работают вокруг
одного реального юрлица. Это отсекает мусорные «несуществующие» организации,
связывает модули между собой и создаёт актив: **базу организаций с накопленными
данными** (онтология «идеального» и «фактического»).

своей копией справочника и не зависит от внешних лимитов.

## Хранение (сделано / план)

**Сделано (nj580, экстраполяция в модуль-хаб при появлении 2-го потребителя):**
- `nj_580_organizations` — ОГРН (UNIQUE), ИНН, полное наименование, адрес,
  ОКВЭД, руководитель, JSONB profile, источник, updated_at;
- `nj_580_packages.org_id/ogrn` — пакет привязан к организации;
- `nj_580_feedback` — уточнения участников итераций (текст, автор, used_at).

**План (модуль `nj190_orgs` — «хаб организаций», отдельный сервис):**
- `nj_190_orgs` — canonical карточка (источник истины), merge из nj580;
- `nj_190_org_edges` — связи org↔org: (src, dst, тип: учредитель/филиал/поставщик/клиент,
  основание, confidence) — граф организаций;
- `nj_190_org_claims` — «идеальная» модель: пользователь подтверждает/правит поля,
  расхождение «факт из ЕГРЮЛ vs заявлено» хранится, а не затирается;
- `nj_190_org_members` — сотрудники организации (user_id ↔ org_id, роль):
  совместные пакеты, права «команда» вместо «владелец».
- Миграция nj580 → nj190: таблицы переезжают, nj580 оставляет вью/синонимы;
  Service_Nj190_Orgs::find_by_ogrn()/upsert() — единая точка для всех модулей.

## Итерации пакета (совместная работа) — сделан фундамент

1. Участник добавляет «уточнение» на странице пакета (текст, автор, дата).
2. «Пересобрать пакет» передаёт неотмеченные уточнения воркеру (приоритет
   выше прочих пожеланий), после сборки они помечаются «учтено».
3. Следующий шаг: дифф-просмотр двух сборок (content JSONB уже версионировать
   несложно: nj_580_doc_versions(document_id, content, created_at, job_id)).

## Монетизация (естественные точки оплаты)

- **Freemium по пакетам**: N бесплатных документов/мес на пользователя;
  оплата — безлимит + ZIP/Excel + приоритет очереди.
- **Лицензия на организацию (по ОГРН)**: подписка юрлица → все сотрудники
  (nj_190_org_members) работают с общим пакетом, свои бланки/шаблоны, история версий.
- **Официальные выписки**: «выписка ЕГРЮЛ с ЭП ФНС» — себестоимость ≈0 (ФНС
  бесплатно), продаётся как «проверка контрагента» пакета.
- **API для бухгалтерских фирм**: ведут 30–100 организаций → подписка по числу
  ОГРН (ключ = ОГРН), белая выручка без инфраструктурных затрат.
- Данные никому не продаются (доверие = конверсия); выгода — в удержании:
  чем полнее карточка организации, тем дороже уйти.

## Гигиена данных (чтобы не перегреть сервер)

- сырые данные: 100 КБ/пакет, файлы пакетные — замена без дублей (сделано);
- кэш организаций — ~1 КБ/юрлицо (миллионы строк не страшны, JSONB сжимается);
- файлы DOCX/PDF: ретеншн-политика (будущее): пакеты без обращений 180 дней —
  ZIP в холодный tar, строки БД остаются;
- nj_580_usage — агрегаты в админке уже есть; раз в месяц варьзать в monthly.
