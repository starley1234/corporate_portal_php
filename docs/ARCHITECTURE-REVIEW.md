## 1. Целевой контракт модуля

### 1.1 Состав

```
prxNNN_slug/
  AGENTS.md                  # состояние, границы, маршруты, права, сервисы, данные, проверки
  init.php                   # при необходимости маршрутов
  config/
    prx_module.php           # манифест по схеме (make manifest-check)
    prxNNN_slug.php          # настройки модуля
  migrations_pg/             # только при наличии таблиц
    pgMigration_Prx_NNN_001_*.php
  classes/
    Controller/PrxNNN/*.php  # тонкие: actor -> service -> view/JSON
    Policy/PrxNNN/*.php      # объектные правила доступа (Prx_Policy)
    Service/PrxNNN/*.php     # публичный контракт + SQL через Prx_Db
    Model/PrxNNN/*.php       # только простые CRUD/ORM
  views/NNN/*.php            # при наличии UI; без SQL и решений о доступе
tests/Unit/PrxNNN*Test.php   # политика: гость и чужая организация
```

Обязательны AGENTS.md и манифест; остальные каталоги — по необходимости.
Для prx-модулей единственный каталог миграций — `migrations_pg/`.

Генератор: `make new-module id=312 slug=claims name="Заявки" entity=Claim`.

### 1.2 Слои и правила

- **Controller** — без SQL, бизнес-правил и решений о доступе к объекту.
  Только: метод запроса, `$this->actor()->require(...)`, вызов сервиса,
  выбор view/JSON, flash/redirect.
- **Policy** — RBAC + ownership + оргконтекст. Возвращает 403 (нет права на
  модуль) или 404 (чужая запись).
- **Service** — единственное место бизнес-логики и SQL. Публичный метод —
  стабильный контракт. Чужие таблицы не читаются: только публичный сервис
  владельца.
- **View** — получает готовые данные и флаги; не знает ACL, не делает SQL.
- **Manifest** — метаданные для каталога/поиска/health/cleanup/schedule.
  **Не является проверкой доступа.**

### 1.3 HTTP/API

| Тип | Префикс | Auth | CSRF | Ответ |
|---|---|---|---|---|
| Внешний machine API | `/api/v1/<domain>/<resource>` | Bearer-ключ `prx150` + scope | нет | плоский JSON успеха; ошибка `{"error":{"code","details"}}` |
| Внутренний AJAX | `/<module>/api/<action>` | session | да | JSON envelope, 401 JSON для гостя |
| Worker API | `/prxNNN/worker/<action>` | `X-Worker-Token` | нет | JSON, отдельный токен |
| Webhook | `/prxNNN/hook/<provider>` | подпись провайдера | нет | 200 после проверки |
| Страница | `/prxNNN_slug` | session + ACL | да на POST | HTML |

Внешний machine API — не сессия и не ACL сотрудника: потребитель предъявляет
ключ `prx150`, право даёт scope, объём — лимит ключа. Код ошибки один и тот
же на всех модулях: `401 unauthorized`, `403 forbidden|key_revoked|key_expired`,
`429 rate_limited`, `503 service_unavailable`; модуль добавляет свои
`409`, `413`, `415`, `422`, `405`. Каждый ответ несёт `X-Request-Id` (ID
строки журнала) и `Cache-Control: no-store`.

**Почему успех плоский.** Обёртка `{data, error, meta}` — ещё один контракт,
который потребитель должен знать: где данные, где ошибка, что в `meta`.
Плоское тело совпадает с телом шлюза и с телом ошибки, а статус и так говорит
об исходнике успеха. `meta` не нужен: `X-Request-Id` уже в заголовке, ссылка
на статус — в теле (`status_url`), постраничность у машинного API не используется.

- `Idempotency-Key` — для всех создающих внешних операций; реализует
  `Prx_Idempotency` (advisory-lock + TTL), владелец — целочисленный ID ключа.
- `Cache-Control: no-store` — для приватных данных.
- Rate limit — мягкий, по журналу за минуту; точный биллинг — отдельная задача.
- OpenAPI/JSON Schema — на каждый внешний API; contract tests.

### 1.4 Манифест

Обязательные поля зависят от `kind` (`module` | `platform` | `library`) —
таблица в `docs/FOUNDATION.md` §5. Инварианты: `id` = номер папки, `slug` = имя папки, `acl` объявлен в
`application/config/acl.php`, `href` не повторяется. Проверка —
`python3 .tools/manifest_check.py`. Списков модулей в ядре нет.

### 1.5 События

- Доменные события — только `Event::publish('prxNNN.entity.action', [...], $initiator_id)`
  (`application/classes/Event.php`): имя и payload проверяет фасад, payload —
  ID и скаляры, не ORM-объекты; инициатор явный, сессия не читается. Подписчик
  (`Event::listen()` в `init.php`) сам обеспечивает идемпотентность. Публикация
  мимо фасада запрещена линтом в `make check`.
- Пользовательские уведомления — `Service_Prx597_Notify`; событие объявлено
  в `notify.events` манифеста.

### 1.6 Тесты

Минимум на модуль: **unit** (валидация, policy, идемпотентность),
**integration** (миграции + сервис на чистой схеме), **HTTP-smoke** (гость
401, чужая организация 403, своя запись 200, CSRF 403, invalid 400),
**design** (`design_audit.py --module prxNNN`).

## 2. Стиль

- **PHP:** PSR-12 + Kohana-конвенции, массивы `[]`, `<?php echo`, имена
  `Controller|Service|Policy|Task_PrxNNN_*`, таблицы `prx_NNN_name`
  (множественное число), колонки `snake_case`. Запрещены `$_POST`/`$_GET` в
  view и service. Стандартные колонки: `id bigserial`, `created_at`,
  `updated_at`, `created_by`, `organization_id` для org-scoped таблиц.
- **Views:** 120 символов soft limit; `HTML::chars()` для пользовательского
  текста; без `<style>` и инлайн-скриптов, кроме JSON-конфига и `data-*`.
  Повторяющиеся блоки — в `partials/` (page-kit).
- **JS/CSS:** общее поведение — только `PRX.*`; токены и компоненты — в
  `.tools/tailwind/input.css`; имена классов не конструировать из частей;
  после новых классов — `npm run build:css` и коммит `app.css`.
- **Документация:** один модуль — одна памятка `AGENTS.md`; правила не
  дублируются, каждое — в одном источнике; битые ссылки — ошибка линтера.

## 3. Решения владельца (23.11.2026)

| Решение | Принято |
|---|---|
| Дизайн-baseline | **v6 exact** (`required_design_sample`); витрина альтернатив удалена |
| Каркас навигации | **Текущий shell** |
| Гранулярность | **Гибрид**: доменные модули + общие page-kit/контракты; отдельный модуль — только если нужен свой lifecycle/permissions. Цена over-fragmentation известна: 110 модулей удалено (`docs/REMOVED-MODULES.md`) |
| Внешний API | **`/api/v1/<domain>/...`** для machine, `/<module>/api/...` для внутреннего AJAX |
| Доступ к БД | **`Prx_Db` + именованные параметры** для новых модулей; legacy — как есть |
| CI | **Без CI-файла**: проект уходит с GitHub. Гейты локальные — `make check`, `bash .tools/php_check_all.sh` |
| PHPStan | **Отложено** до стабилизации фонда; сейчас работает tree-sitter-разбор и 10 PHP-линтеров |
| Документооборот и ИИ-сервисы | **Проба пера**: не расширять и не зависеть от `prx390`–`prx393`; будут удалены или переделаны |

## 5. План: что осталось (по порядку)

Фундамент заложен; дальше — от «проверить» к «строить». Каждый пункт закрыт,
когда выполнен его критерий.

1. **PHP-стенд — первый запуск всего, что не выполняется в песочнице.**
   phpunit (включая `tests/Unit/PrxFoundationTest.php`), `tests/http_smoke.py`,
   `make new-module id=…` вживую с удалением результата; новые страницы
   (`/prx100/logs`, `/prx208_events`, `/architecture/guide`, `/prx597/admin`)
   глазами — светлая/тёмная, 390 px. Критерий: ни одной красной строки.
2. **Контрактные тесты платформы.** `Prx_Actor` (RBAC, гость), `Prx_Policy`
   (403/404), `Prx_PostGuard` (CSRF, машинный токен, вебхуки), `Prx_Db`
   (identifier, transaction), `Event::publish` (имя, payload, журнал, шина не
   подключена) — на реальном PHP/PostgreSQL. Критерий: новый модуль не пишет свои тесты на это.
3. **Первый реальный модуль по контракту §1** (заявки или HR-процесс из плана):
   scaffold → политика → сервис → v6-страница → тесты. Критерий: найденные
   трения возвращены в scaffold и `docs/MODULE_GUIDE.md`.
4. **Чистка legacy — только при заходе.** SQL в манифестах (`count_sql`/
   `delete_sql`), god-сервисы `prx120`/`prx597`, wildcard-мост `prx208`: менять
   тогда, когда туда всё равно придётся зайти, с тестами из п. 2. События
   уже едины: `Event::publish()` (23.11.2026).
5. **Проба пера `prx390`–`prx393` — решение владельца:** удалить
   (`application/modules/prx39*`, `handlers/prx390_intake/`, `handlers/prx392_analysis/`, `docs/design/`,
   `docs/AI-DOCUMENT-PIPELINES.md`) или переделать по контракту. После удаления —
   обобщить диагностический контекст `ocr_client.py`/`docflow_trace.py`.
6. **Воркеры:** разбиение `base.py`/`queue.py` на жизненный цикл и транспорты
   (`docs/WORKERS.md`, приоритеты), контрактные тесты PG/HTTP сохраняются.
7. **Аудит ассетов:** мёртвые JS/CSS в `public_html/assets`, судьба jQuery legacy
   в `app.js`. Критерий: `design_audit --check` и `js_selector_scan` остаются чистыми.
