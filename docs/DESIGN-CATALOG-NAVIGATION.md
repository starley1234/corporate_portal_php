## 2. Принципы (принимаем как контракт)

1. **Манифест — про «что и как показать»** (href, icon, group, keywords,
   card, title/short). **Жизненный цикл — про «кому и когда показывать»**
   (status, audience). Это разделение убирает дубли и делает управление лаконичным.
2. **Лобби вместо каталога.** Левое меню — быстрый доступ к «своим» N сервисам,
   а не полный реестр. Полный реестр — отдельная автособираемая страница-каталог.
3. **Область поиска видна пользователю.** Ctrl/⌘+K фильтрует текущее меню;
   кнопка «Все» открывает поиск по всему доступному каталогу; поиск в шапке —
   по содержимому сайта. Не назначать одно сочетание двум разным областям.
4. **SEO через физические страницы**, а не только JS: /services, /services/<group>,
   карточка сервиса, sitemap из реестра.
5. **Агент видит больше, чем пользователь** — превью-режим для draft/beta.
6. **Персонализацию даёт браузер**, сервер — опциональная синхронизация позже.
7. **Обратная совместимость**: контракт `set_menu()` и манифестов не ломаем;
   новые поля — со значениями по умолчанию (как уже сделано с `hidden/badge`).

## 3. Модель видимости и жизненного цикла (ядро решения)

Вместо трёх разрозненных ключей (`hidden`, `beta`, `badge`) вводим **два явных**,
обратно совместимых (старые продолжают работать как алиасы):

```php
// config/nj_module.php — расширение
return [
    // ... существующие поля ...

    // ЖИЗНЕННЫЙ ЦИКЛ: draft | beta | stable | deprecated
    // (draft — виден только агенту/админу в превью-режиме)
    'status'   => 'beta',        // дефолт: 'beta', если раньше стоял badge='beta'

    // АУДИТОРИЯ: public | auth | admin | agent
    // public — всем; auth — только авторизованным; admin — админам;
    // agent — только агентам/админам (сервис ещё сырой, пользователям не показываем)
    'audience' => 'public',      // дефолт 'public'
];
```

Матрица видимости (единая функция `Service_Nj110_Catalog::visible_to($user_ctx)`):

| status / audience | public | auth | admin | agent |
|---|---|---|---|---|
| **stable** | ✅ | ✅ | ✅ | ✅ |
| **beta** | ✅ (с бейджем) | ✅ | ✅ | ✅ |
| **draft** | ❌ | ❌ | ✅ (превью) | ✅ |
| **deprecated** | ❌ (со странички уходит в «архив») | ❌ | ✅ | ✅ |

`hidden` остаётся как частный случай `audience='admin'` (админ-страницы вроде
`/nj600/admin`). Агенту включается превью-режим `?agent_preview=1` (или роль
`agent`) — тогда draft/beta видны и интерактивны, но публично не светятся.
Работа агента над сервисом идёт «включённым», при этом сырой модуль скрыт от
пользователей.

## 4. Левое меню — «лобби»

Меню перестаёт быть зеркалом каталога. Состав по умолчанию (автоматически):

1. **Главное** — закреплённые пользователем + автоматические «частые/недавние»
   (считаются по кликам), всего **7–9 пунктов**.
2. **Основные сервисы** — стабильные heavyweight-сервисы, отмеченные в манифесте
   как `pin='menu'` (или попавшие в «быстрый доступ»): НДС, сумма прописью,
   дашборд и т.п. Ещё ~7–9.
3. Ссылка **«Все сервисы →»** — в каталог `/services`.
4. Поле **Ctrl+K/⌘K** фильтрует текущее меню; кнопка **«Все»** рядом ищет по полному каталогу (см. §6).

Что это даёт:
- в сайдбаре всегда ~15–20 строк вместо 54 — лёгкая страница;
- никакой горизонтальной прокрутки и «простыней»;
- пользователь по-прежнему в 1–2 клика/тапах от любого сервиса (через поиск);
- админ-группа «Платформа» и аккаунтные страницы остаются, но свёрнуты за
  пунктом-аккордеоном («Администрирование» / «Аккаунт»).

### Персонализация (браузер, без БД)

`localStorage`-схема `n2j.nav.v1`:
```json
{
  "pinned":   ["/vat", "/json"],
  "hidden":   ["/3d"],
  "recents":  ["/json", "/radar", ...],
  "expanded": ["Разработчику"]
}
```
- «Закрепить» / «Скрыть» — через `…` у пункта меню;
- «частые» — топ по `recents` и частоте кликов (счёт на клиенте);
- сброс — одной кнопкой. Действия мгновенно влияют только на меню пользователя.
- Позже (фаза 4) — необязательная синхронизация на сервер (nextjs-ключи в
  существующей таблице профайла), но для v1 браузерного хватит.

## 5. Отдельная автособираемая страница каталога `/services` (SEO-ядро)

Серверный рендер (без обязательного JS — для SEO и лёгкости), источник — тот же
`Service_Nj110_Catalog`:

- **`/services`** — все *опубликованные* (stable+beta, audience≠admin/agent)
  сервисы, сгруппированные как сейчас, с поиском, количеством, поисковой
  строкой `<title>/<meta>`, хлебными крошками.
- **`/services/<group-slug>`** — страница-хаб группы («Инструменты
  разработчика», «Финансы и расчёты»…) — посадочные под SEO-запросы.
- **`/services/<service-slug>`** (опц., фаза 3) — публичная карточка сервиса:
  title/short/описание/API/статус/ссылка «Открыть». Даёт отдельный SEO-объект
  на каждый сервис + `sitemap.xml` из реестра.

Лендинги `/s/<task>` (nj611, «под задачу») **остаются** — это другой вход,
по задаче, а не по каталогу; они дополняют `/services`, не конкурируют.

## 6. Поиск сервисов: три понятные области

Это не один общий поиск: у каждого поля своя задача, и подписи показывают её.

- **Фильтр меню** — Ctrl+K/⌘K фокусирует поле в сайдбаре; оно фильтрует только
  уже видимые пункты меню. «/» тоже фокусирует это поле.
- **Полный каталог сервисов** — кнопка «Все» в сайдбаре открывает палитру,
  которая получает JSON через `GET /nj110/api/catalog` и ищет по title+short+
  keywords+group. В ней работают стрелки, Enter и Esc; доступны все сервисы,
  разрешённые текущему пользователю.
- **Страница `/services`** — собственное поле фильтрует серверный список групп
  и сервисов; оно работает независимо от меню и палитры.
- **Поиск в шапке** остаётся отдельным: он ищет содержимое сайта, не сервисы.

## 7. Управление админом и агентом

- **Админ** меняет `status` и `audience` в одном месте (ergo218 или отдельный
  экран «Каталог»): draft→beta→stable, public/auth/admin. Клик — и сервис
  появляется/уходит из меню, каталога, поиска и sitemap.
- **erp218** остаётся источником жизненного цикла (у него уже `status` +
  `is_published`): каталог читает статусы оттуда, **манифест** — источник «что
  показать». Синхронизация односторонняя: erg218.status → каталог; если erp218
  не заполнен, берём `status` из манифеста. Кэш каталога (на запрос)
  всплывает/инвалидируется при смене статуса.
- **Агент** работает с `?agent_preview=1` (или ролью `agent`) — видит draft/beta
  как полноценные, не влияя на публичную выдачу. «Сервис сыроват, но агент с ним
  работает» решается именно этим полем, без взлома `hidden`.

## 9. Тех-механизмы (минимально инвазивно)

- Новые методы `Service_Nj110_Catalog`: `visible_modules($ctx)`,
  `catalog_json()`, `menu_items()` перепишется на «лобби»-набор.
  Контракт `set_menu()` и формат пунктов меню не меняются → контроллеры и view
  не трогаем.
- `GET /nj110/api/catalog` (контроллер-тонкий слой над `catalog_json()`).
- `/services` — обычный Controller + View (SSR), данных из того же агрегата.
- JS-палитра — в общем скрипте шаблона (рядом с существующим `nav-search`),
  данные кэшируются в `localStorage` до инвалидации.

## 11. Риски и ограничения (чтобы «ничего не сломать»)

- **Не ломаем контракт `set_menu()`**: переписываем только наполнение
  `menu_items()`, не форматы пунктов, не ACL-фильтр.
- **`hidden`/`badge`/`beta` остаются валидными** (алиасы) — старые манифесты
  работают без правок; new `status/audience` — опциональны.
- **Поиск учитывает права**: не показываем admin/agent-сервис пользователю без
  прав (иначе — утечка «сырых» адресов в UI, косвенно и в логи).
- **SEO**: JS-поиск не заменяет SSR-каталог; `/services` рендерится сервером.
- **Производительность**: реестр кэшируется на запрос (как сейчас `modules()`);
  добавление полей не меняет стоимость.
