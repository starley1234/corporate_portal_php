## Протокол одного модуля

1. Вход: контекст-пак модуля (`make brief m=<модуль>`) + `docs/DESIGN-SYSTEM.md`.
   Эталон (70 КБ) не читать.
2. `python3 .tools/design_audit.py --module <модуль>` — исходные цифры (в сообщение коммита).
3. Перевод:
   - корень `n2j-ds w-full px-3.5 pt-4 pb-16 sm:px-6 lg:px-8`; шапка — `partials/page_header`;
   - кнопки — по ролям; поля, карточки, статусы, таблицы — компонентами;
   - цвета — палитра v6; текст — от 12 px;
   - `confirm/alert` и свои armed-копии → `N2J.*` и `data-n2j-*`; свои `<style>` → компоненты или утилиты.
4. Поведение и договор с сервером не менять: id, `data-*`, имена полей, на которые опираются JS
   и тесты, остаются. Прогнать стенды и тесты модуля (`.tools/njXXX_*`, `npm run test:*`).
5. `npm run build:css`, коммит `app.css`. Посмотреть глазами: светлая и тёмная тема, 1280 и
   390 px; при сомнении — скриншоты владельцу.
6. Готово, когда `design_audit --module` = 0 (законные исключения — комментарием с причиной).
   Модуль вносится в `DONE` в `.tools/design_audit.py` — дальше CI держит его чистым.
7. Один коммит на модуль: «дизайн v6: njXXX — …», пуш в рабочую ветку.
