# nj646_label: грабли с историей (почему код написан именно так)

Это вынос из памятки модуля (`application/modules/nj646_label/AGENTS.md`): там тот же
список, но одной строкой на пункт — чтобы памятка влезала в бюджет и читалась целиком.
Здесь к каждому пункту оставлена ПРИЧИНА: что именно сломалось, как это выглядело у
владельца и почему лечение такое.

Читать стоит, когда правишь соответствующую часть модуля: половина пунктов — это
ошибки, которые уже один раз доехали до продакшена.

- `INSERT … RETURNING` выполняется как `DB::query(Database::SELECT, $sql, FALSE)` и только потом `->current()`. Тип `Database::INSERT` для таких запросов возвращает `[lastInsertId, rowCount]` — именно на этом падал `analyze` (500 `current() on array`).
- **jsonb в `DB::update()->set()` — только через `DB::expr()`.** `_json()` возвращает УЖЕ закавыченный литерал (он для сырых SQL), конструктор экранирует его второй раз → «invalid input syntax for type json» → 500. Образец — `Service_Nj645_Store::run_apply()`; стережёт `tests/Smoke/LabelRunTest.php`.
- **Ответ модели разбирает `webread.json_from_text`, а не свой `json.loads`.** Живая этикетка ломала наивный разбор: обрыв по `NJ646_MAX_TOKENS`, перенос строки внутри строки JSON, проза после объекта. Страховка — `_salvage_composition()` + `result.note`; стерегут `workers/tests/test_nj646_label_parse.py`.
- **Приёмка `worker_result` пишет в лог каждый исход** (403, 404, 500, успех): 03.10.2026 результат фото не доезжал, а записей не осталось. Только `Log_Plain::event()`, НЕ `Kohana::$log->add()` — Kohana сбрасывает буфер на диск лишь при исключении.
- `result.note` — пометка к составу (обрыв ответа, блик, мелкое фото): приёмка обязана её сохранять (`run_apply_worker()`), иначе страница показывает обрезанный состав как полный.

- **Полос нет нигде** (владелец: «полосы убрать везде»): ход виден спиннером и секундомером (`partials/live_status.php`, опции `bar` нет), доля/уровень — числом или точками (шкала вердикта, риск вещества).
- **Оборванный ответ допрашивается, а не только помечается.** `_continue_composition()` — при `finish_reason=length` или незакрытом `composition`, но НЕ при цикле/подозрении на выдумку; бюджет — остаток `NJ646_LLM_TIMEOUT` (два запроса не должны выйти за `timeout_sec` 360 с); сбой допроса не критичен — состав уедет с пометкой.
- **Размер фото важнее промптов, и кадр только УМЕНЬШАЕТСЯ.** Из кадра меньше 800 px модель мелкий шрифт угадывает (воркер пишет это в `result.note`); крупные ужимаются до 1400 px, мелкие остаются как есть — апскейл деталей не создаёт, а токены жжёт (владелец: «зачем увеличиваешь?»). Стережёт `workers/tests/test_nj646_label_image.py`.
- **Цикл модели режется в воркере.** `_loop_cut()` ищет периодичный хвост и оставляет первую копию блока, `_dedupe_items()` снимает полные повторы, `_suspicion_note()` (≥ 8 позиций с одинаковым началом) только предупреждает.
- `trim()` с байтовым списком символов режет multibyte — обрезать через `preg_replace('/…/u')`.
- **JS модуля пишет HTML-строки, поэтому Tailwind-классы обязаны быть целиком в `views/646/js/*.php`** (`core.php` — `window.N646` и `mountLive`, дальше `label.php`/`book.php`/`profile.php`); после правок — `npm install && npm run build:css`, собранный `app.css` коммитится.
- Ожидания JS по API (сверять при правках): `analyze` → `score/verdict/verdict_label/score_label/counts.{risky,avoid}/items[]/unknown[]/advice[]/title/product.{id,name,name_auto,producer,title,icon,score}`; `ingredient` → карточка (`name_ru…source`); `search` → `items[].{slug,name_ru,category,e_code,hits}`; `vote` → `votes.{agree,dispute}`; `status` → `status/result/text/kind/note/transcript`; `photo` → `run_id`; `forget` → `deleted.*`.
- **`Store.php` распилен на трейты** (`Store/*.php`): помощники (`self::db/_all/_json…`) живут в классе, в частях не дублируются; новый метод — в свой раздел. Сверка состава — стенд `nj646_store_split_stand`.
- Сопоставление позиций — по нормализованному тексту и синонимам (`Service_Nj646_Label::find`): новые синонимы сразу улучшают распознавание.
- Лимиты на посетителя считаются по `client_ip` (`Service_Nj100_Ratelimit::client_ip()`), исключение — `study_per_day` (по посетителю).
- **`AND`/`OR` связывают СЛАБЕЕ `=`, `=>` и `?:`.** `$x = A AND B` присваивает результат ПЕРВОГО сравнения (из-за этого `study_queue_state()` звал свежую задачу «зависшей»), а `A AND B ? 'x' : 'y'` печатает `1` (ключ товара получал «|1» у всех производителей). Условие в присваивании и тернарнике — всегда в скобках; стережёт `.tools/php_ternary_lint.py`.
- **Страница разбора показывает СЕГОДНЯШНЕЕ состояние базы, а не снимок.** `items` — снимок на момент разбора; страница берёт карточки по slug (`ingredients_by_slugs`) и пересчитывает совет, снимок — только для удалённых карточек. Доступ: владелец (`analysis_owned`: метка браузера или user_id) и админ; остальным 404.
- **Справочник админки открывается НА ЧТЕНИЕ.** Правка — по карандашу (`#nj646-edit-toggle` → форма `#nj646-edit`), переобучение — кнопкой рядом; после сохранения списки (`synonyms/avoid/sources`) возвращаются в `state.current` массивами, иначе чтение покажет коды одной строкой.
- **Перезапись карточки моделью — только по кнопке «переизучить».** `ingredient_draft($row, $refresh = TRUE)` правит существующую карточку лишь при `source = llm` (ручное и посев не трогаются); флаг едет в задаче и обязан вернуться в результате — иначе приёмка не отличит повторное изучение от первого.
- **Дерево справочника: уровни — SQL-выражения, а не колонки.** Из `catalog_modes()` строятся `GROUP BY`, фильтр ветви и подписи; значение из браузера сравнивается как текст.
- **В списках админки формы НЕ вкладываются.** У строки свои формы («изучить», «игнор»), поэтому панель массовых операций — пустая форма с `id`, а галочки/кнопки связаны с ней атрибутом `form="…"`; листание истории несёт `name="offset"`. Без JS уходит обычным POST и возвращает flash.
- **Сообщения админки — через сессию, не через `?flash=`.** Ссылка с текстом в query позволяла подсунуть странице любую плашку и копила мусор в истории; вид сообщения («ok/warn») без сессии терялся бы после 303. Образец — nj602/nj605/nj606 (`Session::instance()->set('…_flash')` + `get_once()`).
- **`php -S` не перечитывает `.env`.** Значения попадают в `getenv()` при первом запросе и живут до перезапуска `bin/serve`: правка лимита «не действует», пока сервер не перезапущен.
- **Пределы ЗАПИСИ (`raw_text_kb` 64, `result_kb` 256) — страховка колонок, не формы:** режем по байтам (`mb_strcut`), обрезка помечается (`about.cut`, `_cut`) и видна на странице.
- **`_list_sql(array $extra)`** — добавочные колонки только аргументом: приклеенные к готовой строке, уезжают ПОСЛЕ JOIN-ов (`FROM … JOIN …, a.user_id` → 500).
- **Трейты и `php_method_lint`.** Линт видит методы трейтов и `self::` внутри них: без этого распил `Store` давал 448 ложных «метода нет».
- **Фото не едет в payload очереди.** Кадр — файл `<run_id>.<ext>` в `application/cache/nj646_photo` (вне git), задача несёт `photo` и `run_id`, воркер забирает через `/label/api/photo_file`. Удаляем при УСПЕХЕ (попытка может повториться) и старше 6 ч (`photo_gc()`).
- **Пищевая ценность входит и выходит через одну дверь.** Проверка значений — только `About::nutrition_sanitize()` (она же принимает форму), чтение из строки БД — `Store::nutrition_of($row)` (списки берут `SELECT p.*`, и jsonb приезжает строкой), запись — `_nutrition_json()` (пусто = `{}`, иначе в базе заводятся два разных «пусто» и отбор по `nutrition::text = '{}'` промахивается).
- **Промпты требуют алфавит оригинала, но этого мало.** Модель переводила русскую этикетку на английский; `_latin_drift(исходник, ответ)` ловит снос по доле букв и откатывает на `_composition_from_lines_local()`. Порог грубый нарочно: «Вода (Aqua)» и INCI в скобках — не перевод. Правишь промпты — прогони `workers/tests/test_nj646_label_parse.py` (там же проверка, что слова про кириллицу из промптов не пропали).
- **На разбор веществ идёт `Label::composition_block($text)`, а не весь текст.** Человек вставляет всю упаковку; без обрезки «масса нетто», «ГОСТ», «Изготовитель: …» и строки пищевой ценности становились «неизвестными веществами» и уходили в ОПЛАЧИВАЕМУЮ очередь изучения. В `About`/`raw_text` по-прежнему едет полный текст — из него берутся товар, производитель и пищевая ценность.
- **Товар ищется `product_by_key()`, а не `WHERE key = …`.** Ключ считается от названия, название правят руками и уточняет модель; поиск обязан смотреть и в `key_aliases` (jsonb `@>`, GIN-индекс). Стережёт `php tests/mini_runner.php LabelGoods`.
- **Пересчёт «на порцию» → «на 100 г» (`nutrition_per100()`) в базу НЕ пишется.** В карточке остаётся то, что напечатано на упаковке, пересчёт живёт на экране и помечен; порция вне 5–500 г и «1 батончик» — отказ, а не выдумка.
- **Чистка очереди удаляет насовсем.** Правила — `Label::looks_like_service()` (чистая функция, тесты на двух списках: мусор и настоящие вещества), удаление — только после показанного человеку списка и только для строк без карточки (`studied` не трогаем).
- Таблицы создают и миграция, и `Store::ensure_tables()` (модуль поднимается одним pull).

## Булевы колонки: `false` приезжает строкой «f»

PostgreSQL через PDO отдаёт `boolean` строкой `t`/`f`, и `! empty($row['name_auto'])`
истинно ВСЕГДА — даже когда в базе `false`. Поймано 04.10.2026 сразу в двух местах:

- `product_upsert()` считал «имя рабочее» у каждого товара и на каждом разборе откатывал
  название, которое человек поправил руками, к напечатанному на этикетке;
- JSON-LD на карточке товара, наоборот, не выводился никогда — условие «имя не рабочее»
  не выполнялось ни разу.

Лечение одно: любой булев столбец читать через `Store::flag()` (он понимает `t/f/1/0/
true/false`). В вёрстке — считать флаг один раз в шапке вьюхи и дальше пользоваться
переменной.

## Название от модели должно доезжать до карточки товара

Задача `title` отвечает названием для РАЗБОРА (`analysis_title_set`). Пока товар не
переименовывался вместе с ним, карточка оставалась «Печенье и крекер без названия», а
следующий разбор той же этикетки считал ключ уже от настоящего имени, не находил товар и
заводил дубль. Теперь `analysis_title_set()` зовёт `product_name_from_model()`: он меняет
ТОЛЬКО рабочее имя (`name_auto`) и обязательно через переклейку ключа.
