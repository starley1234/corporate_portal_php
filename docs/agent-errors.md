# Сводный журнал ошибок агента

Файл ведётся накопительно: перед новой диагностикой сначала сверять этот список, а новые ошибки добавлять краткой записью с датой и способом обхода. Секреты, токены и содержимое `.env` сюда не записывать.

## 2026-09-21

### PHP runtime без PostgreSQL
- **Симптом:** запуск Kohana/Minion и runtime-проверок завершается ошибкой `Call to undefined function pg_pconnect()`.
- **Причина:** доступный PHP.wasm не содержит `pgsql`/`pdo_pgsql`.
- **Обход:** использовать PHP lint и статические проверки; полноценные DB-проверки выполнять только в Docker/production-like окружении.
- **Не повторять:** не считать HTML-страницу ошибки Kohana успешным запуском `bin/console`.

### OOM при массовом lint
- **Симптом:** запуск 24 параллельных PHP lint-процессов приводит к нехватке памяти.
- **Обход:** запускать lint максимум в 4 параллельных процесса.

### Swoole binary
- **Симптом:** скачивание static PHP 8.4/Swoole asset с GitHub release CDN завершалось `TLS EOF`.
- **Обход:** не блокировать задачу на этом asset; использовать доступный локальный runtime и Docker как основной runtime.

### Legacy route names in erp218
- **Симптом:** часть ссылок в `erp218_module_manager` вела на старые `erp218_index`, `erp218_scanner`, `erp218_api`.
- **Исправление:** ссылки приведены к `/erp218`, `/erp218/scanner`, `/erp218/index/...` и `/erp218/api/...`.
- **Не повторять:** при добавлении страницы сначала сверять зарегистрированный route в `application/routes.php`.

### Digest delivery runtime
- **Статус:** SMTP-доставка после переноса в background не проверена в этой песочнице из-за отсутствия PostgreSQL extension.
- **Что проверено:** синтаксис PHP, схема статусов, worker endpoint и расписание kicker.
- **Что проверить в окружении с БД:** вызов `/nj597/api/outbox` воркером, резервирование `pending → sending`, фактическое письмо, `sent/failed`.

### Предупреждение GitHub о большом файле
- **Симптом:** при push GitHub сообщил о существующем файле размером около 80 MB.
- **Статус:** push успешен; файл не относится к текущим изменениям.
- **Не повторять:** не добавлять новые крупные артефакты в Git; для обязательных больших файлов использовать существующий LFS/внешнее хранилище проекта.

### 2026-09-21 — повторная доставка digest
- **Симптом:** пользователь получил несколько писем вместо одной сводки.
- **Причина:** параллельные worker/cron-вызовы могли одновременно выбрать одинаковые `pending`-строки до перевода их в `sending`; проверка не была атомарно защищена на уровне запуска.
- **Исправление:** `send_digests()` теперь использует PostgreSQL advisory lock `597597`, восстанавливает зависшие `sending` старше 30 минут и пропускает конкурентный запуск.
- **Важно:** письма регистрации, сброса пароля и ручное тестовое письмо не являются уведомлениями nj597 и по-прежнему отправляются отдельно.

### 2026-09-21 — произвольный текст в URL уведомления
- **Симптом:** ссылка 3D-уведомления содержала URL-кодированный OpenSCAD-текст вместо кода модели.
- **Причина:** уведомитель без проверки доверял `payload.code`; один из пайплайнов передавал в этом поле исходный текст.
- **Исправление:** в URL допускается только короткий alphanumeric route-id; при его отсутствии используется корень раздела (`/3d`, `/tasks` и т. п.). Для новых 3D-задач код модели теперь явно добавляется в payload.

### 2026-09-21 — модуль nj604 не был подключён в bootstrap
- **Симптом:** манифест и routes `nj604_news` существовали, но `/news` и пункт меню не появлялись в работающем приложении.
- **Причина:** модуль не был добавлен в `Kohana::modules()`; аналогично отсутствовали новые `nj602_content` и `nj603_kicker`.
- **Исправление:** добавлены `nj602_content`, `nj603_kicker` и `nj604_news` в `application/bootstrap.php`.

### 2026-09-21 — перезапись AGENTS.md инструментом записи
- **Симптом:** при добавлении инструкции `write_file` заменил весь корневой `AGENTS.md`, потому что не является append-операцией.
- **Исправление:** восстановлена версия из `HEAD`, затем инструкция добавлена через append.
- **Не повторять:** для добавления в существующий файл использовать `edit_file` или `bash` с предварительным сохранением исходного содержимого; `write_file` применять только для новых/полностью перезаписываемых файлов.

### 2026-09-21 — зависшие scheduled jobs при проверке контент-конвейера
- **Симптом:** одновременно `nj602.article` и несколько `nj603.kick` оставались в `processing` сотни секунд; LLM не было видно в интерфейсе.
- **Причина риска:** `ensure_tables()` у nj593/nj602/nj603 выполнял DDL в горячем API-пути; четыре слота worker могли быть заняты пинками, ожидающими такие HTTP/DB операции. Статус `processing` сам по себе не подтверждает обращение к LLM.
- **Исправление:** добавлены миграции схем nj602/nj603, DDL автосоздание выключено по умолчанию, для nj602 добавлен явный лог начала LLM-вызова и таймаут 60–360 секунд (по умолчанию 240).
- **Проверка после deploy:** применить миграции, перезапустить worker, смотреть лог `nj602: обращаюсь к LLM`; если строки нет — задача застряла на поиске/RAG, если есть и затем timeout — проверять LLM endpoint и модель.

### 2026-09-21 — настройки nj597 не сохранялись
- **Симптом:** `/nj597` показывал flash «Настройки сохранены», но значения возвращались к прежним.
- **Причина:** `save_prefs()` отправлял `INSERT ... ON CONFLICT` как `Database::SELECT` без `execute()`; запрос не гарантировал выполнение.
- **Исправление:** запрос переведён на `Database::INSERT` с явным `->execute()`.

### 2026-09-21 — резервная доставка digest из пиналки
- **Симптом:** outbox-задача Python могла долго оставаться в `processing`, и сводка не доходила.
- **Исправление:** `nj603` после `sweep_jobs()` теперь запускает `send_digests()` в фоновом cron-проходе; advisory lock не допускает дубли с `/nj597/api/outbox`.

### 2026-09-22 — несовместимый `execute()` в save_prefs
- **Симптом:** отключение email на `/nj597` падало с `Call to a member function execute() on array`.
- **Причина:** в используемом Kohana Database-драйвере `query(Database::INSERT, ..., FALSE)` уже возвращает результат-массив; вызов `execute()` применим не к этому возвращаемому значению.
- **Исправление:** убран `->execute()` из `save_prefs()`, сохранён штатный стиль запросов проекта.

### 2026-09-22 — настройка email визуально не менялась
- **Причина:** checkbox `email_enabled` был `disabled`, если на сервере не определён `EMAIL_DSN`; пользователь не мог изменить сохранённое значение. Дополнительно сохранение не возвращало прочитанное значение для проверки.
- **Исправление:** checkbox теперь всегда отправляется и показывает фактическое значение `nj_597_prefs`; отсутствие транспорта отображается отдельным предупреждением. Сохранение выполняется через `INSERT ... ON CONFLICT ... RETURNING user_id`, после чего flash показывает фактически записанные параметры.

### 2026-09-22 — запись prefs требовала подтверждения, а не общего flash
- **Симптом:** после flash «Настройки сохранены» повторное открытие показывало старые значения.
- **Исправление:** `save_prefs()` переведён на явный UPDATE с fallback INSERT; после записи сервис перечитывает строку и сравнивает все три значения. Контроллер показывает ошибку, если БД не подтвердила изменение, вместо ложного success.
