# Отдел автоматизации: как запускаем задачи, список задач, правила

Готовый каркас для подразделения, которое оптимизирует и автоматизирует процессы холдинга с помощью ИИ.
Это **отдельный проект** для инструмента `arch`: он живёт рядом с архитектурой платформы, но не зависит от неё
и собирается своей командой.

```
dept/
  arch/meta.yaml              разделы страницы: операционная модель · портфель · решения
  arch/model/*.yaml           порядок запуска задач, жизненный цикл заявки, команда и метрики
  arch/portfolio/01-…yaml     как выбираем задачи: критерии, веса, жёсткие стопы
  arch/portfolio/02-ranked    СГЕНЕРИРОВАНО: список задач по баллам
  arch/portfolio/03-map       СГЕНЕРИРОВАНО: карта «балл и скорость»
  arch/portfolio/04-quarter   СГЕНЕРИРОВАНО: план квартала (бюджет часов, решения совета)
  arch/decisions/*.yaml       решения подразделения (ADR)
  portfolio/config.yaml       веса, пороги, настройки модели оценки
  portfolio/*.yaml            карточки процессов — источник истины для портфеля
  reviews/<квартал>.yaml      решения портфельного совета: что взяли, что отложили и почему
  dist/architecture.html      результат сборки (один файл, открывается офлайн)
```

## Команды

```bash
npm install                     # один раз, из корня репозитория

npm run portfolio               # карточки -> балл -> вкладки со списком задач
npm run build:dept              # dept/arch -> dept/dist/architecture.html
npm run check:dept              # проверки модели подразделения (строгие)

node scripts/portfolio.mjs --dir dept --json   # портфель машинно, для отчётов
node scripts/portfolio.mjs --dir dept --check  # проверить карточки, не пересобирая вкладки
node scripts/arch.mjs show --dir dept portfolio/04-quarter  # выжимка плана квартала
node scripts/arch.mjs adr --dir dept --status proposed      # открытые решения
node scripts/arch.mjs snapshot --dir dept Q1                # снимок состояния
node scripts/arch.mjs diff --dir dept snapshots/<снимок>    # что изменилось
```

## Квартальный цикл

Портфель без цикла — это список пожеланий. Цикл состоит из пяти шагов, и каждый оставляет файл,
а не воспоминание о разговоре.

1. **Замер «как было».** По каждой задаче плана: сколько кейсов в месяц, сколько минут на кейс,
   сколько стоит ошибка. Числа пишутся в карточку (`dept/portfolio/*.yaml`). Пока замера нет,
   задача может стоять в плане, но вкладка «План квартала» прямо говорит: «замер нужен».
2. **Оценка.** `npm run portfolio` считает балл и стоимость внедрения по карточкам.
3. **Бюджет.** В `config.yaml` задано, сколько у команды сил: `capacity.fte × hours_per_fte × (1 − reserve)`.
   Скрипт набирает план сверху вниз по баллу, пока не кончился бюджет и не упёрлись в `max_projects`.
4. **Совет.** Люди смотрят расчёт и решают по-своему: `take` / `next` / `pause` / `stop`,
   с причиной и сроком. Решения — в `dept/reviews/<квартал>.yaml`. Расхождение с расчётом нормально:
   расчёт — входные данные, а не приговор; ненормально — решение без причины (скрипт предупредит).
5. **Пересборка и снимок.** `npm run portfolio && npm run check:dept && npm run build:dept`,
   затем `node scripts/arch.mjs snapshot --dir dept <квартал>`. Через квартал видно, что обещали
   и что сделали.

Текущий цикл — `2026-Q1`: 4 задачи в плане на 900 ч из 1152 ч бюджета, 9 в очереди,
1 в паузе, 2 остановлены. Это образец заполнения, а не прогноз: числа в карточках демонстрационные.

Правила, которые скрипт не даёт обойти: неизвестный код задачи или неизвестное решение —
ошибка сборки; решение без причины — предупреждение; перебор бюджета — не запрет, но виден числом
в плане и в отчёте.

## Как адаптировать под свой холдинг

1. **Карточки.** `dept/portfolio/*.yaml` — один процесс = один файл. Замените демонстрационные 16 процессов
   своими: код, название, функция, владелец, объём кейсов в месяц, минуты на кейс, класс данных.
   Числа — только из замера «как сейчас»; заглушки годятся лишь для сравнения процессов между собой.
2. **Веса и пороги.** `dept/portfolio/config.yaml`: веса четырёх критериев, порог «берём в работу»,
   граница «быстрая победа / стратегическая ставка», пригодность классов данных.
   Там же квартальный цикл: `quarter.name` (по нему ищется файл решений), `capacity` (сколько сил
   у команды) и `effort` (из чего складывается стоимость внедрения, если в карточке нет `build_hours`).
3. **Разделы и шлюзы.** `dept/arch/model/01-operating-model.yaml`: если в вашем холдинге другой порядок
   согласований (например, ИБ решает до бизнес-кейса) — правьте схему и таблицу шлюзов, а не документ в вики.
4. **Решения.** `dept/arch/decisions/*.yaml` — правила, которые нельзя обходить. Спорное остаётся
   `proposed`, пока его не закроет человек; это и есть защита от «решили в переписке».
5. **Сборка.** `npm run check:dept && npm run build:dept`, закоммитить `dist/`. CI платформы проверяет
   только корневой проект; для подразделения ту же проверку стоит добавить отдельным job.

## Что здесь важно не сломать

- Сгенерированные вкладки `arch/portfolio/02-ranked.yaml`, `03-map.yaml` и `04-quarter.yaml`
  перезаписываются скриптом — правьте карточки, настройки и файл решений, а не таблицу.
- Карточка без хозяина процесса или без пригодных данных не считается «низким приоритетом»:
  она попадает в паузу с причиной. Это разные вещи, и путать их нельзя.
- Балл — инструмент разговора, а не истина: если он мешает, меняйте веса и карточки осознанно
  и фиксируйте это решением в `arch/decisions/`.
