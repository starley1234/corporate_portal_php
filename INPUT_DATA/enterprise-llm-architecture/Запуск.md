# Запуск: Windows, macOS, Linux

Всё, что нужно — **Node.js LTS** и этот репозиторий. Ни Docker, ни WSL, ни прав администратора.

## Windows: один раз настроить, дальше — двойной клик

1. **Node.js.** Скачайте LTS с [nodejs.org](https://nodejs.org/ru) и установите с галочкой
   «Add to PATH» (стоит по умолчанию). Проверка: откройте PowerShell и введите `node -v` —
   должна показаться версия (18 или новее).
2. **Репозиторий.** `Code → Download ZIP` на GitHub, распакуйте в папку без пробелов в пути,
   например `C:\arch`. Или `git clone`, если git установлен.
3. **Запуск.** Двойной клик по **`start.bat`**. Он поставит зависимости, проверит модель,
   соберёт страницу и откроет её в браузере. Первый запуск — около минуты.

Дальше страница лежит в `dist\architecture.html` — её можно открывать двойным кликом без Node.

## Windows: команды

В том же окне (или в PowerShell из папки проекта):

```bat
arch.bat status                     :: состояние и что делать дальше
arch.bat ask "что делает DLP"       :: ответ со ссылкой на вкладку
arch.bat impact dlp                 :: что затронет изменение
arch.bat hypo                       :: список гипотез
arch.bat invariants                 :: держатся ли правила «чего быть не должно»
arch.bat export tobe/04-guardrails  :: один HTML-файл для смежников (папка exports/)
```

В PowerShell те же команды пишутся с точкой и слешем: `.\arch.bat status`.
Если консоль ругается на `npm`, закройте и откройте её заново — переменная PATH подхватится
после установки Node.

Живая страница на локальном сервере (нужна редко, файл и так работает):

```bat
npm run serve            :: http://127.0.0.1:8765
npm run serve -- --open  :: плюс открыть браузер
```

## macOS и Linux: тоже одной командой

```bash
chmod +x start.sh   # один раз, если скачали ZIP
./start.sh          # установить, проверить, собрать, открыть страницу
```

Руками, если нужно по шагам:

```bash
npm install
npm run check && npm run build   # проверить и собрать
npm run status                   # что есть и что делать дальше
npm test                         # 148 тестов
npm run serve                    # посмотреть в браузере
```

## Ассистент (MCP)

Сервер `scripts/mcp.mjs` даёт ассистенту 8 инструментов: сводка, поиск, влияние, карточки
объектов, гипотезы, вкладки, проверки. Настройка в клиенте с поддержкой MCP:

```json
{
  "mcpServers": {
    "arch-graph": {
      "command": "node",
      "args": ["C:/arch/scripts/mcp.mjs"]
    }
  }
}
```

Путь на Windows — через прямые слеши (`C:/arch/...`), так надёжнее. Проверка без клиента:

```bat
echo {"jsonrpc":"2.0","id":1,"method":"tools/list"} | node scripts\mcp.mjs
```

## Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| `'node' не является внутренней командой` | Node не установлен или PATH не подхвачен — переустановите, откройте новое окно |
| `start.bat` закрывается мгновенно | запустите его из PowerShell — сообщение об ошибке останется на экране |
| Кракозябры в консоли | в `.bat` уже стоит `chcp 65001`; в старом cmd поможет `chcp 65001` вручную |
| `npm install` падает | проверьте интернет и что папка не в `OneDrive`/`Program Files` |
| Порт 8765 занят | `npm run serve -- --port 8766` |
| Страница не обновилась | `npm run build` — она собирается из `arch/`, руками не правится |
| Проверки падают после правки | в выводе указан файл и место; частая причина — незакавыченное `Название: продолжение` в YAML |

## Что запускать каждый день

| Когда | Команда |
|---|---|
| Начать работу | `arch.bat status` |
| Найти, что где описано | `arch.bat ask "<вопрос>"` |
| Перед изменением | `arch.bat impact <объект>` |
| После правки модели | `npm run check && npm run build` |
| Перед коммитом | `npm test` |
| Поделиться разделом со смежниками | `arch.bat export <вкладка или раздел>` — получится один `.html` в папке `exports/`, открывается двойным кликом |
