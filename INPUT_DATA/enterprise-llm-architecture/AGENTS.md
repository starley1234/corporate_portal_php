# Инструкции для агента

Архитектура платформы живёт в `arch/*.yaml` (формат — `docs/FORMAT.md`). Всё остальное — производное.

## Старт сессии (быстро и дёшево)
1. `npm run arch -- status` — размеры модели, покрытие реестром, проверки, открытые гипотезы и готовый список следующих шагов.
2. Прочитай `docs/CONTEXT.md` (краткое описание AS-IS/TO-BE, открытые решения). Больше ничего целиком не читай.
3. Если нет `node_modules` — `npm install`. Затем `npm run arch -- tabs`.
3. Что решено и почему — вкладка «Журнал решений» (`arch/decisions/`); что ещё проверяется — «Гипотезы» (`arch/hypotheses/`).
   План развития движка — `docs/TOOLKIT.md`.

## Как работать (экономно по токенам)
0. **Сначала граф, потом файлы.** Модель — это граф сущностей и связей:
   `npm run arch -- ask "<вопрос>"` (ответ с цитатами), `entity <id>` (карточка объекта и старые имена),
   `impact <id>` (что затронет изменение), `path <a> <b>` (как связаны), `hypo` (гипотезы).
   MCP-сервер `scripts/mcp.mjs` даёт то же самое ассистенту инструментами
   `arch_ask`, `arch_impact`, `arch_entity`, `arch_hypotheses`, `arch_show`, `arch_graph`, `arch_check`, `arch_inventory`.
   Читай YAML только после этого и только нужный кусок.
1. Не читай целиком большие файлы. Ориентируйся командами:
   `npm run arch -- tabs | show <вкладка> [o|d] | node <id|текст> | grep <текст>`.
   Нужна машиночитаемая выжимка — добавь `--json` (`show`, `tabs`, `map`, `ask`, `impact`).
2. Добавить узел/связь: `npm run arch -- add-node …` / `add-edge …` (откат при ошибке). Сложные правки — прямо в нужном `arch/…yaml`.
3. Расставить координаты: `npm run arch -- layout <вкладка> o [--mode auto|missing|zone|flow] [--all] [--dry]`.
4. После правки: `npm run check` (ошибки = стоп), затем `npm run build` и закоммить пересобранный `dist/`
   (CI-проверка «dist/ не устарел» падает, если `arch/` изменён без сборки в том же коммите).
5. Не редактируй `dist/`, `reference/` и `snapshots/`. `src/` — только при изменении движка или оболочки страницы.

## Правила
- Один узел — один `id` в пределах схемы; связи и маршруты ссылаются на объявленные `id`.
- Если связь означает действие, а не просто поток — ставь тип: `{rel: uses | carries | runs_on | enforces}`.
  Без `rel` связь считается потоком (`flow`). Неизвестный тип — ошибка `check`.
- Новому узлу `at` не обязателен; не двигай чужие узлы без нужды. Если задаёшь `at: [x, y, w]`, избегай наложений (check предупредит).
- `kind` только из `kinds` в `arch/meta.yaml`.
- Разделы (слои) заданы в `meta.sections`: `role` (`primary` — целевой, `asis` — текущее, `solution` — прикладной слой, `governance` — управление, куда складываются сгенерированные вкладки) и `locked: true` — раздел заморожен (см. ниже). По умолчанию — `tobe` (целевое) и `asis` (текущее, скрыто).
- Залоченные разделы (`locked: true`) менять нельзя: `check`/`build` сверяют их с `arch/lock.yaml`,
  а `add-node`/`add-edge`/`layout` в них отказывают. Состояние — `npm run arch -- lock --list`;
  поставить/переставить замочки осознанно — `npm run arch -- lock` (первый раз) или `lock --force` (после правок).
- Описание компонента — в `arch/components.yaml`, не дублируй в нескольких местах.
- Один компонент — одна сущность: канонический id в `arch/entities.yaml`, старые имена — в `aliases`;
  в новых схемах ссылайся на сущность через `ref: <id>`. Неизвестный `ref` и занятый `alias` — ошибка `check`.
- Гипотеза — не решение: `arch/hypotheses/NN-*.yaml` (вопрос, варианты, доказательства, итог).
  Открытая гипотеза означает, что опирающаяся на неё часть схемы — предположение; итог переносится в `arch/decisions/`.
- Тексты: `**жирный**`, `` `код` ``; не пиши HTML, кроме `<br>`. Без внешних ресурсов (CDN, шрифты): файл открывается офлайн.
- AS-IS вкладки описывают v1.7.x и не должны превращаться в TO-BE; целевое состояние — только в TO-BE.
- Новые вкладки — файл `arch/<раздел>/NN-имя.yaml` (порядок по имени).
- Вкладка «Карта перехода» собирается из `arch/map.yaml` — править её напрямую нельзя,
  `add-node`/`add-edge` туда тоже не пустят.
- Открытые решения описываются в `arch/decisions/NN-имя.yaml` (`id`, `title`, `status`,
  `context`, `decision`) — а не таблицей в плане внедрения. Из них собирается вкладка
  «Журнал решений (ADR)» в разделе `governance`; список — `npm run arch -- adr`,
  открытые — `npm run arch -- adr --status proposed`.
- Прикладная вкладка (раздел `role: solution`) объявляет `uses: [...]` — узлы платформы,
  которыми пользуется, и при необходимости `via: [...]` — узлы своей схемы, через которые
  разрешены обращения к моделям. Обзор — `npm run arch -- contract`.
- Внешний вид страницы выбирается в `arch/meta.yaml`: `ui.shell: panel | classic`.
  Оболочки — в `src/shells/<имя>/` (`index.html`, `styles.css`, `app.js`), движок схем —
  в `src/js/engine/` и он общий. Меняешь оболочку — проверь обе.
- Инструмент работает с любым каталогом проекта: `--dir <каталог>` (или `ARCH_DIR`).
  Новый проект — `npm run arch -- init <каталог>`; из общего словаря — `init <каталог> --profile <имя>`
  (список: `npm run arch -- profiles`, формат: `profiles/README.md`).

## Инварианты архитектуры (не ломать при правках содержания)
Записаны в `arch/decisions/` как принятые решения (ADR-010, ADR-011) и проверяются `npm run check`
(контракт `via` в прикладных вкладках). Изменить инвариант — значит изменить решение: правится
`arch/decisions/*.yaml`, а не только текст документации.
- Regex-DLP строго синхронный; `BLOCK` запрещает вызов модели.
- Guard-проверки идут параллельно генерации, но ответ не выдаётся клиенту до вердикта Response Gate; ошибка/таймаут ≠ allow (fail-closed для чувствительных маршрутов).
- Для cloud-маршрутов спекулятивный старт не предотвращает передачу текста провайдеру: confidential-данные — preflight до LiteLLM либо local-only.
- Логи и метрики не содержат сырых промптов, PII, ответов и секретов.

## Второй проект: `dept/`

`dept/` — самостоятельный проект для того же инструмента (операционная модель подразделения,
портфель процессов, ADR подразделения). Он не участвует в проверках корневого `arch/`.

- Сборка: `npm run build:dept`, проверки: `npm run check:dept`.
- Портфель: карточки `dept/portfolio/*.yaml` — источник истины; `npm run portfolio` пересобирает
  вкладки `dept/arch/portfolio/02-ranked.yaml`, `03-map.yaml` и `04-quarter.yaml` (генерируются, руками не правятся).
- Квартальный цикл: бюджет сил — `capacity` в `dept/portfolio/config.yaml`; решения совета (`take | next |
  pause | stop` + причина) — `dept/reviews/<quarter.name>.yaml`. Неизвестный код или решение валят сборку,
  решение без причины — предупреждение, перебор бюджета виден числом в плане.
- Смысл и границы — `docs/DEPARTMENT.md`, устройство каркаса — `dept/README.md`.

## Инварианты и выгрузка
- `npm run arch -- invariants` — правила `arch/invariants/*.yaml` («чего быть не должно»): где нарушены.
  Нарушение с `severity: error` валит `npm run check`. Новое правило — файл с `id`, `title`, `rule`
  (`no-bypass` | `no-edge` | `reachable`), `tabs`, `from`, `to`, `through`, `why` (формат — `docs/FORMAT.md`).
- `npm run arch -- controls [--missing]` — требования `arch/controls/*.yaml` и чем они обеспечены.
  Пробел (`satisfied_by: []`) — не ошибка: это решение, которого ещё нет. Не закрывай пробел фиктивным
  компонентом: либо найди настоящий, либо оставь `note`.
- `npm run arch -- graph --cypher --out <файл>` — выгрузка графа в Neo4j (идемпотентно, `MERGE`).
- `npm run arch -- export <вкладка|раздел> [--out файл]` — один самодостаточный HTML для смежников
  (по умолчанию `exports/<slug>.html`, в git не коммитится). Выгрузка отменяется, если в модели есть ошибки.

## Проверки
`npm run check` — модель (ошибки и, с `--strict`, предупреждения = код 1).
`npm test` — тесты компилятора, раскладки, сборки и CLI. Меняешь код инструмента — добавь тест.
