## Назначение
«Плоские иллюстрации» (`/draw2d`): описание темы словами (и/или фото) →
python-воркер собирает векторную сцену (прямые, кривые Безье, заливки) →
SVG-холст в браузере даёт править руками, хранить ревизии и публиковать в
каталог. Младший брат nj667_graph3d: та же схема «проект → задача nj120 →
ревизии → модерация → каталог», но в 2D и без OpenSCAD.

## Ключевые классы
| Класс | Роль |
|---|---|
| `Service_Nj668_Draw2d` | единственная дверь в модуль: проекты, ревизии, лимиты, постановка задач, модерация, идеи |
| `Service_Nj668_Scene` | нормализация и рендер сцены: `shapes[]` → SVG, валидация фигур и цветов |

| `Controller_Nj668_Worker` | приёмная воркера `/draw2d/w/*` (токен) |

## Таблицы (полное владение)
- `nj_668_projects` — проект: `code` (`[23456789a-z]{8,24}`), `user_id`/`visitor_uid`,
  `title`, `summary`, `tags`, `kind`, `status` (draft/review/published/rejected),
  `featured`, `scene_json` (`{shapes:[…]}`), `prompt`, `shapes_count`, `model`,
  `error`, `remix_of`/`remixes`, `views`, `job_id`, `deleted_at`.
- `nj_668_revisions` — история правок проекта (снимки сцены).
- `nj_668_idea_presets` — пресеты идей для кнопки «Идеи» (собирает воркер).
- `nj_668_settings` — настройки модуля (модель и т. п.), одна строка.
- Чистка (манифест `cleanup`): проекты и ревизии старше 180 дней.

## Маршруты и API
- `GET /draw2d` — витрина; `GET|POST /draw2d/create` — новая иллюстрация
  (право `nj668.start`: `admin`, `vip`); `GET /draw2d/projects` — мои работы;
  `GET /draw2d/catalog` — публичный каталог.
- `GET /draw2d/p/<code>` — рабочее место (только владелец);
  `GET /draw2d/c/<code>` — просмотр опубликованного.
- `GET|POST /draw2d/ideas`, `GET|POST /draw2d/moderate` — право `nj668.moderate`.
- `POST /draw2d/api/{create,generate,save,publish,delete,status,moderate}` —
  аккаунт + `csrf`; `GET /draw2d/api/preview` — SVG сцены;
  `GET /draw2d/api/ideas` — три случайных пресета.
- `POST /draw2d/w/{context,scene,fail,ideas}` — воркер, токен `Gate::worker_request()`.

## Правила, которые нельзя нарушать
1. Сцена — только `shapes[]` через `Service_Nj668_Scene`: ответ модели
   нормализуется и режется по `max_shapes`, цвета и координаты валидируются;
   «сырое» SVG от модели не принимаем и не храним.
2. Чужой проект недоступен: правки — `owns()`; публично — только `published`.
3. Опасные действия (удалить, отклонить) — `data-n2j-arm` вторым нажатием,
   без `confirm()`.
4. Лимиты и rate из конфига, а не из констант в контроллере.
5. Воркер отчитывается на `/draw2d/w/*` только с токеном; результат пишет
   сайт (валидация сцены на стороне PHP), а не воркер напрямую в БД.

## Не трогать / подводные камни
- `reconcile` в манифесте считает задачу выполненной по `job_id = 0` и
  непустым `shapes` — при смене схемы хранения сцены править и его.
- Код проекта без `0`/`1` (алфавит как у nj667) — маршруты это проверяют.
- `Controller_Nj668_Api` наследует `Controller`, не `Controller_Erp100_Base`.
