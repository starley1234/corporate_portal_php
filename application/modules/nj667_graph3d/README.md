# nj667_graph3d — Графовый 3D-конструктор

Карта модуля: куда смотреть и что не разносить. Правила и запреты — в `AGENTS.md`.

Страницы: `/graph3d`, `/graph3d/create`, `/graph3d/projects`, `/graph3d/catalog`,
`/graph3d/p/<code>`, `/graph3d/c/<code>`, `/graph3d/d/<code>` (чертёж),
`/graph3d/b/<code>` (изделие: 3D-модель в браузере, спецификация, чертежи
узлов; печатные файлы — STL).

На `/graph3d/create` три режима: обычный граф по описанию/фото через LLM;
«Простой» — один из четырёх локальных каркасов (куб, табурет, ферма, домик)
без LLM; «Простой (для пользователя)» — описание → граф → автоматическая
сборка `flat` и STL узлов. Начальная LLM-генерация доступна с правом
`nj667.start` (роли `login`, `vip` или `admin`); после принятия графа воркер
пишет состояние в `settings_json`,
ставит в очередь модель и детали, а страница проекта сама открывает сборку.

Вкладка «Простой (для пользователя)» намеренно тихая: без поясняющей плашки
про STL и без заголовка над полем описания, фото изделия — компактной
кнопкой-ссылкой рядом с этим полем (одно фото обычному пользователю, до
четырёх — модератору), кнопка отправки зелёная.

## Три сервиса, одна дверь

Контроллеры, вьюхи и стенд зовут **только** `Service_Nj667_Graph3d::*`.
Так не разъедутся вызовы, если чистый граф переедет ещё раз.

| Файл | Что внутри | Когда открывать |
|---|---|---|
| `Graph3d.php` | проекты, ревизии, публикация, очередь, фото, RAG, доступ; короткие делегаты на Graph/Drawing | БД, права, воркер, настройки |
| `Graph.php` | `graph_clean`, `graph_validate`, RFC 6902, `graph_merge`, `svg_preview` | мусор от модели, патчи, превью |
| `Drawing.php` | ортогонали, штамп, SVG/CSV; размеры из координат | чертёж `/graph3d/d/<code>` |
| `Build.php` | посадки и пазы, union-find кластеры, сигнатуры и дедупликация, лист раскроя, `.scad`, CSV, чертёж типа, `stl_stats` | не та спецификация, посадка, `.scad` |

Четвёртый сервис не нужен: фото и очередь живут рядом с проектами.
Конфиг (`canvas`, лимиты, типы узлов и профиль квот) читает дверь; Graph её
спрашивает, чтобы не копировать `config()`.

Серверные лимиты разрешаются одним `Service_Nj667_Graph3d::quota_limits()`:
сейчас профиль `registered` задаёт 5 платных операций `generate`/`inpaint` за
UTC-день, 5 активных проектов, 3 сохранённые ревизии плюс текущую и до 30
типов деталей за один запуск. Модератор с ACL `nj667.moderate` меняет
индивидуальные значения проектов и LLM/сутки на `/graph3d/limits` — плотной
таблицей с поиском, порядком (`новые`, `старые`, `по имени`, `кто менялся
последним`) и размером страницы (30/50/100/200): страница рассчитана на сотни
людей, поэтому расход по всей странице считается двумя запросами, а не двумя на
строку; пустое поле
наследует профиль, а сохранённые overrides применяются тем же серверным
резолвером. Ручное сохранение и экспорт дневную квоту не расходуют. API
самостоятельно проверяет дневной лимит и ACL `nj667.moderate` для LLM-правок
существующего графа; начальное создание остаётся за `nj667.start`. На новом
развёртывании нужны миграции 012 (дневной счётчик), 013 (границы запуска деталей)
и 014 (индивидуальные квоты, аудит запросов файлов и тип рендера сборки).

## Что менять где

- Сломалась нормализация графа / AI-Guard / undo-патч → `Graph.php`, стенд.
- Не те размеры на чертеже, не те виды → `Drawing.php`, стенд `чертёж:`.
- Узел не туда лёг в пачке, не тот статус → `Graph3d.php` (`build_parts_*`) +
  таблица `nj_667_build_parts`, стенд `план:`/`scad узла:`.
- Не та посадка/раскрой/число деталей → `Build.php`, стенд `сборка:` (это
  считается на PHP, и только потом уезжает в OpenSCAD).
- Узел выглядит не так → `scad/node_types/<тип>.scad`; режим вывода →
  `scad/generators/assembly.scad`. Файл `scad/` не знает про базу и про
  человека: только параметры и данные из `NODES/EDGES/CL/CTYPE/UNIQ`.
- Очередь, ревизии, публикация, фото на диск → `Graph3d.php`.
- Текст страницы, кнопки, форма → `views/nj667/` + `Controller_Nj667_Graph3d`.
  Вьюхам с произвольными значениями Tailwind (`xl:grid-cols-[minmax(300px,…)]`)
  нужен `npm run build:css`: в репозитории лежит собранный `app.css`, и без
  пересборки класса в нём нет — грид молча не применяется, а вёрстка выглядит
  «как раньше». Проверяется `python3 .tools/tailwind_classes_lint.py`.
- JSON API → `Controller_Nj667_Api` (метода `$this->can()` нет).
- Холст, гизмо, спиннер, день-ночь → `nj667-graph3d.js`.
- Промпт модели, JSON воркера → `nj667_graph3d.py`.

## Сборка: кто что считает

```
граф (jsonb) → Service_Nj667_Build → спецификация + .scad → воркер (openscad)
     ↑                    ↓                                        ↓
  правка на холсте   страница /graph3d/b/<code>  ← GLB в браузер, STL в слайсер
```

* PHP: единицы и оси (`[x, -z, y] · unit_size`), пазы и упоры, сращивание
  пересекающихся узлов в одну деталь (union-find по `2·r_in + merge_gap`),
  сигнатура узла (число лучей + углы, шаг 0.5°) и дедупликация типов, лист
  раскроя (`len - 2·r_in + 2·insert`), проверки собираемости.
* OpenSCAD: только геометрия — `core/` + `node_types/<тип>.scad` +
  `generators/assembly.scad`, данные приходят строками `NODES/EDGES/CL/CTYPE/UNIQ`.
  Никакого `echo()` и никакой математики графа: иначе цифры страницы и модели
  разойдутся независимо.
* Воркер: `nj667.build` берёт `.scad` у сайта и вызывает `scad.py`. Обычная
  задача (`render_kind=glb`) временно рендерит STL/VRML, конвертирует результат
  в GLB и сохраняет только GLB изделия. Ошибка конвертера или приёмки не
  запускает STL-fallback. Полный STL — отдельная задача (`render_kind=stl`),
  доступная только модератору с ACL `nj667.moderate`; она сохраняет только STL.
  Старые задачи `render_kind=legacy` до миграции 014 сохраняют прежний протокол,
  чтобы безопасно завершить очередь. Если GLB отсутствует, зарегистрированный
  пользователь может запросить собственный GLB-job: он создаёт отдельную
  сборку в проекте, копирует параметры выбранной сборки и не перезаписывает
  исходную. После успешной постановки задача регистрируется в
  `nj_667_build_file_requests`; открытие страницы и скачивание не считаются.
  Автор этой пользовательской сборки может отдельно поставить STL-узлы в очередь;
  такие запросы тоже учитываются там (миграция 015). Нет бинаря — `no_engine`, и
  страница предлагает забрать `.scad`. Тот же канал
  с `kind=parts` рендерит пачку:
  по одному STL на уникальный тип (`?part=N&file=stl`), бюджет общий — не
  успели, доделайте остаток той же кнопкой; готовые узлы не перерендериваются.
  Лимит пачки (`parts_max`) режет список ПОСЛЕ того, как из него вычтены готовые
  типы. На один пользовательский запуск выбирается не более 30 типов (предел
  профиля и `parts_max`); номер запуска и его набор сохраняются в `parts_run_id`.
  Автопродолжение после короткого бюджета повторяет только выбранный набор и
  не подмешивает новые типы. Остальные запускаются отдельным нажатием после
  завершения текущего.
* Тег скрипта просмотрщика носит `?v=ГГГГММДД` (как `nj510`/`nj644`): правку
  `assets/js/*.js` человек должен получать перезагрузкой страницы, а не чисткой
  кеша — дата в имени забывается обязательно, иначе браузер держит старое.
  Вторая правка в тот же день — буквенный суффикс (`?v=20261013b`).
* Типы узлов нумеруются с нуля: «узла нет» = `part=-1`, а не 0.
* Цвет в 3D даёт только GLB: `glb.py` кладёт в glTF материал «бумага/PLA»
  (`baseColorFactor` в ЛИНЕЙНОМ пространстве, просмотрщик переводит его в sRGB
  — иначе цвет выглядит грязью). STL не несёт цвета; STL деталей предназначены
  для слайсера. Просмотрщик изделия целиком показывает только GLB и не загружает
  полный STL как запасной формат.
* Пачка узлов (`kind=parts`) статус сборки НЕ меняет: `nj_667_builds.status`
  описывает рендер изделия, а отметку о каждом узле несёт своя строка в
  `nj_667_build_parts`. Пометить сборку «done» после узлов — значит показать
  человеку «модель не легла» там, где модель никто не заказывал.
* Результат сверяется с ожидаемым `render_kind`: GLB-job успешен только если
  `glb_path` принят, STL-job — только если принят `stl_path`. Наличие другого
  формата не маскирует ошибку. Старые строки `legacy` продолжают учитывать любой
  из файлов, чтобы не сломать задачи до миграции 014.
* Кнопка «Собрать 3D файлы сборки» появляется у зарегистрированного пользователя,
  когда GLB изделия нет. Запрос создаёт новую собственную строку `nj_667_builds`
  с отдельным id, `graph_hash` и параметрами выбранной сборки, затем ставит
  GLB-задачу; исходная сборка владельца не перезаписывается и не становится
  его текущей — `build_current()` выбирает сборку текущего аккаунта либо
  опубликованную. `nj_667_build_file_requests` учитывает только принятую
  очередью задачу, не открытие страницы и не скачивание. Автор этой сборки
  может запускать и STL-узлы; их очередь учитывается там как `file_kind=parts`.
* «Скачать STL» изделия и отдельный POST для рендера доступны только ACL
  `nj667.moderate`; прямой `?file=stl` тоже защищён на сервере. STL узлов
  к печати остаются отдельными. Обычный просмотр и карточки работают только
  с GLB; если `data-src` пуст, запроса за отсутствующим файлом нет.
* `can_read_build()` дополнительно проверяет публикацию самой сборки: аноним
  не получает страницу, файлы или polling неопубликованной сборки, даже если
  проект публичен. У зарегистрированных пользователей доступ остаётся, если
  сам проект им виден.
* Параметры сборки сохраняются в `params_json`; геометрия идентифицируется
  `graph_hash`/`revision_id`, а файлы лежат в `storage/nj667/<code>/build-<id>.{scad,stl,glb}`.
* Цвет в GLB придумывает не просмотрщик: OpenSCAD пишет `color()` в VRML
  (`.wrl`), `glb.py::parse_wrl` разбирает его в группы, и только потом группы
  склеиваются в glTF. Формат экспорта — ОДИН `Shape` на всё изделие, а краски
  лежат на гранях: палитра `color Color { color [ … ] }` плюс `colorIndex` на
  каждую грань при `colorPerVertex FALSE` (src/io/export_wrl.cc).
  `material/diffuseColor` при этом — константа `0.97647 0.843137 0.172549`,
  жёлтая метка «цвета нет». Кто читает только её, рисует ровно то, о чём писал
  владелец 13.10.2026: «цвета в браузере для модели нет» при полностью готовом,
  принятом и показанном GLB. Метка — не краска: `WRL_DEFAULT_SRGB` превращается
  в `None`, и такие грани едут в бумагу `PAPER_SRGB`. Отсюда порядок
  `("stl", "wrl")` в воркере: нет `.wrl` — нет цвета, модель серая, и это не баг.
* Цвет и пачка упираются в схему БД, и молчать об этом конвейер не имеет права:
  без колонки `glb_path` (миграция 010) сайт вообще не просит у воркера GLB —
  браузер получает STL, то есть серую сборку «со всеми палочками»; без таблицы
  `nj_667_build_parts` (миграция 009) детали к печати не появятся никогда.
  `build_schema_state()` стоит одного запроса на страницу, вьюха говорит об этом
  amber-строкой «накатите миграции (make migrate)», а кнопка пачки отказывает тем
  же текстом, а не тишиной. Проверка на сервере: `\d nj_667_builds` и
  `\dt nj_667_build_parts` в psql.
* Пустого места в окне просмотра быть не может по построению: карточка —
  flex-колонка, холст в ней `flex: 1 1 auto`, а `fit()` в `nj667-stl.js`
  считает дистанцию камеры по fov И по отношению сторон кадра (three.js мерит
  только вертикаль). Фиксированная высота холста плюс «вертикальный» fit =
  модель в углу большого белого окна, то есть «зачем столько пустого места?».
* Действие стоит там, где на него смотрят: кнопка пачки живёт и в шапке
  карточки, и под списком деталей, а статус `spec` читается как «3D-модели ещё
  нет — нажмите «Пересчитать и в 3D»», а не как «спецификация готова».
* От движка зависит, будет ли цвет вообще: `color()` наружу выносит ТОЛЬКО
  выгрузка `.wrl`, а в стабильном OpenSCAD 2021.01 её нет как класса (в `.off`,
  `.amf` и `.3mf` цветов тоже нет). Значит «модель одноцветная» на 2021.01 —
  не баг приёмки, а отсутствие формата: нужен development-snapshot новее.
  Страница говорит об этом прямо и называет переменную `NJ667_OPENSCAD_BIN`.
* Потолок групп — одно число в трёх местах: `build.limits.glb_prims_max` (PHP),
  `MAX_GROUPS` в `glb.py` и `MAX_GROUPS` в `nj667-stl.js`. Стенд сверяет все
  три; разойдутся — цвет начнёт молча пропадать на N-том типе узла.
* Потолок считается по ЦВЕТАМ, а не по солидам: красок в `assembly.scad` девять,
  а гранёных групп OpenSCAD выдаёт десятки. `parse_wrl` раскладывает грани по
  палитре, `glb.merge_by_color` доклеивает совпадающие, и `MAX_GROUPS` проверяет
  уже число цветов — иначе большая сборка падала на лимите, ловила `GlbError` и
  уезжала на сайт серой из STL («цвета в сборке не вижу», 13.10.2026).
* Пачка узлов не имеет права ставить СБОРКУ в `queued`: она рендерит детали, а
  не модель, и «Ждём модель из воркера…» повисло бы навсегда (воркер отвечает
  по пачке отдельно и статус сборки не трогает нарочно). Залипший `queued`
  снимает `Service_Nj667_Graph3d::build_reconcile`: задача не живая — статус
  считается по тому, что лежит на диске.
* Сколько узлов уже на диске — видно в СТРОКЕ СТАТУСА («узлы: 1 из 12»), а не
  плашкой поверх холста: заметка на модели мешала смотреть саму модель.
* «в 3D» в строке пачки смотрит узел по `?part=N&file=stl` сразу, не дожидаясь
  модели изделия: человек видит узел, пока остальные ещё в очереди.
* Чертёж узла (`?part=N&format=svg`) рисует `Build::part_svg`, а не
  `Drawing.php`: у чертежа проекта свои задачи, переиспользовать нечего —
  размерные линии, дуги углов, штриховка и штамп живут локальными `_svg_*`.
  Лист A4 с рамкой (ГОСТ 2.301), план + изометрия (ГОСТ 2.317) + сечение А–А,
  размеры со стрелками и выносными линиями (ГОСТ 2.304) и упрощённый штамп
  (ГОСТ 2.104). План и изометрия масштабируются раздельно, каждый вид подписан
  своим «1:N»: общий масштаб превращает узел с вертикальными лучами в точку.
* Числовые поля формы — на `step="any"`: с шагом `1` браузер отвергает
  собственный дефолт `10`, потому что `min` (`0.001`) не лежит на сетке шага, и
  человек получает «введите 10.001» вместо того, что уже набрал.
* Светлая тема: одних классов `border-gray-300` полю не хватает — Tailwind
  preflight обнуляет рамку (`border: 0 solid`), и поле ввода на белой карточке
  становится белым на белом. С 20.10.2026 (дизайн v6) поля страницы сборки —
  общий компонент `n2j-input` / `n2j-select`: рамка и подложка в обеих темах
  живут в одном месте (`app.css`), класс полю даёт `$in` во вьюхе и JS, который
  переписывает параметры типа. Своего правила в `<style>` больше нет.
* 14.10.2026 — шаги после «цвета в браузере» (переключатель сетки, «пол» под
  моделью, ожидание пачки, архив `?format=zip`) отменены владельцем: revert до
  `aab0235`. Из них оставлена только эта правка темы. Возвращать остальное —

  владельца относятся именно к нему.
