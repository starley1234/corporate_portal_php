## Назначение
«Графовый 3D-конструктор» (/graph3d): описание изделия словами и/или фото
превращается в пространственный граф — узлы-детали и рёбра-связи. Граф лежит
в jsonb и правится на 3D-холсте (three.js): узлы можно тягать с умными
направляющими, выделенное место — достраивать отдельным промптом, любую правку
— откатывать по истории (RFC 6902), а готовое — публиковать в каталог
(пре-модерация выкл по умолчанию, `NJ667_PREMODERATE=1`) и кнопкой
«использовать как шаблон».

Ключевое отличие от картиночных генераторов: источник правды — топология, а не
изображение. Картинку всегда можно перерисовать; геометрию из неё — нет.

Из того же графа на `/graph3d/b/<code>` выходит изделие: тип узла и его сечение
выбирает человек, спецификацию и раскрой считает PHP, воркер в OpenSCAD
рендерит и сохраняет GLB для просмотра. STL всего изделия отдельно запрашивает
только модератор (`nj667.moderate`); STL деталей к печати остаются доступны.
Без OpenSCAD страница всё равно полезна: раскрой, чертежи узлов и .scad остаются.

## Таблицы (полное владение)
- `nj_667_projects` — проект. Ключевое: `code` (адрес), `user_id`/`visitor_uid`
  (владение), `graph_json` (граф целиком), `summary` + `embedding`
  (саммари TEXT и его вектор для RAG; `vector(N)` при pgvector, иначе `real[]`),
  `kind` (`private|public`), `status` (`draft|review|published|rejected`),
  `featured`, `topo_hash`, `remix_of`/`remixes`, `job_id`, `settings_json`
  (сборочные настройки и `simple_flow`), `deleted_at`.
- `nj_667_revisions` — ревизия. `no` (порядковый), `kind`
  (`commit` — патч RFC 6902 в `patch_json`; `milestone` — снимок графа в
  `graph_json`), `author_kind` (`user|ai`), `label`, `deleted_at` (мягкое
  удаление: спрятана из списка, накатка истории её всё равно берёт).
  С миграции 004: `status` (`''|review|published|rejected`) — старые
  заявки-снимки. Новая публикация ревизию не пишет: заявка живёт на
  `nj_667_projects.status`.
- `nj_667_events` — журнал: `submit|publish|approve|reject|feature|unfeature|remix|guard`
  с необязательной причиной.
- `nj_667_builds` — сборка изделия (миграция 008): `project_id`, `revision_id`,
  `status` (`spec|queued|done|published|error`), `type_key`, `graph_hash` (координаты +
  связи: по нему сборка помечается устаревшей), `topo_hash`, `params_json`
  (чем собрать), `spec_json` (что показать: только числа, не геометрия),
  `stats_json`, `render_kind` (`glb|stl|legacy`), `scad_path`/`stl_path`/`glb_path`
  (пути ОТНОСИТЕЛЬНО `storage/`, байты не в базе), размеры, `stl_sha` и
  `glb_size`, `error`, `job_id`, `render_ms`, `done_at`.
- `nj_667_build_parts` — узлы к печати (миграция 009): `build_id`+`part_index`
  уникальны, `status` (`spec|queued|done|published|error`), `copies` (файл всегда один),
  свои `scad_path`/`stl_path`/`stl_sha`, своя `error`. Отдельной строкой —
  чтобы один тип мог упасть, когда остальные уже скачивают.
- `nj_667_quota_overrides` (миграция 014) — индивидуальные значения
  `active_projects` и `llm_operations_per_day`; `NULL` наследует план.
- `nj_667_build_file_requests` (миграции 014–015) — принятые запросы GLB, STL
  изделия и STL-узлов; пользователь, исходная и новая сборки, проект, job и дата.
  Переходы по ссылкам и скачивания не считаются.
- `nj_667_settings` — ключ/значение админки: `model` (провайдер::модель,
  пусто — модель воркера), `photo_max_px` (длинная сторона кадра для
  vision, дефолт 512), `rag` (`1`/`0` — дефолт чекбокса на сборке).

## Маршруты и API
Страницы:
- `GET /graph3d` — витрина
- `GET|POST /graph3d/create` — новая сборка: LLM, локальный шаблон без LLM или
  «описание → граф → автоматическая сборка»; шаблон открыт вошедшим, LLM и
  полный маршрут требуют `nj667.start` (ACL включает роли `login`, `vip`, `admin`)
- `GET|POST /graph3d/projects` — мои проекты (POST — мягкое удаление)
- `GET|POST /graph3d/catalog` — публичный каталог и поиск (`?q=`; POST — remix)
- `GET|POST /graph3d/p/<code>` — рабочее место (POST — откат или мягкое удаление ревизии без JS)
- `GET  /graph3d/c/<code>` — публичная страница графа (каталог)
- `GET|POST /graph3d/d/<code>` — чертёж с размерами (единица мм/см/м, масштаб, PDF/SVG/CSV)
- `GET|POST /graph3d/b/<code>` — изделие: тип узла, посадки, спецификация,
  модель. Обычный рендер хранит только GLB; отдельный STL всего изделия может
  запросить и скачать только модератор с ACL `nj667.moderate`. STL деталей
  (`?part=N&file=stl`) остаётся доступен по прежним правилам. Если GLB нет,
  зарегистрированный пользователь может запросить собственную сборку — она не
  перезаписывает сборку владельца, не меняет его `build_current()` и наследует
  параметры выбранной сборки.
  `?format=scad|csv`, `?file=glb|stl`, `?part=N&format=svg|scad` (SVG — лист
  A4: план, изометрия, сечение А–А, штамп), `?build=ID`. GET страницы, прямые
  URL файлов и polling закрыты для незарегистрированных, когда сборка не
  опубликована, даже если проект опубликован.
- `GET|POST /graph3d/limits` — индивидуальные квоты (проектов и LLM/сутки), только ACL `nj667.moderate`.
  `?q=&sort=new|old|email|changed&per=30|50|100|200&page=N` — поиск, порядок и размер страницы;
  в шапке видно «Найдено N», срез и пагинацию, пустое поле наследует план, ноль запрещает операцию
- `GET|POST /graph3d/settings` — модель, размер кадра и RAG (право `nj667.moderate`)
- `GET  /graph3d/moderate` — панель модератора (право `nj667.moderate`)
- `GET  /graph3d/c/<code>?r=<no>` — публичная страница конкретной ревизии
- `GET  /graph3d/usage` — генерации: превью, промпт, токены, поиск и страницы (`nj667.moderate`).
  Основа — `nj_120_usage` (живёт дольше задач, nj120/005), задача и проект — LEFT JOIN;
  таблица «История по дням» (`?days=7|30|90|366`), клик по дню — `?day=YYYY-MM-DD`
- `GET  /graph3d/p/<code>` чужого проекта с правом `nj667.moderate` — **режим контроля**:
  страница читается, кнопки сборки/отката/удаления скрыты, POST → 403; API-записи
  по-прежнему только владельцу (`Api::_project` → `owns()`)

JSON API страницы (аккаунт + `csrf`):
- `POST /graph3d/api/create` — новый проект и сразу сборка (право `nj667.start`, 5 платных LLM-операций за UTC-день)
- `POST /graph3d/api/generate` — пересобрать существующий граф (владелец + `nj667.moderate`)
- `POST /graph3d/api/inpaint` — достроить выделенное (узлы + глубина; владелец + `nj667.moderate`)
- `generate` и `inpaint` резервируют общую дневную квоту в сервисе; ручное сохранение и экспорт её не расходуют.
- `POST /graph3d/api/save` — сохранить граф после ручной правки
- `GET  /graph3d/api/history` — ревизии проекта
- `POST /graph3d/api/revision` — контрольная точка (`action=milestone`), откат
  или мягкое удаление ревизии (`action=delete`)
- `POST /graph3d/api/publish` — заявка + саммари, вектор и пре-модерация в очередь
- `POST /graph3d/api/moderate` — вердикт модератора (право `nj667.moderate`)
- `POST /graph3d/api/remix` — скопировать чужой граф себе (`nj667.start`)
- `POST /graph3d/api/delete` — удалить проект (владелец; `Controller_Nj667_Api`
  не наследник Erp100 — права через `_can_moderate()`, не `$this->can()`)
- `GET  /graph3d/api/status?code=` — живое состояние для поллинга, включая
  `simple_flow` (состояние автосборки и `build_id`)
- `GET  /graph3d/api/search?q=`, `/catalog?tag=` — поиск по каталогу
- `GET  /graph3d/api/ideas` — три случайных пресета для `/graph3d/create` (без аккаунта)
- `GET  /graph3d/api/preview?code=&r=` — превью графа картинкой (SVG; `r` — номер ревизии)
- `POST /graph3d/api/build` — пересобрать изделие и (render=1) поставить рендер
  в очередь; требует права `nj667.start` и лимитер: минуты CPU — та же монета
- `GET  /graph3d/api/build_status?code=&build_id=` — статус рендера для
  поллинга; доступ проверяет и проект, и публикацию самой сборки. `glb_size`
  определяет готовность просмотра изделия целиком.

Приёмная воркера (`X-Worker-Token`):
- `POST /graph3d/w/context` — граф (или окрестность выделенного), лимиты,
  справочники, похожие графы для few-shot и референс-фото (`photos`: JPEG
  base64 с диска; в jsonb очереди кадров нет)
- `POST /graph3d/w/graph` — принять граф: чистка, AI-Guard, сохранение
  (`merge=1` — достройка); только новый граф запускает `simple_flow`, если он
  заранее включён для проекта
- `POST /graph3d/w/summary`, `/embed`, `/moderation` — саммари, вектор, вердикт
- `POST /graph3d/w/build` — .scad сборки для рендера (текст с диска, не из jsonb);
  `render_kind=glb|stl|legacy` задаёт ожидаемый формат задачи. Новые сборки — GLB,
  STL всего изделия — отдельная модераторская задача; `legacy` оставлен старым job.
- `POST /graph3d/w/build_file` — принять STL или GLB (`kind`; multipart `file`;
  сайт проверяет размер и целость, потом кладёт на диск)
- `POST /graph3d/w/build_result` — итог: `ok`, `error`, `render_ms`

## Очередь
- Каналы:
  - `nj667.generate` — сборка графа по описанию и/или фото (few-shot из каталога;
    кадры — в контексте сайта, не в payload задачи);
  - `nj667.inpaint` — достройка ВЫДЕЛЕННОГО (в модель уезжает окрестность);
  - `nj667.summary` — текстовое саммари графа (поиск по каталогу);
  - `nj667.embed` — вектор саммари (эмбеддинг-модель из workers/.env);
  - `nj667.moderate` — пре-модерация текста (токсичность, мусор, обман).
    Сайт ставит задачу только при `NJ667_PREMODERATE=1`;
  - `nj667.build` — .scad → STL (+ GLB для браузера) в OpenSCAD. Модель НЕ
    зовётся, `model` в
    payload не подставляется (очередь иначе требовала бы выбранный LLM);
    таймаут свой — `timeout.build` (900 с), потому что CSG считается минутами;
  - он же с `kind=parts` — пачка узлов (по STL на тип). Одна задача на все
    типы и свой бюджет `parts_budget_s`: воркер бросает на середине сам, а не
    доедает до kill'а очереди, и недобранное видно по статусам строк.
- Обработчик: `workers/n2j_workers/handlers/nj667_graph3d.py`
- Постановка: `Service_Nj667_Graph3d::queue($channel, $project, $payload)` поверх
  `Service_Nj120_JobQueue::push` (payload всегда содержит `project_id`;
  `model` — выбранная в админке спецификация, если она не пуста)

## Env
Воркер читает `workers/.env` (ключи ниже с пометкой «воркер»); сайт —
корневой `.env` (пометка «сайт»). Без своего блока канал всё равно
живёт: адрес и токен берутся из общих `NJ120_API_BASE` / `WORKER_SITE_TOKEN`,
модель — из модели воркера по умолчанию. Свой `NJ667_MODEL` нужен, только
если сборке графа нужна другая модель, чем остальным каналам.
- `NJ667_MODEL` — «провайдер::модель» для сборки и достройки графа (пусто — модель воркера). Воркер. Если задан, важнее выбора в `/graph3d/settings`.
- `NJ667_LIGHT_MODEL` — дешёвая модель для названия, описания, тегов, идей, саммари и пре-модерации. Воркер и сайт. Пусто — та же, что `NJ667_MODEL`.
- `NJ667_MODELS` — список «провайдер::имя» через «;» для админки (сайт, иначе дефолт в config).
- `NJ667_API_BASE`, `NJ667_SITE_TOKEN` — адрес сайта и токен для воркера
  (по умолчанию берутся `NJ120_API_BASE` и `WORKER_SITE_TOKEN`). Воркер.
- `NJ667_CONTEXT` (8000) — бюджет символов на граф в подсказке саммари. Воркер.
- `NJ667_LLM_TIMEOUT` (300), `NJ667_MAX_TOKENS` (4000) — вызов модели. Воркер.
- `NJ667_FEW_SHOT` (2) — сколько похожих графов показывать модели. Воркер.
- `NJ667_PHOTO_MAX_PX` (512) — длинная сторона кадра для vision. Воркер
  (запасной дефолт; основной — админка `photo_max_px`).
- `NJ667_MAX_NODES` (500), `NJ667_MAX_EDGES` (1200) — лимиты графа (AI-Guard). Сайт.
- `NJ667_CANVAS_RADIUS` (24), `NJ667_SNAP` (0.5), `NJ667_SNAP_PX` (8) — сцена. Сайт.
- `NJ667_RATE_PER_MINUTE` (6), `NJ667_RATE_PER_HOUR` (60) — частотный limiter. Сайт.
- `NJ667_MAX_SUMMARY` (4000) — длина саммари. Сайт и воркер. Колонка TEXT (миграция 006).
- `NJ667_TTL_DAYS` (180) — сколько живут гостевые черновики без движения. Сайт.
- `NJ667_STORAGE_STALE_DAYS` (30) — через сколько дней сборка, которая не последняя и не последняя готовая, становится устаревшей для очистки. Сайт.
- `NJ667_STORAGE_BATCH` (500) — сколько файлов уходит за одно нажатие очистки. Сайт.
- `NJ667_STORAGE_ORPHAN_MIN_AGE` (3600) — секунд, прежде чем файл без строки в базе считается сиротой. Сайт.
- `NJ667_PREMODERATE` (выкл) — пре-модерация перед каталогом. Сайт. Пусто/0 —
  «Опубликовать» сразу `published`, без новой ревизии и без `nj667.moderate`.
  `1`/`true`/`on` — заявка `review` к человеку и канал пре-модерации.
- `NJ667_BUILD_MIN_ANGLE` (22), `NJ667_BUILD_MIN_SPAN` (5) — пороги
  собираемости (угол, пролёт между пазами). Сайт.
- `NJ667_BUILD_MAX_NODES` (400), `NJ667_BUILD_MAX_EDGES` (1200),
  `NJ667_SCAD_MAX_KB` (280 — под лимит `scad.py` в 300 000 символов),
  `NJ667_MAX_STL_MB` (24) — лимиты сборки (свои: рендер дороже правки). Сайт.
- `NJ667_BUILD_TIMEOUT` (900) — секунды на рендер, Сайт (очередь) и воркер:
  держать в ладу, иначе очередь убьёт задачу раньше OpenSCAD.
- `NJ667_OPENSCAD_BIN` — бинарь воркера (по умолчанию общий с nj570); сайт
  смотрит на него только чтобы сказать, ждать ли STL.
- `NJ667_BUILD_MERGE_NODES`/`_SHOW_STICKS`/`_PERFORATION` (1/1/0) —
  геометрические настройки страницы сборки. Параметра хранения STL изделия больше
  нет: обычные задачи сохраняют GLB, полный STL запрашивает модератор отдельно.
- `NJ667_BUILD_PARTS_MAX` (12) и `NJ667_BUILD_PARTS_BUDGET` (3600 с) — размер и
  бюджет пачки «узлы к печати». Сайт.
- `EMBEDDING_MM_*` (общие, `workers/.env`) — эмбеддинг-модель для канала `nj667.embed`

- **В модель уезжает не весь проект** — Достройка (`nj667.inpaint`) шлёт окрестность выбранного узла (`graph_neighborhood`, по умолчанию 1 шаг) плюс саму просьбу.

- **Удаление — маленькая иконка, вторым нажатием** — `confirm()`/`alert()` в браузере не используем.
- **Файлы на диске — отчёт и порции, только админ** — Файлы лежат в `storage/nj667/<code>/`, в базе только путь.

- **three.js — только вендором** — CDN в проекте запрещён (проверка `assets_cdn_lint`).
- **Без WebGL — не пустой кадр** — У владельца уже был пустой WebGL-кадр в nj570 (заметка в nj643_cad).

## Не трогать / подводные камни
Полный список — `RULES.md`, раздел «Не трогать / подводные камни». Главное:
- pgvector: `similar()` дублирует выражение расстояния в SELECT и WHERE;
  размерность и тип колонки (`vector`/`real[]`) фиксируются миграцией, HNSW
  только при ≤ 2000.
- Ревизии: `graph_clean()` нормализует `-0`, порядок операций `patch_diff()`
  (удаления с конца → правки → добавления), `_trim_revisions()` сперва делает
  milestone.
- `Controller_Nj667_Api` наследует `Controller`, не `Controller_Erp100_Base`;
  контроллеры/вьюхи/стенд зовут только `Service_Nj667_Graph3d::*`.
- `$x = a AND b` без скобок — ловушка приоритета; `#nj667-stage` есть только
  на редакторе.

## Как тестировать
- Стенд чистых функций и рендера вьюх (php-wasm, `.tools/phpwasm_stand.mjs`):
  `N2J_ROOT=$(pwd) N2J_STAND_FILES="$(git ls-files public_html/assets/js workers/n2j_workers workers/.env.example application/modules/nj667_graph3d/scad | tr '\n' ':')" node .tools/phpwasm_stand.mjs .tools/nj667_graph3d_stand.php`
  (кроме `.php` копируется всё из `N2J_STAND_FILES` — иначе JS/Python/SCAD-проверки краснеют)
- Тесты воркера: `cd workers && python3 -m pytest tests/test_nj667_*.py -q`
  (рендер STL — с подменённым `scad._run`, бинарь не нужен)
- Просмотрщик (jsdom, парсеры GLB и STL): `node --test tests/Js/nj667_stl.test.mjs`
- Живой рендер (если бинарь стоит): `NJ667_OPENSCAD_BIN=openscad` в `workers/.env`,
  затем `/graph3d/b/<code>` → «Пересчитать и в 3D»
- Логика холста (jsdom): `npm run test:graph3d`
- Проверка PHP перед пушем: `bash .tools/php_check_all.sh application`
- Индекс памятки: `python3 .tools/context_pack.py index application/modules/nj667_graph3d/AGENTS.md --write`
