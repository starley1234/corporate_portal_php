# База знаний (nj560_knowledge) — памятка для агентов

Централизованный комбинированный RAG по наработкам воркеров всех модулей.

## Зачем

- **Не выполнять похожую работу дважды**: `remember()` дедуплицирует по точному
  ключу (sha256 нормализованного текста задачи) и считает повторы;
- **Копить материал**: анализ отзывов (nj540), резюме поисков вакансий (nj550) —
  готовый датасет для будущих пайплайнов, дообучения и аналитики.

## Как устроено

| Слой | Что |
|---|---|
| `nj_560_docs` | записи: source_module, kind, entity_key, content, summary, meta, hits |
| векторы | коллекция `nj560_knowledge` в nj115_semantic (индексация через очередь `semantic.index`) |
| `Service_Nj560_Knowledge` | remember / find_exact / search (текст + семантика) / cleanup |
| `/nj560` (админ) | статистика, комбинированный поиск, удаление, очистка |

## Интеграция

Модуль после успешной задачи воркера (обычно в reconcile):

```php
Service_Nj560_Knowledge::remember('nj550', 'job_search',
    Service_Nj560_Knowledge::make_key($direction.'|'.$city),
    'Вакансии: ...', $summary, [...]);
```

Вызов оборачивать в try/catch — сбой БЗ не должен ломать модуль
(примеры: nj540/nj550).

Разовый перенос уже готовых результатов — кнопка «Собрать сейчас» на `/nj560`
или `Service_Nj560_Knowledge::backfill(100)` (nj550 done-поиски + nj540 done-ответы,
дедуп не даёт задвоить). Дедуп-переиспользование: nj550.create возвращает
готовый поиск, если идентичный выполнен за `dedup_days` (конфиг nj550).

## Правила для агента

Правила для агентов:

- remember() из модулей — только в try/catch; сбой БЗ не ломает модуль.
- Ключ дедупа — sha256 от НОРМАЛИЗОВАННОГО текста задачи (make_key), не сырой.
- Векторная индексация — через очередь semantic.index (HTTP не тормозит);
  семантический поиск — синхронный вызов nj115 (только админка/фоновые задачи,
  не в горячем HTTP-пути пользователя).
- Очистка — cleanup() по retention_days (config/nj560_knowledge.php).
- Не складывать сюда персональные данные: только наработки (тексты задач,
  результаты ИИ, метрики).
