# nj654_similar — Похожие картинки

Свой банк изображений с поиском по смыслу. Форма, отдельный экран результата,
банк и админка — без возврата фокуса к мобильному полю после отправки.

- `/similar` — **поиск**: текст, картинка или и то и другое. По умолчанию
  показывается ОДНА самая похожая картинка (`top_default`), при желании —
  до десяти. Рядом с числом близости стоит человеческая оценка
  («почти то же самое», «похоже», «непохоже»).
- `/similar/result/<id>` — запрос, состояние обработки и совпадения на отдельной
  странице, чтобы мобильная клавиатура не раскрывалась снова; если очередь
  недоступна или не вернула ID задачи, страница показывает ошибку вместо ожидания.
- `/similar/collection` — **банк**: массовая загрузка (до 20 файлов за раз,
  `bulk_max`), правка подписи и текста, удаление по галочкам, отбор по
  подписи и «только мои».
- `/similar/admin` — **админка** (роль admin): два журнала рядом — что люди
  кладут и что ищут, плюс уборка (убрать отмеченное, выбросить несчитанное,
  очистить журнал поисков).

## Как это работает

1. Человек загружает файлы. Каждая картинка **уменьшается до
   `image_max_width` (1024 px) ещё до записи на диск** и ложится в
   `public_html/storage/nj654/ГГГГММ/<sha1>.jpg`. Повторная загрузка того же
   файла отбивается отпечатком (`fingerprint`).
2. Строка банка появляется сразу со статусом `queued`; в очередь уходит
   задача `nj654.embed`.
3. Воркер (`workers/n2j_workers/handlers/nj654_similar.py`) берёт картинку с
   сайта (`POST /similar/api/photo_file`), считает вектор мультимодальной
   моделью и отдаёт его обратно (`POST /similar/api/worker_result`).
4. Поиск: запрос тоже превращается в вектор, а ближайшие элементы ищет
   PostgreSQL (pgvector `<=>` или своя `nj_654_vec_dist`).

Модель — та же, что у `nj653_veclab`, и настраивается там же
(`EMBEDDING_MM_*` в `workers/.env`). Текст и картинки лежат в одном
пространстве смыслов, поэтому слова находят изображение без всяких тегов.

Оформление страниц следует общему дизайн-эталону N2J
(`/pages/required_design_sample`): шапка с крошками, рабочая область 2/3 + 1/3
с блоком-компаньоном, радиусы `rounded-xl`/`rounded-lg`, тач-таргеты 44 px,
удаление в два шага и никаких полос прогресса — только числа.

## Настройки (`config/nj654_similar.php`)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `image_max_width` | 1024 | ширина, до которой ужимается файл перед записью |
| `jpeg_quality` | 82 | качество JPEG при уменьшении |
| `photo_mb` | 12 | предел исходного файла |
| `bulk_max` | 20 | сколько файлов принимать за одну загрузку |
| `top_default` / `top_max` | 1 / 10 | сколько похожих показывать |
| `text_max` | 1000 | длина текста элемента и запроса |
| `per_hour` | 120 | поисков с одного адреса в час |
| `timeout_sec` | 300 | предел задачи воркера |
| `scale` | 5 ступеней | словесная оценка близости |

Все пределы, кроме шкалы и `top_*`, переопределяются переменными
`NJ654_SIMILAR_*`.

## Установка

```
bin/console db:migrate          # nj_654_items, nj_654_queries
```

Каталог `public_html/storage` создаёт `bin/setup.sh`; подкаталог `nj654`
сервис делает сам при первой загрузке. Бэкап покрыт `BACKUP_PUBLIC_DIRS`.

Для воркера в `workers/.env`:

```
NJ654_API_BASE=https://n2j.ru/similar/api
NJ654_SITE_TOKEN=<WORKER_API_TOKEN сайта>
```

## Проверка

```
bash .tools/php_check_all.sh
cd workers && python3 -m pytest tests/test_nj654_similar.py -q
```

Логика и все три вьюхи проверяются без базы и без PHP на машине:
`.tools/nj654_similar_stand.php` (PHP-in-WASM, запуск описан в шапке файла).

## Чем отличается от nj653_veclab

`nj653_veclab` — лаборатория: проверка модели, диалекты запросов, карта
сходства, сравнение пар. Там смотрят НА МОДЕЛЬ. Здесь — рабочий инструмент:
банк картинок и ответ на вопрос «есть ли у меня похожее». Общий код —
клиент модели в воркере; таблицы, хранилище и страницы свои.
