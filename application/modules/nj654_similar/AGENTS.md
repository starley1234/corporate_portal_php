## Назначение
Банк изображений с поиском по смыслу: человек складывает картинки (пачкой) и
тексты, а потом находит нужное описанием или другой картинкой. Младший брат
`nj653_veclab`: та же модель и тот же клиент, но вместо лаборатории — один
простой рабочий инструмент.

## Ключевые классы
| Класс | Роль |
|---|---|
| `Service_Nj654_Bank` | вся логика: файлы, очередь, приёмка, поиск, правка |
| `Controller_Nj654_Similar` | страницы `/similar`, `/similar/result/<id>` и `/similar/collection` |
| `Controller_Nj654_Api` | JSON: статус, картинка для воркера, приёмка |
| `Controller_Nj654_Admin` | `/similar/admin` — журналы и уборка |

Сервис один намеренно: таблиц две, действий мало — размазывать их по трём
классам значит заставить читателя прыгать между файлами ради строки SQL.

## Таблицы (полное владение)
- `nj_654_items` — банк. `status ∈ queued|ready|error`, `embedding` NULL до
  готовности, `file` — путь относительно `public_html/storage/nj654`,
  `fingerprint` — отпечаток дубля (уникальный частичный индекс
  `nj_654_items_print_uidx WHERE fingerprint <> ''`).
- `nj_654_queries` — журнал поисков: что искали, чем и что нашлось (`hits`
  jsonb). Чистится через 90 дней (`cleanup` манифеста).

Колонка `embedding` — `vector(dims)` при наличии pgvector, иначе `real[]` плюс
своя функция `nj_654_vec_dist`. HNSW строится только при `dims <= 2000`:
pgvector шире индекс не умеет.

## Маршруты и API
- `GET /similar` — форма поиска; `POST /similar/find` → 303 на
  `/similar/result/<id>`; старый `/similar?q=<id>` проверяет владельца и
  перенаправляет на тот же экран результата.
- `GET /similar/collection` — банк; `POST /similar/{add,rename,delete}`
- `GET /similar/admin`; `POST /similar/admin/{delete,drop_failed,clear_log}`
  (роль admin)
- `GET /similar/api/status` — `?q=<id>` состояние поиска (только владелец):
  `status/stage/elapsed_sec/found/cards`; без `q` — сколько элементов банка ещё
  считается. Страницу опрашивает движок `654/search_js` и достраивает плитки,
  ничего не перезагружая.
- `POST /similar/api/photo_file` и `POST /similar/api/worker_result` — только
  по `X-Worker-Token` (`Vision::worker_token_ok`)

Форма поиска и операции коллекции работают обычными формами без JS: POST
`/similar/find` отвечает 303 на `/similar/result/<id>`. С JS тот же POST уходит
fetch-запросом (`X-Requested-With`), получает JSON, показывает карточку запроса
и дописывает находки без перезагрузки — страница `/similar/result/<id>` тогда
работает как адрес того же состояния. `654/zoom` отвечает только за просмотр
картинок.

## Очередь
- Канал: `nj654.embed`, постановка через `Service_Nj120_JobQueue::push`
- Обработчик: `workers/n2j_workers/handlers/nj654_similar.py`
- Два вида задач:
  `{"kind":"items","items":[{"id","text","has_image"}, …]}` и
  `{"kind":"query","id","text","has_image"}`
- Приёмка: `{"kind":"items","model","items":[{"id","vector"}|{"id","error"}]}`,
  `{"kind":"query","id","model","vector","elapsed_ms"}`
- Поиск по векторам делает САЙТ (`Service_Nj654_Bank::search`), воркер только
  считает векторы

## Правила, которые нельзя нарушать
1. **Картинка уменьшается ПЕРЕД записью на диск** (`image_max_width`, по
   умолчанию 1024 px). Банк на тысячу снимков с телефона — это гигабайты.
2. **Коллекция общая, права — по `visitor`.** Поиск идёт по всему банку;
   править и удалять можно только своё, админ — любое.
3. **Картинки не ездят в payload очереди.** Воркер забирает их отдельным
   запросом `/similar/api/photo_file`: base64 в jsonb — это мегабайты на
   каждый опрос очереди.
4. **Одна плохая картинка не роняет пачку.** Элемент получает свою строку
   ошибки, остальные попадают в банк.
5. **Отбор `items(['ids' => []])` = «ничего»**, а не «всё»: иначе удаление с
   пустым списком галочек снесло бы случайный элемент.
6. Все изменения — POST + CSRF + редирект 303; файл с диска удаляется только
   когда на него не осталось ссылок.
7. **Поиск не перезагружает страницу.** Нажали «Найти» — форма скрывается
   (значения целы, их возвращает «Новый поиск»), вместо неё карточка запроса
   `654/panel` с неразрывным статус-рядом, находки приезжают плитками в
   `654/results`. **Фокус в поле ввода не возвращается никогда**: движок снимает
   его (`blur()`) и не вызывает `focus()` — на телефоне клавиатура закрывается
   и не закрывает результаты. Новые плитки рисуются из `<template
   data-nj654-tile-tpl>` по якорям `data-nj654-*`, а не второй вёрсткой; это
   проверяют стенд модуля и `.tools/nj654_similar_ui.mjs`.
8. **Вёрстка — по дизайн-эталону** `/pages/required_design_sample`: обёртка
   `w-full px-3.5 pt-4 pb-16 sm:px-6 lg:px-8`, шапка БЕЗ крошек и без ссылок
   на соседние страницы раздела (их даёт `set_module_nav`), рабочая область
   2/3 + 1/3; пределы и важные подсказки остаются рядом с формой, а на телефоне
   колонка продолжается под ней. Скрывать можно только вторичные общие советы.
   Карточки `rounded-xl`, контролы `rounded-lg`, бейджи `rounded-md`,
   тач-таргеты `min-h-[44px]`, таблицы `py-2.5`/`text-sm`, удаление в два
   шага, неразрывный ряд «спиннер + этап + секундомер». **Полос прогресса
   нет нигде** — доля и количество показываются числом. Стенд это
   проверяет: раздел «Дизайн-эталон».

## Банк на сотню картинок
- Плитка: 48 на страницу, миниатюры `aspect-square`, до 8 в ряд (`xl:`).
- Список (`?view=list`): 25 на страницу, подпись и текст правятся прямо в
  строке — форма строки лежит ВНЕ таблицы (`id="nj654-row-<id>"`), потому что
  вложенные формы браузер запрещает.
- Правка одного элемента из плитки — ссылка `?edit=<id>`, панель над списком.
  «Гармошки» внутри плиток не делать: они ломают сетку.
- Отбор, вид и номер страницы едут в скрытых полях (`_whence()` контроллера),
  чтобы после правки человек возвращался на то же место.
- Список — вид по умолчанию; плитка открывается ссылкой `?view=grid`.

## Картинка целиком
- Миниатюру открывает общая вьюха `654/zoom` (модальное окно + делегирующий
  слушатель на `document`). Подключается один раз в конце страницы.
- Открывает любой элемент с `data-nj654-zoom="<url>"` (и необязательным
  `data-nj654-zoom-title`); внутри окна — ссылка «Файл целиком» на сам файл.
- Новых вкладок для просмотра не делать: человек листает находки и
  возвращается к списку по Esc.

## Не трогать / подводные камни
- `fingerprint` считается по ИСХОДНЫМ байтам файла, а не по уменьшенным:
  иначе один и тот же снимок, залитый дважды, не опознается как дубль.
- `has_pgvector()` определяется по `information_schema` и кешируется в
  статике процесса — после ручной миграции перезапустить php-fpm.
- Секция `health` в манифесте не объявлена намеренно: «хвост ошибок» читает
  `COALESCE(finished_at, updated_at, created_at)`, а таких колонок нет.

## Как тестировать

bash .tools/php_check_all.sh
cd workers && python3 -m pytest tests/test_nj654_similar.py -q
# логика + все вьюхи без БД (PHP-in-WASM):

php .tools/nj654_similar_stand.php
# поведение поиска без перезагрузки: та же вёрстка в jsdom

дождаться `status=ready` → `/similar` → поиск словами.
