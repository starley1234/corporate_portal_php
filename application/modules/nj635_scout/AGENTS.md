# NJ-635 · Разведка контрагента (nj635_scout)

## Состояние
- **Сервис** «Разведка контрагента» (`/scout`): единая точка входа в сквозной
  контур проверки контрагента. НЕ собирает данные сам — оркестрирует готовые
  сервисы и хранит только связи артефактов.
- Один вход: домен / название / ИНН / ОГРН → маршрут из 5 шагов.
- Требует входа (`auth: TRUE`): все артефакты привязаны к `user_id`.
- **08.10.2026 — замок «только по аккаунту»** (решение владельца): сервис работает по
  бесплатному аккаунту. Гость вместо рабочей формы видит плашку входа — общий partial
  `application/views/partials/auth_wall.php` через `Gate::wall('scout')`
  (`application/classes/Gate.php`); API отдаёт 401 JSON
  `{ok:false,error:'auth',login:'/auth/login?return_url=scout'}`
  (`application/classes/HTTP/Exception/401.php`). Воркерские точки (`worker-result`,
  `worker-upload`, `photo_file`, `cron-poll`, `webhook`) замок пропускает: у них свой
  `X-Worker-Token`, проверяют его сами. Быстрая проверка `/check` осталась публичной (решение
  владельца), но маршрут разведки `/scout/<code>` — только по аккаунту.

## Быстрая проверка /check (публичная, без входа)
- `GET /check?q=…` — одна строка ввода (название, ИНН/ОГРН, домен, ссылка на
  вакансию) → одна карточка: реквизиты ЕГРЮЛ/ЕГРИП, вакансии компании, сигналы
  по реестру и кнопки «что дальше». Модель НЕ запускается — только данные
  платформы (nj594 + nj642 + связи), поэтому ответ мгновенный.
- `POST /check` с `act=run` — **«полный отчёт» одной кнопкой**: запускает всё
  через владельцев данных (залогинен — сквозной маршрут nj635 →
  nj594 + nj609 + nj591 + nj598; гость — только досье nj598, оно умеет анонимов)
  и приводит на ту же страницу с блоками `views/635/parts/*`. `act=card` —
  только карточка (кнопка «Проверить» на главной). PRG (303): обновление
  страницы не создаёт вторую разведку.
- `GET /check/api/status` — JSON состояния шагов для живого опроса
  (`Service_Nj635_Report::steps_with_html()`): статус, этап, секунды, `rev`
  и готовый HTML блока. Страница опрашивает раз в 4 с и меняет только блоки с
  новым `rev`; когда все шаги терминальные — опрос останавливается и страница
  один раз перезагружается (только если что-то менялось — иначе был бы цикл).
- `Service_Nj635_Report` — `start()`, `ref()`, `query()`, `has_ref()`,
  `state()`, `block()`, `steps_with_html()`, `map_status()`, `mine()`.
  Чужое не показываем: `mine()` повторяет правила доступа владельцев
  (`user_id`, кука, `g:<ubid>`), недоступный шаг рендерится как `locked`.
  Стенд — `.tools/nj635_report_stand.php`.
- Если ФНС на паузе (мягкий лимит nj594), карточка показывает это в `fns` и
  подсказывает «реестр сейчас на паузе» вместо непонятной ошибки.
- `Service_Nj635_Card`: `parse()` (чистая), `build()` (сборка), `signals()`,
  `verdict()`, `vacancy_keys()`, `name_variants()` — сигналы и нормализация
  названий проверяются стендом `.tools/nj635_card_stand.php`, рендер страницы —
  `.tools/nj635_check_view_stand.php`.
- Сеть: единственный внешний вызов — `Service_Nj594_Orgs::refresh()` по явному
  ИНН/ОГРН, которого нет в справочнике (карточка ФНС сохраняется у nj594).
  По пользовательским ссылкам никуда не ходим: ссылка разбирается локально,
  вакансия ищется в своей базе.
- Страница связана с /dossier (кнопка «Сначала быстрая проверка…») и с карточкой
  организации /orgs/<ogrn> (блок «Проверка: сигналы и вакансии»).

## Маршрут (шаги в порядке)
| Шаг | Сервис | Что делает | Автозапуск |
|---|---|---|---|
| Карточка в справочнике | nj594 | ЕГРЮЛ/ЕГРИП: ИНН, ОГРН, статус, руководитель | да (search → link) |
| Под наблюдение | nj609 | суды/банкротства/ЕГРЮЛ раз в неделю | да (add_subject) |
| Профиль сайта | nj591 | сфера, размер, контакты, стек, ЛПР | да (create) |
| AI-досье | nj598 | отзывы, техстатьи, новости, Red Flags | да (create; повтор → ведёт к последнему) |
| Первое письмо | nj592 | холодное письмо по фактам профиля | НЕТ — нужен оффер/аудитория (кнопка) |

Первое письмо не запускается автоматически, потому что требует от пользователя
содержательного ввода (`product` ≥ 3 символа). Остальное стартует сразу при
создании проекта.

## Безопасность
- SSRF-гард для домен-входа (`_is_local_host`): localhost, `.local`/`.internal`,
  приватные IPv4/IPv6 (RFC1918, loopback, link-local, metadata 169.254.169.254).
- Пользовательский ввод — только через `Database::quote`, без `exec`/shell.
- Мягкий лимит маршрутов: `rate_per_minute=3`, `rate_per_hour=30` (по таблице владельца).
- Никакой своей сетевой активности: все данные — из nj594/nj591/nj609/nj598/nj592,
  каждый из которых сам держит свои credit/rate/SSRF-защиты.

## Конвенции
- Данные читаем только через сервисы-владельцы (`Service_Nj594_Orgs`, `_Nj591_Company`,
  `_Nj609_Watchdog`, `_Nj598_Dossier`, `_Nj592_Coldmail`).
- Связь с карточкой организации — `Service_Nj594_Orgs::link('nj635', project_code, org_id, …)`.
- Шаги идемпотентны: при повторном boot пропускаем уже заполненные code-поля.
