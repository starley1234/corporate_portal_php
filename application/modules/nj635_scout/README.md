# nj635_scout — «Разведка контрагента»

Единый вход в сквозной контур проверки контрагента на платформе N2J:

**домен / название / ИНН / ОГРН** → карточка ЕГРЮЛ (nj594) → наблюдение за рисками
(nj609) → профиль сайта (nj591) → AI-досье с отзывами (nj598) → первое письмо (nj592).

## Принцип

Модуль не дублирует логику и данные других сервисов — он оркестрирует их
публичные методы и хранит в одной таблице `nj_635_projects` только **связи**
артефактов (`org_id`, `profile_code`, `subject_code`, `letter_code`, `dossier_code`)
и статус маршрута. Каждый шаг остаётся владельцем своих данных, кредитов,
лимитов и воркеров.

Быстрая часть (`Service_Nj635_Card`, страница `/check`) собирается из уже
собранных данных: реквизиты nj594, вакансии компании nj642 (метод
`for_company_keys`, ключи — домен и варианты названия), связи артефактов и
сигналы по правилам реестра. ИИ на этой странице не запускается — долгие шаги
остаются отдельными сервисами за кнопками.

## «Полный отчёт» на одной странице (`Service_Nj635_Report`)

Владелец: «слишком много кликов по интерфейсам — нужен один экран, который всё
делает и показывает результат». Поэтому `/check` умеет работать не только
карточкой, но и **единым отчётом**:

1. `GET /check?q=…` — карточка сразу (без ИИ и без ожидания);
2. `POST /check` (`act=run`) — одна кнопка запускает всё: у залогиненного это
   сквозной маршрут nj635 (справочник → наблюдение → профиль сайта → досье),
   у гостя — AI-досье nj598 (единственный шаг, доступный анонимам);
3. дальше страница сама опрашивает `GET /check/api/status` раз в 4 с и
   подменяет только изменившиеся блоки (`views/635/parts/{dossier,profile,watch}.php`)
   по отпечатку `data-rev`; когда все шаги терминальные — опрос останавливается
   и страница один раз перезагружается уже с готовым результатом.

Правила, которые здесь важны:

- **одно место правды** — блоки рисуют те же виды, что отдают SSR и опрос,
  поэтому страница и опрос не могут разойтись;
- **чужое не показываем**: у шага nj598 доступ по `user_id`/куке/`g:<ubid>`,
  у nj591 — по владельцу, у nj609 — через `subject_by_code(..., FALSE)`;
  для недоступного шага рендерится `locked` без данных;
- **секунды не в отпечатке**: таймер тикает локально, иначе идущий шаг
  перерисовывался бы на каждом опросе;
- **перезагрузка только при изменениях** — иначе только что открытая страница
  крутила бы перезагрузку бесконечно;
- авто-стоп «зависших» задач (нет пульса ~4 мин, прогресс застыл 10 мин) —
  общий, из `Service_Nj120_JobQueue`, как на страницах владельцев.

## Роуты

| URL | Что |
|---|---|
| `GET /check?q=…` | быстрая проверка: одна строка → карточка (доступна гостям) |
| `POST /check` (`act=run`) | «полный отчёт» одной кнопкой → та же страница с блоками |
| `POST /check` (`act=card`) | только карточка (кнопка «Проверить» на главной) |
| `GET /check/api/status?p=…&d=…&pr=…&w=…` | JSON: состояние шагов + готовые блоки (для опроса) |
| `GET /scout` | форма старта + мои разведки |
| `POST /scout` | создать маршрут (csrf) |
| `GET /scout/<code>` | карта шагов со статусами |
| `POST /scout/<code>` (`act=letter`) | запустить «Первое письмо» |

## Зачем письмо вручную

Холодное письмо требует содержательного оффера от пользователя (`product` ≥ 3
символов) и тона/аудитории. Автозапуск без ввода дал бы пустую или отфутболенную
валидацию — поэтому это единственный шаг, где нужен явный ввод.

## Безопасность

- карточка и AI-досье доступны гостям, профиль сайта и наблюдение — только
  владельцу (в отчёте такие шаги показываются как `locked`/«войдите»);
- `POST /check` — только с csrf; запуск идёт через PRG (303), поэтому обновление
  страницы не создаёт второй разведки;
- коды шагов в адресе — тот же формат, что у страниц-владельцев (8 hex на шаг);
  параметры вычищаются `preg_replace('~[^0-9a-z_]~i')`;
- `/check/api/status` отдаётся с `private, no-store` и не собирает меню модулей
  (страница опрашивает её каждые 4 с);
- SSRF-гард на домен-вход (нет localhost/приватных IP/metadata);
- мягкий лимит маршрутов: 3/мин и 30/час на пользователя (кнопка «Обновить
  отчёт» в шапке отчёта запускает новый маршрут — лимит общий);
- ввод в БД только через `Database::quote`, без `exec`;
- собственных сетевых вызовов нет.

## Env

Ключей не требуется.
