## Назначение
«Многоголосая озвучка» (/multivoice): большой текст превращается в книгу, где
у каждого персонажа свой голос, а текст нарезан на блоки с логическим
завершением. Готовое скачивается одним архивом — `project/` (продолжить) и
`production/` (слушать).

## Таблицы (полное владение)
- `nj_666_books` — книга. Ключевое: `code` (адрес), `user_id`/`visitor_uid`
  (владение), `chars`, `mode` (`auto|search`), `block_min_min`/`block_max_min`,
  `single_block`, `status` (`new|planning|planned|voicing|done|error`), `stage`,
  `progress`, `error`, `job_id`, `settings_json`, `deleted_at`.
- `nj_666_characters` — персонаж. `key` (нормализованное имя — защита от
  двойников), `kind` (`character|narrator`), `gender`, `age`, `voice`,
  `locked` (замочек: модель не трогает), `mentions`, `sort`.
- `nj_666_blocks` — блок. `no`, `chars`, `seconds_est`, `turns_json`
  (реплики: `{speaker, text}`), `status` (`new|voiced|error`), `file`, `bytes`.

Файлы: `public_html/storage/nj666/<code>/` — `source.txt`, `block-NNN.<ext>`,
`audiobook.zip`. Превью голосов: `storage/nj666/_preview/<sha1>.<ext>`.
Текст и звук в базе не лежат.

## Маршруты и API
Страницы:
- `GET  /multivoice` — мои книги и форма новой (работает и без JS: обычный POST)
- `GET  /multivoice/b/<code>` — рабочее место книги
- `GET|POST /multivoice/b/<code>/k/<no>` — просмотр и правка блока
- `GET  /multivoice/f/<code>/<no>` — файл блока (`?dl=1` — скачать)
- `GET  /multivoice/p/<hash>` — превью голоса (sha1 модели+голоса+фразы)
- `GET  /multivoice/zip/<code>` — архив (project/ + production/)

JSON API страницы (аккаунт + `csrf`):
- `POST /multivoice/api/create` — новая книга (право `nj666.start`)
- `POST /multivoice/api/plan` — разбор в очередь (`nj666.start`)
- `POST /multivoice/api/voice` — озвучка блоков в очередь (`nj666.start`)
- `POST /multivoice/api/block_voice` — переозвучить один блок (`nj666.start`)
- `POST /multivoice/api/block` — сохранить title/turns блока (владелец)
- `POST /multivoice/api/settings` — настройки книги (владелец)
- `POST /multivoice/api/character` — правка персонажа; `id=0` — создать
- `POST /multivoice/api/character_del` — удалить персонажа; `to` — кому отдать реплики (пусто → рассказчик)
- `POST /multivoice/api/voice_preview` — превью выбранного голоса (пустое = голос книги)
- `GET  /multivoice/api/status?code=` — живое состояние для поллинга
- `GET  /multivoice/api/voices` — каталог голосов (`?gender=`, `?age=`)
- `POST /multivoice/api/delete` — удалить книгу

Приёмная воркера (`X-Worker-Token`):
- `POST /multivoice/w/context` — текст, настройки, персонажи, голоса, блоки
- `POST /multivoice/w/characters` — слияние персонажей; в ответе `map` (ref → id)
- `POST /multivoice/w/blocks` — принять нарезку; `final=1` закрывает разбор
- `POST /multivoice/w/block` — реплики блока кусками под `NJ665_MAX_CHARS`
- `POST /multivoice/w/audio` — принять звук блока (base64, `part`/`total`)
- `POST /multivoice/w/synth` — запасной синтез на сайте (длинную главу nginx оборвёт)
- `POST /multivoice/w/stage|done|fail|tick` — этап, готово, ошибка, пиналка

## Env
- `NJ666_WINDOW_CHARS` (6000) — сколько знаков текста уходит модели за заход
- `NJ666_LIST_CHARS` (40) — сколько персонажей показывать модели в списке
- `NJ666_LIST_VOICES` (24) — сколько голосов показывать модели для подбора
- `NJ666_CONTEXT` (16000) — примерный контекст модели; окно ужимается под него
- `NJ666_MODEL` — «провайдер::модель» для разбора (пусто — модель воркера)
- `NJ666_SEARCH` (1) — выключатель «утки го»; `NJ666_SEARCH_TIMEOUT` (45)
- `NJ666_API_BASE`, `NJ666_SITE_TOKEN` — адрес сайта и токен для воркера
  (без них берутся общие `NJ120_API_BASE` + `/multivoice/w` и `WORKER_SITE_TOKEN`)
- Сайт: `NJ666_PLAN_TIMEOUT`, `NJ666_MAX_CHARS` (600000), `NJ666_CHARS_PER_MINUTE`
  (950), `NJ666_TTL_DAYS` (30), `NJ666_RATE_PER_MINUTE` (5), `NJ666_RATE_PER_HOUR` (30)
- Синтез на воркере: `NJ665_API_URL`, `NJ665_API_KEY` (те же, что у /voice);
  `NJ665_MODEL` (пусто = `k2-fsa/omnivoice`, поле в API обязательное);
  `NJ666_SYNTH_TIMEOUT` / `NJ665_TIMEOUT` (дефолт 600 с на кусок)

## Правила, которые нельзя нарушать
1. **Длинный синтез делает воркер.** Ключ OmniVoice (`NJ665_API_URL`/`KEY`)
   есть у воркера: глава не сидит в php-fpm, nginx не режет
   `fastcgi_read_timeout`. Кусок — `synth_chunk_chars()` (`NJ665_MAX_CHARS`),
   не `limits.max_chars` книги. Байты сдаются на `/multivoice/w/audio`.
   Превью голоса на странице — сайт (`synth_bytes`), это короткая фраза.
2. **Замочек — священен.** `locked=1` означает, что модель не меняет имя,
   голос и характер персонажа (`merge_character` обновляет только `mentions`).
3. **Модель видит список персонажей целиком.** У контекста 16 000 токенов
   список ужимается по `mentions`, но передаётся в каждом окне: иначе модель
   плодит двойников («Пётр» и «Пётр Иванович» — два человека). Текст реплик
   берётся из исходника: воркер нумерует куски окна (кавычки/тире — «речь»)
   и просит только `assign` (номер → speaker). Иначе модель повторяет
   «начало» в следующем блоке и склеивает автора с прямой речью.
4. **Замер длины блока — в символах, не в секундах.** `estimate_seconds()` и
   `target_chars()` считают по 950 знаков в минуту при скорости 1,0.
5. **Говорящий хранится как id персонажа** (или строка `narrator`); голос
   подставляется в момент озвучки (`block_turns_with_voices`). Поэтому смена
   голоса не требует переразбора книги — только переозвучки блока.
6. **Удаление в интерфейсе — вторым нажатием**, не `confirm()` (решение
   владельца 10.10.2026; образец — `views/665/script.php`).
7. **Чужая книга недоступна**: `Service_Nj666_Multivoice::owns()` проверяется
   на каждой точке (страница, файл, zip, все API).
8. **Запуск — по праву `nj666.start`** (роль `vip` или админ): книга это
   десятки вызовов модели и часы GPU. Правка своей книги — любому владельцу.
9. **Отказ разбора — `/fail` и исключение**, не `{stopped:True}` и не
   `return` после `/fail`: иначе монитор «готово», страница «ждите».
10. **Ручная правка персонажа — только присланные поля.** Смена голоса не
    должна затирать имя, замок и описание. «Рассказчик (…)» — это
    рассказчик, не новое действующее лицо.
11. **«Имя (голос N)» — не новый персонаж.** Голос пишется в поле `voice`,
    не в имя. `name_key` / `fold_aliases()` склеивают такие хвосты.
12. **Select голоса/пола/возраста — уникальные `name`/`id`.** Без них Chrome
    копирует выбранный option по всем одинаковым спискам карточек.
13. **Речь без кавычек — всё равно речь.** «говорит купец: …» режется кодом,
    speaker не оставляем narrator. В синтез у каждой реплики свой `voice`:
    пустой голос OmniVoice меняет сам на абзац.
14. **Удаление книги — иконкой**, вторым нажатием (класс `bg-red-600`, не
    `confirm()`). В БД мягко (`deleted_at`), файлы каталога сразу целиком.
15. **Превью голоса — play/stop** рядом с `<select>` персонажа, без `confirm()`.
    Пустой голос = `default_voice` книги. Синтез через `synth_bytes`, файл в
    `_preview`. **Удаление с переназначением** — отдельно от корзины: `to` в
    `character_del`. Рассказчика не удалять. **Правка блока** на
    `/multivoice/b/<code>/k/<no>`: смена turns сбрасывает status и файл;
    одна смена title — нет.

## Не трогать / подводные камни
- `turns_json` правится SQL по jsonb: удаление персонажа переставляет
  `speaker` через `jsonb_agg(... CASE ...)`, а НЕ выборкой по `WHERE` — иначе
  блок потеряет всех остальных говорящих.
- Формат файла берётся из ответа синтеза (`sniff_format`): просили mp3,
  пришло wav — имя файла ищется по всем расширениям (`block_file()`).
- Книга «одним блоком» всё равно режется на запросы по `synth_chunk_chars()`
  (`NJ665_MAX_CHARS`, не лимит книги 600 000) и склеивается: `concat_audio()`
  (wav — с пересборкой шапки RIFF). Иначе `clean_turns` обрезает главу, либо
  nginx обрывает php-fpm, пока TTS пишет звук.
- Окно текста режется по абзацам (`_windows` в воркере): порезать ровно по
  6000 знаков значит испортить модель половиной фразы.
- `apply_blocks` нумерует от `MAX(no)` книги: воркер шлёт пачками по 5,
  счётчик с нуля давал несколько «главы 1».
- Пустой `turns` в блоке — не ошибка разбора, а сигнал посмотреть логи
  воркера. Битое окно больше не пропускается: куски уходят рассказчику,
  чтобы дыр в книге не было.
- `/multivoice/w/context` при «книги нет» / «нет source.txt» отвечает 200
  `{ok:false, error}`: HTTP 404 — это для site.post_json «маршрут пропал»,
  он ретраит ~2 с. Воркер на отказ зовёт `/fail` и бросает (11.10.2026).
- Подсказка персонажей для модели: `id=5 [рассказчик]: Рассказчик`, а не
  `Рассказчик (рассказчик)` — иначе появляются «Рассказчик (Рассказчик)»
  и «Рассказчик (голос 1)». `fold_aliases()` чистит рассказчика и
  «Принц (голос 2)» на уже живых книгах.

## Как тестировать
- Стенд чистых функций (без БД, WASM-PHP):
  `N2J_ROOT=$PWD node /tmp/phpwasm/phpwasm_stand.mjs .tools/nj666_multivoice_stand.php`
- Живая проверка: создать книгу на `/multivoice`, нажать «Разобрать книгу»,
  дождаться появления персонажей и блоков, озвучить, скачать архив и
  распаковать — ждём `project/project.json`, `project/audio/block-001.*`,
  `production/*.mp3` и `production/playlist.m3u`.
- Воркер (логика разбора и озвучки, сайт и модель поддельные):
  `cd workers && python3 -m pytest tests/test_nj666_multivoice.py tests/test_omnivoice.py -q`
- Воркер: `python3 -m n2j_workers.cli run --channels nj666.plan,nj666.voice`
  (нужен `WORKER_SITE_TOKEN` и доступный LLM-шлюз).
