# nj642_vacancies — «Вакансии компаний»

Следим за страницами **«Карьера», «Вакансии», «О компании»** на сайтах
работодателей: что открылось, что закрылось, с историей и письмом о новых
подходящих вакансиях.

## Зачем

Владелец (26.09.2026): вакансии работодателя — важная и обновляемая информация,
её надо хранить с историей появления и исчезновения, а по вакансиям нужен
отдельный сервис: указать **город** и **направление** и мониторить изменения на
сайтах компаний, с уведомлением письмом.

Владелец (27.09.2026): «режим: только город + направление, компании с сайтами
сервис находит сам — максимально автоматизируем, ориентируемся на онтологию».
Поэтому компании в мониторе **необязательны**: сервис подбирает сайты
работодателей сам и показывает их владельцу с пометкой, откуда компания взялась.

## Режим «только город + направление» (авто)

1. Владелец заполняет город и направление (плюс, при желании, ключевые слова).
   Своих компаний можно не указывать — блок «Свои компании» свёрнут и необязателен.
2. Первый сбор ставится сразу, даже если компаний в мониторе ещё нет
   (`_enqueue` в авто-режиме пустой список компаний не блокирует).
3. Воркер подбирает сайты: сначала `GET /vacancies/api/hints/<code>` — наше
   знание (карта отрасли **nj607** по словам направления и города, профили
   компаний nj591, находки потоков nj606, прошлые сборы nj642, мониторы с тем же
   критерием), затем открытый поиск (`NJ642_VACANCIES_DISCOVER_BUDGET` секунд).
4. Найденное уходит на сайт (`POST /vacancies/api/companies`), попадает в компании
   монитора и видно владельцу: название, сайт, чип «нашлась сама», источник и
   пояснение (`source`, `why`, `found_at`).
5. Компания, у которой вакансии реально прочитаны, добавляется в монитор и при
   обычном сборе (тот же `api_companies`) — список со временем дополняется.
6. Агрегаторы (hh.ru, superjob, 2gis и прочие job-борды и справочники) отсеиваются
   и в подборе: вакансии принимаются только с сайта работодателя.

## Страницы и API

- `GET /vacancies` — форма монитора, мои мониторы и лента вакансий
  (чипы «Активные / Новые / Избранное / Закрытые», поиск, «Строк:» 20|50|100);
- `GET /vacancies/<code>` — один монитор: живой ряд сбора, компании, вакансии;
- `POST /vacancies/api/collect` — сбор созревших мониторов (пиналка nj603);
- `POST /vacancies/api/ingest` — приём вакансий от воркера (`X-Worker-Token`);
- `POST /vacancies/api/companies` — сайты работодателей, найденные воркером сам;
- `GET /vacancies/api/hints/<code>` — кандидаты в компании из нашей базы;
- `POST /vacancies/api/finish` — воркер закончил обход: задача очереди → «Готово»;
- `GET /vacancies/api/status/<code>` — живой статус-ряд (эталон `/trends/<code>`);
- `POST /vacancies/api/run|cancel|match` — действия страницы (владелец + CSRF).

## Воркер

Канал `nj642.vacancies` (`workers/n2j_workers/handlers/nj642_vacancies.py`):
главная сайта → страницы «Вакансии / Карьера / О компании» → Markdown →
один LLM-вызов со строгой JSON-схемой → `POST /vacancies/api/ingest`.
Страницы работодателя для профиля компании (nj591) переиспользуют ту же функцию
`ingest_from_pages()`.

Переменные окружения — в `workers/.env.example`, блок `nj642_vacancies`:
`NJ642_VACANCIES_API_BASE`, `NJ642_VACANCIES_SITE_TOKEN`, `NJ642_VACANCIES_MODEL`,
`NJ642_VACANCIES_PAGES`, `NJ642_VACANCIES_MD_CAP`, `NJ642_VACANCIES_COMPANY_BUDGET`,
`NJ642_VACANCIES_COMPANIES` (компаний на сбор, 12), `NJ642_VACANCIES_DISCOVER_BUDGET`
(секунд на автоподбор компаний, 120).

## История и дедупликация

Вакансия живёт одной записью: отпечаток `компания|должность|город|путь ссылки`.
Каждый сбор обновляет `last_seen_at`; вакансия, которой в полном сборе не было,
получает статус `gone` и запись в истории. Возвращение вакансии — событие
`restored` (оно же считается «новой» для уведомлений).

## Связи

- **nj591 (профиль компании)** — собирает те же страницы работодателя, отдаёт
  вакансии сюда; на странице профиля есть чип «Вакансии: N»;
- **nj607 (онтология)** — компания становится сущностью карты знаний, связь ведёт
  на `/vacancies?company=<домен>`;
- **nj597 (уведомления)** — письмо о новых подходящих вакансиях (не чаще раза в
  час на монитор, с учётом настроек пользователя);
- **nj120 (очередь)** — задачи сбора и живой прогресс; **nj603** — расписание.
