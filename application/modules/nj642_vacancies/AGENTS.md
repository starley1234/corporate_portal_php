Владелец (26.09.2026): «в обход страниц также смотри страницы „Карьера“ „Вакансии“
„О компании“ (для сбора информации о вакансиях с сайта работодателя) — эта важная
информация, её можно обновлять и хранить историю появления и исчезновения
вакансий; по вакансиям от работодателя можно сделать отдельный функционал
(отдельный модуль): указать город, направление и мониторить изменение (появление
интересных, с уведомлением письмом) вакансий на сайтах компаний; связывай
онтологией с компанией и другими модулями».

## Что где

* `Service_Nj642_Vacancies` (`classes/Service/Nj642/Vacancies.php`) — вся логика:
  мониторы, приём вакансий, история, оценка совпадений, уведомления, онтология.
  Для сводной карточки компании (nj635, страница /check): `by_url()` — найти
  вакансию по ссылке (точные формы адреса, затем хвост пути) и
  `for_company_keys()` — активные вакансии по набору ключей `company_key`
  (+ счётчики); ключи готовит вызывающая сторона, SQL живёт только здесь.
* `Controller_Nj642_Vacancies` — `/vacancies` (лента + форма) и `/vacancies/<code>`
  (один монитор). Действия — только POST → Redirect → GET, результат через сессию
  (`nj642_flash`), а не через `?flash=` в адресе.
* `Controller_Nj642_Api` — `/vacancies/api/…`: `collect` (пиналка), `ingest`
  (воркер), `companies` (воркер принёс найденные им сайты работодателей),
  `hints/<code>` (кандидаты в компании из нашей базы — карта отрасли/профили/
  прошлые сборы), `finish` (воркер закончил обход → задача «Готово»),
  `status/<code>` (живой ряд), `run`, `cancel`, `match`.
* `views/642/*` — `index`, `watch`, `vacancy` (карточка), `script` (AJAX), `card`
  (виджет главной для каталога).
* Воркер: `workers/n2j_workers/handlers/nj642_vacancies.py`, канал
  `nj642.vacancies`. Функция `ingest_from_pages()` переиспользуется обработчиком
  профиля компании (nj591), поэтому история вакансий одна на всю платформу.

## Правила, которые нельзя нарушать

1. **Вакансии — только из текста страниц.** Промпт `SYSTEM_VACANCIES` прямо
   запрещает додумывать; пустая страница («вакансий сейчас нет») даёт пустой
   список — это честный результат, а не ошибка.
2. **Агрегаторы — не работодатели.** hh.ru, superjob, avito и прочие job-борды
   отсеиваются (`_BLOCKED_HOSTS`, плюс `_FIND_BLOCKED` на этапе автоподбора):
   вакансии должны быть с сайта компании.

2.1. **Авто-режим «только город + направление»** (владелец, 27.09.2026: «компании
   с сайтами сервис находит сам — максимально автоматизируем, ориентируемся на
   онтологию»). Монитор создаётся БЕЗ компаний: сервис обязан подобрать их сам и
   сохранить в мониторе (`nj_642_watches.companies`, пометки `auto/source/why/
   found_at`), чтобы владелец видел, у кого именно нашлись вакансии. Порядок
   подбора: `discover_seed()` (карта отрасли nj607 по словам направления и города →
   профили nj591 → находки nj606 → прошлые сборы nj642 → мониторы с тем же
   критерием) и лишь затем открытый поиск в воркере (`_discover_queries`, не более
   `NJ642_VACANCIES_DISCOVER_BUDGET` секунд). Пустой подбор — тоже валидный
   результат: задача закрывается «Готово», а причина видна в этапах.
3. **Одна вакансия — одна запись.** Дедупликация по отпечатку
   (`company_key|должность|город|путь ссылки`, запросы URL отбрасываются) — иначе
   счётчики в ссылках плодили бы «новые» вакансии на каждом сборе.
4. **Исчезновение отмечается только при полном чтении.** Отметка `gone` идёт,
   если воркер прочитал страницы (`full` + `pages_read > 0`). Иначе сбой сети
   выглядел бы как «все вакансии закрылись».
5. **Граница сбора — время БАЗЫ**, не PHP (`SELECT now()`): часовые пояса PHP и
   PostgreSQL расходятся, и вакансии этого же сбора уезжали бы в «закрытые».
6. **Живой статус-ряд обязателен** (общий механизм `partials/live_status` +
   `partials/live_status_js`, эталон `/trends/<code>`): `status/stage/stages/
   elapsed_sec/silent_sec/found`; авто-остановка застрявшего воркера — в
   `/vacancies/api/status/<code>` по общим порогам `JobQueue::silent_stop_sec()`
   и `stalled_progress_sec()`.
7. **Сбор обязан закончиться.** У воркера есть бюджет на компанию
   (`NJ642_VACANCIES_COMPANY_BUDGET`), а у страницы — авто-стоп: «нет пульса» и
   вечный спиннер недопустимы.
8. **Уведомления — через nj597** (`Service_Nj597_Notify::notify`), не чаще раза в
   час на монитор: иначе письмо приходило бы на каждый сбор.
9. **Обход закончен — закрываем задачу сами**: воркер зовёт `/vacancies/api/finish`
   (`Service_Nj642_Vacancies::finish_run`), иначе живой ряд ждал бы авто-остановки,
   хотя работа сделана. Вакансии приходят по компании за запрос, поэтому закрытие
   вынесено в отдельный вызов, а не в `ingest`.
10. **Онтология — через nj607** (`Service_Nj607_Ontology::remember`) в try/catch:
   компания становится сущностью общей карты, связь ведёт на `/vacancies?company=…`.
11. **Права**: обычные действия — владелец монитора; `nj642.admin`
    (`application/config/acl.php`) — администратор видит и правит чужие мониторы.

## Данные

* `nj_642_watches` — мониторы (город, направление, ключевые слова, компании,
  пауза, уведомления, минимальная оценка совпадения). Компания — объект
  `{name, domain, profile_code}`; у найденных автоподбором добавляются
  `auto: true`, `source` («карта отрасли», «поиск», «сбор», «профиль компании»,
  «поток заказчиков», «соседний монитор»), `why` (пояснение/запрос) и `found_at`;
* `nj_642_vacancies` — вакансии компаний: статус `active|gone`, `seen_count`,
  `first_seen_at`/`last_seen_at`/`gone_at` (история жизни вакансии);
* `nj_642_events` — журнал: `appeared`, `gone`, `restored`, `found`;
* `nj_642_matches` — «вакансия подошла монитору»: оценка, объяснение (`why`),
  пометка пользователя (`new|saved|hidden`), `notified_at`.

Миграция — `pgMigration_Nj_642_001_Vacancies`; приложение дополнительно создаёт
таблицы само (`ensure_tables()`, тот же DDL) — деплой без миграций не оставляет
модуль без данных.

## Как включить авто-мониторинг

Расписание живёт в пиналке (`application/modules/nj603_kicker/config/nj603_kicker.php`,
пункт `vacancies`, каждые 3 часа; созревание держит сам модуль — `every_hours`).
Сейчас пункт внутри блока, который владелец поставил на паузу до тестов сервисов:
убрать комментарий вокруг блока — и мониторы начнут собираться сами. Кнопка
«Собрать» и первый сбор при создании монитора работают и без пиналки.
