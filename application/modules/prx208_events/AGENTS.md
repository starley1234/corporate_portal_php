# AGENTS.md — prx208_events (шина событий)

> Памятка агенту. Общие правила платформы — в корневом /AGENTS.md.

## Назначение
Central Event Bus: pub/sub между модулями без прямых связей. Модуль публикует
`Event::fire('prx401.task_done', [...])`, другие модули подписываются в своих
`init.php`. Все события журналируются в БД.

## Состояние
- Готовность: рабочий; основа слабой связанности модулей.

## Ключевые классы
| Класс | Роль |
|---|---|
| `Event` (application/classes/Event.php) | фасад: `Event::fire()`, `Event::listen()` — автоматом подтягивает текущего пользователя как инициатора |
| `Service_Prx208_EventBus` | реестр слушателей, публикация, мост в центр уведомлений prx597 (`_bridge_to_prx597`), исключение инициатора из получателей |
| `Controller_Prx208_Api` | REST: publish/get_events |
| `Model_Prx208_Event`, `_Subscriber`, `_EventListener`, `_EventPublisher` | модели шины |

## Таблицы
- `prx_208_events` — журнал всех событий;
- `prx_208_event_subscribers` — подписки.

## Маршруты и API
- `/prx208/api/publish_event` (POST event_name, payload) — публикация внешними системами;
- `/prx208/widget/latest_events` — виджет последних событий.

## Именование событий
`prx<id>.<сущность>.<действие>`: `prx401.task.done`, `prx501.calc.finished`.
Имя события — контракт: менять только с оглядкой на слушателей.

## Не трогать / подводные камни
- Не публиковать события из циклов в больших объёмах — журнал растёт;
  потоковые данные — в очередь prx120.
- Payload сериализуется в JSON: только скаляры/массивы, без ORM-объектов.
