# AGENTS.md — prx208_events (шина событий)

> Памятка агенту. Общие правила платформы — в корневом /AGENTS.md.

## Назначение
Central Event Bus: pub/sub между модулями без прямых связей. Модуль публикует
`Event::fire('prx401.task_done', [...])`, другие модули подписываются в своих
`init.php`. Все события журналируются в БД.

## Состояние
- `Event::listen` регистрирует слушателей модулей независимо от DB-подписок.
- Загрузка активных строк `prx_208_event_subscribers` по умолчанию выключена:
  старые записи могли не исполняться из-за ошибки PostgreSQL. Включение
  `PRX208_DB_SUBSCRIBERS_ENABLED=1` — только после аудита на staging;
  см. `docs/ENVIRONMENT.md`. Это не включает wildcard-мост `proxy_to_notification_center`.

## Ключевые классы
| Класс | Роль |
|---|---|
| `Event` (application/classes/Event.php) | фасад: `Event::fire()`, `Event::listen()` — автоматом подтягивает текущего пользователя как инициатора |
| `Service_Prx208_EventBus` | реестр слушателей, публикация, мост в центр уведомлений prx597 (`_bridge_to_prx597`), исключение инициатора из получателей |
| `Controller_Prx208_Api` | Сессионный API: publish/get_events/subscribe/unsubscribe |
| `Model_Prx208_Event`, `_Subscriber`, `_EventListener`, `_EventPublisher` | модели шины |

## Таблицы
- `prx_208_events` — журнал всех событий;
- `prx_208_event_subscribers` — подписки.

## Маршруты и API
- `/prx208_events/api/publish_event` (POST event_name, payload, csrf) — публикация
  в авторизованной сессии; отдельной токенной авторизации внешних систем нет.
- `/prx208_events/api/subscribe|unsubscribe` — POST + CSRF + право управления.
- `/prx208_events/widget/latest_events` — виджет последних событий.

## Именование событий
`prx<id>.<сущность>.<действие>`: `prx401.task.done`, `prx501.calc.finished`.
Имя события — контракт: менять только с оглядкой на слушателей.

## Не трогать / подводные камни
- Не публиковать события из циклов в больших объёмах — журнал растёт;
  потоковые данные — в очередь prx120.
- Payload сериализуется в JSON: только скаляры/массивы, без ORM-объектов.
- Мост `is_notification` вызывается не более одного раза на имя события для
  всех DB-строк и доставляет только явным `target_user_id(s)`; поля события
  `user_id/user_ids/recipients` не добавляют получателей; поля `channels` и
  `force_self` не обходят роли и настройки события. Значения для шаблона при
  необходимости передают в `data`. Права и настройки каналов проверяет prx597.
  Это не дедупликация независимых прямых вызовов `Notify` и `sweep_jobs`.
- Флажки в форме сохраняются даже выключенными; управление и удаление
  DB-подписок — POST + CSRF. Изменения видны после инициализации новой шины.
- Ошибки слушателя/инициализации и загрузки DB-подписок фиксируются в
  `prx208_diag` без текста исключения и payload; сбой одного обработчика не
  прерывает остальные. Остальные старые журналы могут содержать приватные данные.
