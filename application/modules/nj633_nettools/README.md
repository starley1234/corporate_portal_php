# Сетевые инструменты (nj633_nettools)

Полезный набор сетевых сервисов **с защитой сервера**:

- **DNS-записи** — A, AAAA, MX, TXT, NS, CNAME, SOA (+ PTR по IPv4);
- **WHOIS** — регистрационные данные домена через публичный сервер (TCP 43),
  с автоматическим переходом по `refer:` TLD-сервера;
- **Доступность порта** — TCP-подключение без ping и без shell;
- **Конвертер IP ↔ 32-битное число** — адрес в целое/hex и обратно (чистое
  вычисление на сервере, без сети);
- **Base64** — кодирование/декодирование текста (строгая проверка при decode);
- **Объяснение результата (ИИ)** — дополнительная опция: короткое пояснение
  простыми словами через очередь задач; сохраняется в БД.

## Безопасность

| Угроза | Мера |
|---|---|
| SSRF | входной фильтр `assert_public_target()` + `is_blocked_ip()`; запрещены localhost, 127/8, 10/8, 172.16/12, 192.168/16, 169.254/16 (метаданные облаков), ::1, ::, ULA/link-local/multicast; проверка по исходной строке **и** по резолву DNS (анти-rebinding) |
| DDoS на сторонние сети | rate limit по IP в БД (мин/час), таймауты сокетов, лимиты чтения |
| Command injection | shell не используется вообще: только `stream_socket_client()` и фасад `Llm`; пользовательский ввод не попадает в exec() |
| Злоупотребление LLM | объяснение идёт не в HTTP-запросе, а через очередь nj120 (канал `llm.summarize`) с try/catch и лимитом попыток |

## Сохранение в БД

- `nj_633_checks` — каждая проверка (что, когда, результат, IP) — источник и для rate limit, и для истории «Мои проверки».
- `nj_633_notes` — LLM-объяснения (queued → done/error).

Чистка старых записей — через `/nj100/cleanup` (пункты `nj633_checks`, `nj633_notes`).

## Как проверять

```bash
curl '/net/api/dns?host=example.com&type=A'
curl '/net/api/whois?host=example.com'
curl '/net/api/check?host=example.com&port=443'
curl '/net/api/ipconv?value=8.8.8.8'        # → int + hex
curl '/net/api/ipconv?value=134744072'       # → 8.8.8.8
curl '/net/api/base64' -d 'text=test&mode=encode'
curl -d 'host=127.0.0.1' /net/api/dns   # → 400, SSRF запрещён
```
