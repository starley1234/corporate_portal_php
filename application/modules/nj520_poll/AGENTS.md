## Контракт

- Сервис `Service_Nj520_Poll` — единственная точка работы с таблицами (стиль
  NJ-120: `Database::instance()` + `quote()`, `INSERT..RETURNING` через
  `Database::SELECT`). Помощники `_one()/_all()/_exec()`; `_one()` нормализует
  пустой `current()` драйвера PostgreSQL (`FALSE`) в `NULL`.
- Таблицы: `nj_520_polls` (code UNIQUE, closed_at), `nj_520_options` (poll
  CASCADE), `nj_520_votes` (**UNIQUE(poll_id, voter_key)**, миграция 004).
- Страницы: `/poll` (создание, POST+CSRF), `/p/<код>` (GET — голосование и
  результаты, POST — голос, редирект 303 с флагом `?voted|already|closed`),
  `/nj520/admin` (список), `/nj520/admin/poll/<код>` (подробности).
- API: `GET /nj520/api/stats/<код>` → `{ok,title,total,leader,closed,hidden,
  options[],url}`; им же страница обновляет цифры и полоски раз в 15 секунд.
  Пока результаты скрыты, ответ короткий: `{ok,title,total,closed,hidden:true,
  note,url}` — без `options` и `leader`. Опрашивает сервер только та страница,
  где цифры уже видны (во вьюху уходит флаг `live`).
- Ключ голосующего: `Service_Nj520_Poll::voter_key()` → `u:<id>` / `g:<ubid>` /
  `ip:<адрес>` (запасной, когда куку поставить не удалось). Зовётся **из
  контроллера до вывода тела**: `Visitor::uid()` лениво ставит куку.
- Кому видны результаты: `results_visible($poll, $has_voted)` — проголосовал
  ИЛИ опрос закрыт. Новых условий сюда не дописывать мимо тестов: правило
  проверяется и в юните, и в дыме.
- Результаты: `results()` отдаёт `percent` (одна десятая) и `leader` — id
  варианта, который впереди ОДИН (при ничьей 0, бейдж «лидирует» не рисуем).

## Не делать

- Не возвращать учёт по IP и не хранить адреса новых голосов: приватность —
  заявленная черта сервиса, а один IP на офис уже ломал голосование.
- Не показывать распределение голосов тому, кто ещё не голосовал в открытом
  опросе — ни в вёрстке, ни в API: это прямая просьба владельца.
- Не убирать UNIQUE(poll_id, voter_key) — это единственная защита от накрутки;
  проверка `SELECT`-ом гонку не ловит.
- Не ставить свою куку: идентификатор посетителя в платформе один (`Visitor`).
- В админке нет GET-параметров и `?flash=`: подробности — адресом
  `/nj520/admin/poll/<код>`, сообщения — через сессию, действия — POST + CSRF,
  удаление — в два клика (`data-n2j-arm` из app.js, без `window.confirm`).
- Не редактировать `modules/`, `system/`; менять применённые миграции нельзя —
  только новая (005+).

## Подводные камни

- **Полоски долей — исключение из общего запрета полос** (корневой AGENTS.md,
  п. 10): это не ход работы, а сам результат. Разрешены владельцем 04.10.2026
  только для результатов голосования. Ширина — инлайновым `style`, Tailwind
  динамических классов не видит.
- **QR — только локальная `/assets/vendor/qrcode/qrcode.js`** (как в nj530):
  ни одного внешнего хоста, адрес опроса никуда не уезжает.
- `set_title()` экранирует шаблон — передавать сырой заголовок, иначе в
  `<title>` приедет `&amp;`.
- Склонения («голос/голоса/голосов») — `votes_word()/options_word()`, не
  новые тернарники в вёрстке: три копии уже расходились между страницами.

## Как тестировать

- `php tests/mini_runner.php PollService` — чистая логика, база не нужна.
- `php tests/mini_runner.php PollVote` — живая БД: голосование, повторы,
  закрытие, каскад, список активных.
- `npm run test:poll-qr` — QR страницы опроса: ссылка читается обратно
  независимым декодером (jsQR), библиотека локальная, страница жива без JS.
- `BASE=http://localhost:8080 node tests/Js/modules_http_smoke.mjs` — коды
  ответов `/poll`, `/p/<нет такого>`, `/nj520/api/stats/<нет такого>`.
- Страницы руками: `/poll` (создать), `/p/<код>` (голос, полоски, QR),
  `/nj520/admin` (только admin).

## Долги и идеи

- Автору опроса негде посмотреть свои опросы: ссылку легко потерять. Напрашивается
  список «мои опросы» по ключу `Visitor::uid()` (без регистрации).
- Нет экспорта итогов (CSV) и нет ограничения по времени («опрос до пятницы»).
- Нельзя переголосовать: иногда это нужно (ошибся кнопкой) — решать вместе с
  честностью подсчёта.
