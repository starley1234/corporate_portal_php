# Декодер JSON (модуль 664) — памятка для агентов

Публичный сервис N2J (группа «Текст»): JSON прилетает в разных видах —
экранированным из лога, процентами из адреса, сущностями из HTML, строкой из
дампа. Модуль узнаёт любой из них и показывает структуру: красивый JSON,
сжатый, вид глазами `print_r()` и готовый PHP-код. Ничего не сохраняется.

## Контракт

- Страница: `GET /json-decode` — пустая форма; `POST /json-decode` (поля
  `input`, `mode`) — разбор без JavaScript. `GET /json-decode?input=…&mode=…`
  — ссылка с данными: поле заполнено и разобрано сразу, ссылкой можно
  поделиться готовым разбором.
- API: `POST /nj664/api/decode {input, mode}` → `{ok, mode, mode_label, result,
  stats}`; при `mode=all` рядом есть `minified`, `php_array`, `php_code`.
  Пустой или неразобранный вход — 422 с причиной, строкой и позицией.
- `POST/GET /nj664/api/sample` → `{ok, input, output}` — пример входа и выхода.
- Сервис: `Service_Nj664_Decode` (`decode`, `beautify`, `minify`, `php_array`,
  `php_code`, `stats`, `mode_label`, `sample`).
- Потолок входа: `MAX_BYTES` 2 МБ. Превышение — честная ошибка, не урезание.
- Таблиц, миграций, очередей и воркеров нет.

## Правила для агента

- **Порядок проб в `decode()` менять нельзя.** Первым идёт «как есть»: честный
  JSON обязан разобраться без всяких догадок. Если поставить `stripslashes`
  раньше, путь `C:\temp` превратится в `C:temp` — данные будут испорчены
  молча. Порядок: raw → slashes → url → html → quoted.
- **`php_array()` обязан совпадать с `print_r()` символ в символ** — иначе
  человек скопирует вывод, вставит в PHP и получит другой вид. Тонкости:
  вложенный массив печатается на той же строке, что и ключ (его отступ — на
  два уровня глубже, у первой строки пробелы сняты), а после закрывающей
  скобки вложенного массива идёт пустая строка. Есть тест-эталон.
- **В браузере и на сервере логика одна.** `views/664/script.php` повторяет
  пять проб в том же порядке; расхождение в порядке — это «в браузере ок, на
  сервере нет». Правя одно, правь и другое.
- **Разбор живёт в браузере** — JSON никуда не уходит. Вкладки «PHP Array» и
  «json_decode()» — исключение, их считает сервер (нужен настоящий `print_r`
  и генератор кода); ответ кэшируется по тексту входа, повторный запрос не
  уходит.
- **Позиция ошибки считается грубым разборщиком** `_broken_spot()`: PHP не
  сообщает, где сломалось, а искать глазами запятую в большом ответе API —
  занятие не для человека. В браузере позицию даёт сам V8 (из текста
  исключения), поэтому тексты ошибок на двух сторонах разные, но обе должны
  называть строку и позицию.
- **По чужим адресам ходит браузер, не сервер.** Кнопка «Ссылка» тянет URL
  из браузера (`fetch` на клиенте). Переносить это на сервер нельзя: любая
  ссылка пользователя станет запросом из внутренней сети сайта (SSRF). Если
  чужой сервер не отдаёт CORS, говорим об этом прямо — молчаливая пустота
  заставит человека искать ошибку у себя.
- Вход пользовательский: в статусе он идёт через `HTML::chars()`, в `<pre>` —
  через `textContent`, а не `innerHTML`.

## Проверки модуля

```bash
# стенд сервиса (php-wasm, без PHP в системе)
N2J_ROOT=$(pwd) node /tmp/phpwasm/phpwasm_stand.mjs .tools/nj664_decode_stand.php

# стенд поведения страницы (jsdom, настоящая вьюха через php-wasm)
npm run test:jsondecode:ui

php tests/mini_runner.php JsonDecodeService
curl -s -X POST -d 'input={"a":1}' 'http://localhost:8080/nj664/api/decode'
curl -s -o /dev/null -w '%{http_code}\n' 'http://localhost:8080/json-decode'
```

## Куда развивать

- Дерево с раскрывающимися узлами и поиском по ключам.
- Память последних входов (localStorage) — как «Load previous data» у
  codebeautify; сейчас этого нет сознательно: вход может быть чужим ответом
  API, а хранилище браузера — не место для чужих данных.
- XML и YAML на вход (экранированные они попадаются не реже JSON).
- Закладка с JSONPath-выборкой (`$.top[*].Name`).
