# AGENTS.md — nj160_mcp

> Памятка агенту. Правила платформы — в корневом AGENTS.md; здесь — только
> специфика модуля.

## Назначение
Единая MCP-точка входа: внешние ИИ-агенты видят инструменты всех модулей
и вызывают их по JSON-RPC.

## Состояние
- Готовность: стабилен.

## Ключевые классы
| Класс | Роль |
|---|---|
| `Controller_Nj160_Rpc` | POST /mcp/api/rpc — JSON-RPC 2.0 (Bearer `MCP_TOKEN`) |
| `Controller_Nj160_Hub` | страница /mcp со списком инструментов |
| `Service_Nj160_Registry` | каскадный сбор `config/mcp.php` всех модулей |

## Как добавить инструмент модулю
Создайте `config/mcp.php` модуля: `name`, `description`, `inputSchema`
(JSON Schema), `'handler' => 'Service_NjXXX_Y::method'` — метод принимает
`array $args` и возвращает массив. Хаб подхватит без правок nj160.

Владелец персонального ключа приходит в `$args['_user_id']`: `Registry::call()`
всегда перезаписывает этот ключ (подделать аргументом нельзя) и вычищает его
для legacy `MCP_TOKEN`. Иначе модуль не знает, в чьё пространство писать.
Персональные данные и запись должны проверять права владельца сами — хаб
отдаёт только уровень admin/user.

## Нюансы
- Токен — env `MCP_TOKEN` на сайте; пустой = API отвечает ошибкой конфигурации.
- Инструмент не должен тянуть тяжёлые задачи в HTTP-запросе — для этого
  очередь nj120.
