# AGENTS.md — prx218_module_manager (менеджер модулей)

> Памятка агенту. Общие правила платформы — в корневом /AGENTS.md.

## Назначение
Реестр модулей платформы: сканирование каталога `application/modules/`,
зависимости, история версий, LLM-анализ кода модулей, генератор скелетов
новых модулей.

## Состояние
- Готовность: рабочий (сканер, реестр, зависимости, LLM-обработчик, scaffold).

## Ключевые классы
| Класс | Роль |
|---|---|
| `Service_Prx218_Scanner` | сканирование файловой системы модулей |
| `Service_Prx218_ModuleManager` | CRUD реестра, зависимости |
| `Service_Prx218_LlmProcessor` | LLM-анализ модулей (через модуль llm) |
| `Task_Module_Scaffold` | `bin/console module:scaffold --id=401 --slug=tasks --name="..."` — генератор скелета модуля |
| `Controller_Prx218_*` | админка модулей, API, сканер, виджеты |

## Таблицы
- `prx_218_modules`, `prx_218_dependencies`, `prx_218_version_history`,
  `prx_218_llm_analysis`.

## Маршруты и API
- Реестр: `/prx218_module_manager`; запуск: `/prx218_module_manager/scanner` →
  POST `…/scanner/run` с CSRF и `module_manager.scan`. Поддерживаются прежние
  `/prx218/...`; CLI-инвентаризация: `make modules`.
- Сканирование обновляет записи, не включает и не публикует модули.
  Счётчики результата различают найденные, добавленные, обновлённые и
  пропущенные папки. «Активность реестра» не является журналом запусков.

## Не трогать / подводные камни
- Генератор модулей (Task_Module_Scaffold) не перезаписывает существующие файлы.
- Шаблоны скелета внутри таска синхронизированы с docs/MODULE_GUIDE.md —
  менять согласованно (гайд + шаблон AGENTS.md в docs/templates/).
