# AGENTS.md — erp212_file_storage (файловое хранилище)

> Памятка агенту. Общие правила платформы — в корневом /AGENTS.md.

## Назначение
Файловое хранилище платформы: загрузка/выдача/удаление файлов с бэкендами
(локальная ФС, S3), права доступа, публичные ссылки.

## Состояние
- Готовность: рабочий (API, скачивание с проверкой прав, бэкенды, cleanup-таск).

## Ключевые классы
| Класс | Роль |
|---|---|
| `Service_Erp212_Storage` | вся логика: выбор бэкенда, метаданные, права |
| `Controller_Erp212_Api` | REST: upload/metadata/delete |
| `Controller_Erp212_Download` | безопасная выдача файла |
| `Controller_Erp212_Link` | публичные ссылки на файлы |
| `Model_Erp212_File`, `_Backend`, `_Link`, `_Permission` | модели |
| `Task_Erp212_Storage_Cleanup` | cron: чистка протухших файлов/ссылок |

## Таблицы
- `erp_212_files`, `erp_212_storage_backends`, `erp_212_file_links`,
  `erp_212_file_permissions` — владелец: этот модуль.

## Маршруты и API
- `POST /erp212/api/upload`, `GET /erp212/api/file/<id>`, DELETE и т.д. (см. init.php)
- Скачивание: через контроллер Download (не прямые пути к диску).

## Не трогать / подводные камни
- Физические пути не хранить в коде: бэкенды конфигурируются (config).
- Долгие операции (загрузка в S3, конвертация) — кандидаты на очередь nj120,
  не держать HTTP-запрос.
- Пользовательский контент: проверять mime/размер, отдавать с корректным
  Content-Disposition (XSS через HTML-файлы).
