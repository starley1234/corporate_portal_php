# AGENTS.md — prl208_events (шина событий)

> Памятка агенту. Общие правила платформы — в корневом /AGENTS.md.

## Назначение
Central Event Bus: pub/sub между модулями без прямых связей. Модуль публикует
`Event::fire('prl401.task_done', [...])`, другие модули подписываются в своих
`init.php`. Все события журналируются в БД.

## Состояние
- Готовность: рабочий; основа слабой связанности модулей.

## Ключевые классы
| Класс | Роль |
|---|---|
| `Event` (application/classes/Event.php) | фасад: `Event::fire()`, `Event::listen()` — автоматом подтягивает текущего пользователя как инициатора |
| `Service_Prl208_EventBus` | реестр слушателей, публикация, мост в центр уведомлений prl597 (`_bridge_to_prl597`), исключение инициатора из получателей |
| `Controller_Prl208_Api` | REST: publish/get_events |
| `Model_Prl208_Event`, `_Subscriber`, `_EventListener`, `_EventPublisher` | модели шины |

## Таблицы
- `prl_208_events` — журнал всех событий;
- `prl_208_event_subscribers` — подписки.

## Маршруты и API
- `/prl208/api/publish_event` (POST event_name, payload) — публикация внешними системами;
- `/prl208/widget/latest_events` — виджет последних событий.

## Именование событий
`prl<id>.<сущность>.<действие>`: `prl401.task.done`, `prl501.calc.finished`.
Имя события — контракт: менять только с оглядкой на слушателей.

## Не трогать / подводные камни
- Не публиковать события из циклов в больших объёмах — журнал растёт;
  потоковые данные — в очередь prl120.
- Payload сериализуется в JSON: только скаляры/массивы, без ORM-объектов.
