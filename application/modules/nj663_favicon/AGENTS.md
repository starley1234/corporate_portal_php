## Состояние работ
- **09.10.2026 (правка по замечаниям владельца):** страница переложена на
  компоновку redketchup.io — СЛЕВА элементы управления (вкладка «Буква или
  эмодзи» по умолчанию, «Из картинки» — вторая), СПРАВА живое превью,
  ползунки формы, кнопка сборки и результат (файлы, превью, HTML-код).
  Справка («Что получите», «Как подключить», «Для разработчика») ушла под
  форму — раньше она занимала правую колонку, а результат висел слева, и
  человек крутил настройки, не видя, что получается.
- **09.10.2026 (замечание владельца: «верхний предел надо делать больше»):**
  верх «Размер шрифта» поднят с 90 % до **200 %** стороны полотна (102–1024 px
  на 512): у буквы высота строчной ~0,7 кегля, поэтому прежних 90 % не хватало,
  чтобы положить символ во весь квадрат, а 200 % позволяет ещё и намеренно
  пустить его за край. Предел живёт в конфиге (`limits.font_share_min` /
  `font_share_max`): ползунок в `views/663/index.php` и приёмка запроса
  (`Service::_options()`) читают ОДНО и то же число — иначе сервер молча
  срезал бы крупный символ, выбранный человеком.
- Управление символом: **шрифт** (7 системных стеков), **размер шрифта**
  (в пикселях полотна 512), **жирный**, **курсив**, цвет, фон и скругление.
  Поля «Путь на сайте» и «Название» УБРАНЫ: код всегда собирается под `/`,
  имя в manifest подставляется своё.
- Шрифты заданы один раз — в `config/nj663_favicon.php` (`fonts`), оттуда их
  получает и вьюха, и JS (`Service_Nj663_Favicon::fonts()`). Только системные
  стеки: браузер рисует букву канвасом, ничего не качаем из сети.
- **09.10.2026:** модуль собран целиком: страница `/favicon-gen`, страница
  готового набора `/favicon-gen/p/<код>`, JSON API, журнал `nj_663_packs`.
  Образец — redketchup.io/favicon-generator (картинка/буква/эмодзи на входе,
  полный комплект и HTML-код на выходе).
- Считают двое: браузер рисует базовое полотно 512×512 на канвасе (цветные
  эмодзи умеет только он), сервер размножает его по размерам, собирает
  favicon.ico, site.webmanifest и zip. В запросе это различает флаг
  `composed`: TRUE — полотно уже готово, сервер не применяет фон/отступ/
  скругление второй раз.
- Без JS работает загрузка файла: форма постится на `/favicon-gen`, полотно
  собирает сервер (`Service_Nj663_Favicon::compose()`). Текст без JS не
  нарисовать: серверного рендера буквы нет (GD не умеет цветные эмодзи),
  букву рисует только канвас браузера.
- Опции символа (`font`, `font_share`, `bold`, `italic`) кладутся в
  `options_json` журнала: по записи видно, чем именно рисовали.

## Назначение
Один исходник (картинка, буква, эмодзи) → полный комплект иконок сайта:
PNG 16–512, apple-touch-icon, android-chrome 192/512, многоразмерный
favicon.ico, site.webmanifest, zip-архив и готовый код для `<head>`.

## Ключевые классы
| Класс | Роль |
|---|---|
| `Service_Nj663_Favicon` | вся логика: чистые функции (цвета, имена, HTML-сниппет, сборка ICO), GD-конвейер, журнал, уборка |
| `Controller_Nj663_Favicon` | страницы `/favicon-gen` и `/favicon-gen/p/<код>` (включая POST без JS) |
| `Controller_Nj663_Api` | JSON API: `/favicon-gen/api/{generate,sizes,pack}` и выдача файлов `/favicon-gen/f/<код>/<имя>` |

## Маршруты
```
GET  /favicon-gen                 страница генератора (+ POST без JS)
GET  /favicon-gen/p/<code>        готовый набор: файлы, превью, HTML-код
POST /favicon-gen/api/generate    собрать комплект (image_b64 или файл image)
GET  /favicon-gen/api/pack/<code> состав набора (JSON)
GET  /favicon-gen/api/sizes       справочник размеров и умолчаний
GET  /favicon-gen/f/<code>/<name> сам файл
```

## Таблица nj_663_packs
`id` · `code` UNIQUE (он же каталог `storage/nj663/<code>`) · `visitor_uid` ·
`client_ip` · `kind` (upload|text) · `source_json` · `options_json` ·
`files_json` · `bytes_total` · `html` · `base_path` · `downloads` ·
`created_at` · `last_access_at`. Индексы по коду, uid, ip и дате.

## Инварианты
- **Исходник не переживает запрос:** хранится только результат (PNG/ICO/zip),
  сам файл пользователя никуда не сохраняется.
- **Выдача файла — только по белому списку имён** (`safe_file_name()`) и коду
  из `^[23456789a-z]{6,24}$`: выйти за пределы каталога набора нельзя.
  В маршруте `<name>` задан свой regex — сегмент Kohana по умолчанию
  (`[^/.,;?\n]++`) не пропускает точку, и «favicon-32x32.png» не матчился бы.
- **Код набора — capability:** угадать чужой набор нельзя, живёт 30 дней
  (`ttl_days`), выметает `sweep()` (файлы + строка журнала).
- **Цвета в сниппете** — только `#rrggbb` из `normalize_color()`; путь сайта —
  только путь (`normalize_base_path()` режет протокол, хост и `..`).
- **Работа — синхронно в запросе:** GD собирает комплект за доли секунды,
  очередь не нужна (осознанное исключение, как у вебхука Алисы nj657).
- Лимиты: `rate` (10 комплектов в минуту, 60 в час) через
  `Service_Nj100_Ratelimit` по таблице журнала; размер файла — `max_input_mb`.
- Отказ виден в логе: `Log_Plain::event(Log::ERROR, 'nj663: …')`.

bash .tools/php_check_all.sh application/modules/nj663_favicon

- Стенд `.tools/nj663_favicon_stand.php` — чистые функции: размеры и цели,
  нормализация цвета и пути, HTML-сниппет и webmanifest, белый список имён
  (включая traversal), код набора, **побайтовая структура ICO** (заголовок,
  число кадров, смещения, BGRA снизу вверх) и разбор опций запроса.
  GD и БД стенд не трогает: их проверяет живой прогон на странице.
- Живой прогон: `/favicon-gen` → «Собрать комплект» → превью 16/32, скачать
  zip, открыть `/favicon-gen/p/<код>`, сверить HTML-код.
