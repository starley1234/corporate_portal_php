# prx113_favorites — Избранное · управление

## Контракт
- Страница `/favorites` (право `prx113.view` = login): порядок (sort), категории,
  переименование, заметки закреплённых сервисов.
- Данные — таблица `prx_110_favorites` (владелец — **prx110_catalog**). Здесь только
  UI: чтение/запись через `Service_Prx110_Favorites::items()/reorder()`.
- Колонки `sort`/`category`/`note` — миграция **prx110/012**; до неё страница
  показывает текущее состояние, сохранение даёт человекочитаемую ошибку.

## Состояние
- Готово: страница с drag&drop + кнопками выше/ниже, категории в сайдбаре
  (SSR sidebar.php и navpalette.js renderFavorites — структура одинаковая),
  переименование/иконка сильнее каталога (только для владельца пина).
- Форма: параллельные массивы `href[]/title[]/icon[]/category[]/note[]` в
  DOM-порядке — перетаскивание двигает узлы, никакого JSON-конкрактa.

## Подводные камни
- `set()` при закреплении перезаписывает title/icon метаданными каталога —
  переименование из prx113 стирается повторным пином (осознанно: звезда = «свежие
  данные каталога»).
- `valid_href` запрещает `/services` и внешние ссылки — и в reorder тоже.
- PHP превращает `.` и пробелы в ключах POST-массивов в `_` — поэтому массивы
  позиционные, а не ассоциативные по href.
