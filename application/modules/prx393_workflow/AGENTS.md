# prx393_workflow — маршруты, календарь и сроки

## Состояние

MVP: правила маршрутизации, производственный календарь РФ 2026, срок по
правилу или подсказке из письма, эскалации T−24/T−4/просрочка. Источник
истины по сроку — `prx_393_deadlines`; prx391 получает снимок только через
`set_sla_snapshot()`.

## Границы

Владеет `prx_393_rules`, `prx_393_calendars`, `prx_393_assignments`,
`prx_393_deadlines`, `prx_393_escalations`. Читает карточку через
`Service_Prx391_Documents::document()`. Не читает таблицы prx391 напрямую.

## Маршруты

- `/sla` — открытые сроки, правила, эскалации.
- `POST /sla/route/<document_id>` — пересчитать маршрут и срок.
- `POST /sla/recalc` — пересчитать до 200 документов.
- `/prx393/api/health`.

## Права

`prx393.view` — `login`; `prx393.manage` — `docflow_manager`. `/sla`
показывает только карточки, разрешённые `prx391`: из 60 ближайших сроков и
20 последних эскалаций. Общие показатели скрыты, если актор не может видеть
все грифы; нефильтрованные `deadlines/escalations/stats` — для доверенного
внутреннего кода, UI использует `visible_*` с актором. `/prx393/api/health`
отдаёт глобальные показатели по worker-токену, не по правам сессии; при пустом
токене development разрешает доступ. Другие страницы документооборота имеют
известные ACL-утечки: ограничения и условия безопасного использования описаны
в `docs/ENVIRONMENT.md`.

## Алгоритм

1. Правила по `priority`; побеждает ПЕРВОЕ подходящее. Сильные признаки —
   домен отправителя и ИНН; затем тип; ключевое слово в теме/резюме не меняет
   маршрут, если тип уже известен и другой. Поле `stop` оставлено в схеме для
   совместимости и на выбор больше не влияет.
2. Нет правила — безопасный маршрут «Канцелярия», роль `docflow_clerk`.
3. Срок: подсказка из текста (`deadline_hint_days/unit`) важнее правила и
   считает календарные либо рабочие дни до 18:00. Без подсказки правило с
   `business_days=true` и SLA ≥ 72 ч считает округлённые вверх рабочие дни;
   остальные сроки считаются календарными часами.
4. `prx_393_assignments` и `prx_393_deadlines` — upsert по `document_id`.
   Закрытие снимает открытый срок с контроля (`met`), reopen возвращает его
   в `open`; повторный пересчёт закрытого документа не открывает срок. Статус
   `met` сам по себе не доказывает, что документ закрыт до даты срока.
5. Снимок в prx391; событие `prx393.document.assigned`. Старые сроки и закрытия
   автоматически не исправляются: порядок и ограничения — `docs/ENVIRONMENT.md`.

Правила-first: тип от ИИ лишь один из входов; при ошибке модели сработает
безопасный маршрут, а не «ИИ решил права».

## События

- Слушает `prx391.document.registered` → `route()`.
- Слушает `prx391.document.updated` с `recalc=true` или `reason=closed` → `route()`.
- Публикует `prx393.document.assigned`, `prx393.deadline.approaching`,
  `prx393.deadline.overdue`.

## Эскалации

`maybe_escalate()` вызывается на `/sla` и из CLI `prx393:escalate` (cron).
Уровни: `t24`, `t4`, `overdue`; уникальный индекс `(deadline_id, level)`
защищает от дублей. Получатели — пользователи роли исполнителя/менеджера,
которые в момент формирования события также проходят `prx391::can_view()` для
конкретной карточки. Ошибка проверки адресатов не записывает эскалацию; пустой
список всё равно может дать запись без доставки. Дальнейшая смена прав после
постановки уведомления в outbox здесь не перепроверяется.
Отметка и событие сами по себе не подтверждают доставку в prx597: wildcard-мост
выключен, и на чистой базе для этих имён нет DB-подписок. Не считать эскалации
готовой доставкой, пока интеграция отдельно не настроена и не проверена.
