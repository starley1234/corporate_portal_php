## Назначение

«Лаборатория LLM» (`/llmlab`) — интерактивная витрина того, как языковая модель
работает с текстом: мини-BPE токенизация и оценка расхода токенов, «следующий
токен» с температурой/top-k/top-p, семантическая близость (эмбеддинги), разбор
промпта по чек-листу, квиз и прогон промпта реальной моделью через очередь.
Для владельца и посетителей сайта: «потрогать LLM руками» без ключей и без
внешних сервисов. Знания копятся в БД: корпус, n-граммы, эмбеддинги, промпты,
попытки квиза.

## Таблицы (полное владение)

- `nj_645_corpus` — тексты корпуса (статусы `published|pending|rejected`), источник n-грамм и словаря.
- `nj_645_ngrams` — счётчики n-грамм (n = 1..3) + backoff-веса: следующий токен.
- `nj_645_terms` — словарь мини-BPE (слова и куски), откуда берётся токенизатор.
- `nj_645_prompts` — библиотека промптов с голосами (статусы `published|hidden`).
- `nj_645_prompt_votes` — голоса за промпты.
- `nj_645_runs` — прогоны промпта реальной моделью (`queued|running|done|error`), ответ, расход.
- `nj_645_vectors` — локальные эмбеддинги текстов для семантической карты.
- `nj_645_guesses` — попытки «человек против модели» (что угадали, что нет).
- `nj_645_quiz_misses` — ошибки квиза: из них строится разбор «что не поняли».
- `nj_645_tokenstats` — суточные счётчики демонстраций (для статистики и лимитов).

## Маршруты и API

- `GET /llmlab` — страница (вкладки демонстраций).
- `POST /llmlab/api/tokenize|sample|guess|corpus|similarity|vector_add|vector_map|prompt_check|prompt_add|prompt_vote|run|run_status|quiz|quiz_answer|stats` — посетитель (сессия/куки, лимиты).
- `POST /llmlab/api/worker_result` — воркер, заголовок `X-Worker-Token`.
- `/nj645/admin` — админ: `moderate`, `rebuild`, `prompt_status`, `trim_vectors` (POST + CSRF).

## Правила, которые нельзя нарушать

1. **Страница работает без ИИ.** Токены, следующий токен, эмбеддинги, разбор промпта и квиз считаются локально по своей БД. Если LLM не настроена — интерфейс говорит об этом прямо, а не падает.
2. **Никаких внешних хостов в вёрстке.** Шрифты, иконки, стили — только свои в `public_html/assets/`.
3. **Долгие операции — только через очередь** `nj120_jobs` (канал `nj645.review`). Ни один HTTP-запрос страницы не ждёт модель.
4. **Демонстрации честные.** Экран «следующий токен» подписан как n-граммная модель, токенизатор — как мини-BPE по своему словарю; нельзя выдавать их за токенизатор конкретной чужой модели.
5. **Вся запись — через `Service_Nj645_Store`**, прямых `DB::query` в контроллерах нет. Исключение — `ensure_tables()` (создаёт свои таблицы при первом обращении).
6. **Личные тексты не публикуются.** Корпус пополняется только через модерацию; в статистику идут обезличенные счётчики.
7. **Новые env-ключи — в хвост `.env.example`**, имена с полным слагом (`NJ645_…`).
8. **Изменил таблицу/манифест — обнови `tests/Unit/ManifestRegistryTest.php`** (реестры каналов и чисток сверяются дословно) и этот файл.

## Не трогать / подводные камни

- `INSERT … RETURNING` выполняется как `DB::query(Database::SELECT, $sql, FALSE)` — иначе драйвер вернёт `[lastInsertId, rowCount]`, а не строку. `->current()` вызывается только на результате SELECT.
- Tailwind-классы, которые JS пишет в HTML-строки, должны быть в файле целиком (`'+ var +'` не попадает в сборку). После правок вьюх — `npm install && npm run build:css`, CSS коммитится.
- `Service_Nj645_Store::ngram_rows()` строит SQL присваиванием — следить, чтобы строка заканчивалась `;`, а не `))`.
- `/llmlab/api/sample` ждёт параметр `context` (не `ctx`).
- Класс в `classes/Service/Nj645/` — Kohana-автозагрузка: файл `Service/Nj645/Lab.php` = `Service_Nj645_Lab`.
- Юнит-тесты: `tests/Unit/LlmlabServiceTest.php` — только чистая логика; БД и сеть в них не ходят.

## Как тестировать

- `php tests/mini_runner.php Llmlab` — 8 тестов Lab (токенизация, распределение, эмбеддинги, промпт, цена).
- `php tests/mini_runner.php Manifest` — каналы и чистки модуля в реестре.
- Живой дым: `curl -s -X POST -H 'Content-Type: application/json' -d '{"text":"привет мир"}' http://127.0.0.1:8080/llmlab/api/tokenize`.
- `POST /llmlab/api/run` без ключей должен отвечать `{"ok":false,"error":"…LLM не подключена…"}`, без 500.
- В БД после разборов появляются строки в `nj_645_tokenstats`; после `corpus` — в `nj_645_corpus` (статус `pending`).
