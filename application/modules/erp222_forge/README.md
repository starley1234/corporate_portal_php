# erp222_forge — Кузница систем (slug: forge)

## Что это

Перенос наработок владельца `source_data/erp222_aeterna_forge` (Koseven + pgvector,
«синтез информационных систем» группой LLM-агентов) в платформу n2j — с
пересмотром логики. В исходнике агенты **говорили о мире**: красивые рассуждения
на экранах Semantic Galaxy и Forge Eye, 15 d3-визуализаций и ни одного документа,
который можно открыть на второй день. Здесь наоборот: **ценность сервиса — готовый
документ**, а разговоры агентов не показываются вообще.

Что делает модуль: владелец описывает мир (задачу проектирования) человеческими
словами, запускает цикл, и группа ролей выпускает артефакты — спецификацию, схему
данных, контракт API, алгоритм, промпт, план проверки, разбор рисков, метрики,
оценку, оффер. Каждый артефакт получает **ценность 0–100** (не самооценку модели:
новизна считается сайтом, критику пересчитывает Критик), публикуется в каталоге и
читается людьми и поисковиками.

Прототип владельца лежит в `source_data/erp222_aeterna_forge/` как история
решения: оттуда взяты модель ценности, роли и `manual.md` с разбором ошибок
(«current transaction is aborted»), которые учтены в `Service_Erp222_Artifact`.

## Цикл синтеза

```
владелец → POST /forge/step (CSRF) → nj_120_jobs (канал erp222.forge)
  ↓ python-воркер n2j_workers/handlers/erp222_forge.py
  1. POST /forge/api/step {run_id} → план шага: роль, тип документа, признак
     готовности, уже выпущенное, контекст (факты и идеи ИИ-радара), рубрика;
  2. LLM пишет документ по строгому JSON (title/summary/body/metadata/scores/
     depends_on/sources) в четыре раза дешевле «рассуждений о мире»;
  3. проверка на воркере «документ или пересказ» (_document_gaps): короткое
     тело, нет входов/выходов, контракт без методов, схема без DDL, риски без
     меры, метрики без источника → один повторный проход на доработку;
  4. POST /forge/api/artifact → сайт нормализует, дедупит по отпечатку,
     считает новизну и ценность, ставит связи (depends_on);
  5. Критик получает САМЫЙ ЦЕННЫЙ неразобранный артефакт мира и пересчитывает
     его оценки (target_scores) — ценность в каталоге меняется по разбору;
  6. POST /forge/api/finish → цикл закрыт, статистика в erp_222_runs.stats.
```

Роли и порядок — `config/erp222_forge.php` (`roles`): Архитектор (спецификация,
схема данных) → Инженер (контракт API, алгоритм) → Аналитик (метрики, оценка) →
Критик (разбор рисков) → Редактор (промпт, план проверки, оффер). Тип внутри роли
чередуется по кругу, поэтому цикл из шести шагов не даёт трёх одинаковых
документов.

## Как считается ценность

`Service_Erp222_Forge::value_score()` — взвешенная сумма осей
(`config value_weights`): полезность 0.35, конкретность 0.30, новизна 0.20,
реализуемость 0.15. Три правила, из-за которых оценке можно верить:

- **новизну считает сайт**, а не модель: 1 − максимальное пересечение слов
  заголовка и сводки с уже выпущенным миром (слова короче 4 знаков
  отбрасываются, как в трендах). Самооценка модели в этом месте бесполезна;
- **молчание не наказывается**: ось, которую роль не назвала, считается
  нейтральной (0.5) — артефакт не падает в ноль из-за отсутствия строки в JSON;
- **критика меняет ценность разобранного**: у Критика есть право переставить
  оценки чужого документа, и в каталоге это видно (`critique` + событие).

Повтор шага (та же мысль в тех же словах) не создаёт копию: отпечаток
`title+summary` возвращает `{duplicate: true}` — воркер считает такие шаги
отдельно и не раздувает каталог.

## Публичный слой

- `/forge/artifacts` — каталог опубликованных артефактов: свежие сверху, поиск
  (`?q=`), фильтр по типу (`?type=risk`), пагинация; в карте сайта и в манифесте
  модуля (`sitemap`).
- `/forge/artifact/<id>` — страница документа: тело, «Опирается на» (связи),
  разбор Критика, стоимость всех осей, «Скопировать документ» одной кнопкой.
  Неопубликованный артефакт отдаёт 404 всем, кроме владельца.
- Публикуется **по умолчанию**; владелец снимает с публикации (доктрина модулей
  трендов и ИИ-радара), тогда адрес уходит из карты сайта.

Владельцу (audience admin, `acl.php` → `erp222.forge` → admin): `/forge` —
дашборд с живым ходом цикла, `/forge/worlds` и `/forge/world/<code>` — миры,
роли, циклы и артефакты мира.

## Живой ход цикла

Запуск уходит fetch-ом (`X-Requested-With: XMLHttpRequest` → JSON, обычная форма
→ 303 и работает без JS), карточка хода появляется сразу и живёт по
дизайн-эталону `/pages/required_design_sample`: спиннер + название этапа +
секундомер одним неразрывным рядом, лестница «Роли → Синтез → Критика → Сводка»
(пройденные зелёные, текущий жирный), счётчики числом («шаг 4/6 · артефактов: 3 ·
ценность: 240»), полос хода нет. Опрос `/forge/progress` раз в 3 с, секундомер
между опросами тикает локально, по завершении страница перезагружается — свежие
артефакты уже в разметке. Кнопка «Один шаг» уходит как `quick=one` (полный цикл
против одного шага — разные вещи). Формы публикации используют «взведённую»
кнопку вместо `window.confirm`.

## Структура

```
config/erp222_forge.php            роли, типы артефактов (с признаком готовности),
                                   оси ценности, лимиты (steps, run_stale_min 90)
config/nj_module.php               манифест: канал erp222.forge + reconcile,
                                   публичный /forge/artifacts, чистка runs/events
classes/Service/Erp222/Forge.php   ядро: чистые функции (value_score, unit_scale,
                                   novelty, fingerprint, run_progress, counters_text,
                                   value_word, type_proof) + БД: миры, циклы,
                                   события, лента, активный цикл, _close_if_dead
classes/Service/Erp222/Artifact.php приём артефакта от воркера: normalize, дедуп,
                                   novelty, ценность, связи, критика, публикация
classes/Controller/Erp222/*.php    Main (шаблон, ACL, шапка), Index (дашборд,
                                   /progress, /step), Worlds (миры), Artifacts
                                   (каталог, страница, публикация), Api (приёмная
                                   воркера: step/artifact/progress/finish/tick)
views/erp222/*.php                 index, worlds, world, artifacts, artifact, card
migrations_pg/pgMigration_Erp222_001_Forge_CreateTables.php  erp_222_worlds|roles|
                                   artifacts|links|runs|events
```

Воркер: `workers/n2j_workers/handlers/erp222_forge.py` (канал `erp222.forge`,
регистрация в `handlers/__init__.py`), настройки — `ERP222_FORGE_*` в
`workers/.env.example` (модель, контекст, бюджет цикла 2400 с, таймаут шага 420 с,
доработка `ERP222_FORGE_POLISH=1`).

## Расширение

- Новая роль: ключ в `config/erp222_forge.php` → `roles` (+ при необходимости
  `ROLE_VOICE` в воркере). Миры берут роли из конфига при создании.
- Новый тип артефакта: `types` (title, about, proof, icon) + правило проверки
  готовности в `_document_gaps` воркера, если у типа есть проверяемый признак.
- Другая модель мира: поле `model` у мира (личный инструмент — эксперименты
  ожидаемы), иначе `llm.default_model` платформы.

## Состояние работ

Сайт проверен вживую (каталог, страницы, публикация, карта сайта, живой ход
цикла, приёмная воркера через API). Воркер проверен тестами и стендом; сквозной
прогон воркера в песочнице (мок-LLM → очередь → артефакты в каталоге) —
следующий шаг, заготовки для него лежат в `source_data/erp222_aeterna_forge`
и `/home/user/erp222_mock`.
