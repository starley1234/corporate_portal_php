## Что это

Личный инструмент владельца (audience admin), но с публичной витриной: группа
LLM-ролей проектирует систему по постановке владельца и выпускает **артефакты** —
готовые документы, по которым можно начинать работу: спецификация, схема данных,
контракт API, алгоритм, промпт, план проверки, риски, метрики, оценка, оффер.
У каждого артефакта есть **ценность 0–100** (свёртка четырёх осей по весам
конфига), поэтому каталог сортируется по ценности, а не по времени: сверху то,
что действительно готово к работе.

Слово владельца (08.10.2026): «интегрируй наработки `source_data/erp222_aeterna_forge`
в сервис n2j.ru, соблюдай дизайн `/pages/required_design_sample`, пересмотри всю
логику: нужно, чтобы модуль формировал ценные и полезные артефакты и был интересен».
Отсюда три решения, которые отличают этот модуль от исходных наработок:

1. **Артефакт вместо «сущности».** В наработках агенты писали в Universal Store
   любые сущности с одним score и логом эволюции; читать это было нельзя.
   Здесь у артефакта тип из словаря (10 типов), требование «чем доказывается»
   (type_proof), разложенные метаданные (входы, выходы, допущения, открытые
   вопросы), четыре оси оценки, связи с другими артефактами и разбор Критика.
2. **Витрина для людей и поисковиков.** `/forge/artifacts` — публичный каталог
   (поиск, фильтр по типу, пагинация общим партиалом), `/forge/artifact/<id>` —
   публичная страница документа; публикуется по умолчанию, владелец может снять
   с публикации. Всё остальное (дашборд, миры, циклы, публикация) — под замком
   `can('erp222.forge')`.
3. **Работа видна.** Цикл — задача очереди nj120 (канал `erp222.forge`), на
   странице живой статус-ряд: спиннер + этап + секундомер одним неразрывным
   рядом и лестница «Роли → Синтез → Критика → Сводка» (по дизайн-эталону
   `/pages/required_design_sample`, полос хода нет).

## Конвейер

```
владелец → POST /forge/step → start_run(): erp_222_runs + JobQueue 'erp222.forge'
  ↓ python-воркер erp222_forge.handle(ctx, {run_id, world_id, steps, limits, model})
  1. POST /forge/api/step {run_id} → план шага: роль, тип, мир, уже выпущенное,
     база знаний ИИ-радара (факты/идеи), «чем доказывается», рубрика оценки;
  2. post /forge/api/progress — живой этап (спиннер/этап/секундомер на странице);
  3. один LLM-вызов со строгой JSON-схемой → документ (title/summary/body/
     metadata/scores/depends_on/sources);
  4. локальная проверка «документ или пересказ» (_document_gaps): короткое тело,
     нет входов/выходов, контракт API без методов, схема без DDL, риски без меры —
     одна доработка (не больше, ERP222_FORGE_POLISH=0 выключает);
  5. POST /forge/api/artifact → сайт дедупит по отпечатку, САМ считает новизну
     (пересечение слов с уже выпущенным) и ценность, сохраняет и связывает;
  6. шаг Критика: он получает самый ценный неразобранный артефакт мира
     (plan.target), возвращает разбор + target_scores — сайт ПЕРЕСЧИТЫВАЕТ
     ценность разобранного (apply_critique) и пишет связь refines;
  7. POST /forge/api/finish {status, stats}.
```

Роли идут по кругу от Архитектора к Редактору (порядок = порядок мысли), тип
внутри роли чередуется, поэтому цикл из 6 шагов обходит все пять ролей и не
выпускает три одинаковых документа. Каждый шаг — ОДИН вызов модели: длину
цикла владелец выбирает сам (1–12, по умолчанию 6).

## Правила модуля

1. **Ценность считает сайт, а не модель.** Ось novelty воркер не присылает —
   сайт считает её сам (пересечение слов с уже выпущенным миром). Самооценка
   модели проходит через `unit_scale` (0..1 или проценты) и веса конфига.
2. **Критика меняет ценность разобранного.** `Service_Erp222_Artifact::apply_critique`
   перезаписывает `scores` и `value_score` ЦЕЛИ (не только сохраняет текст
   разбора) — это и есть «эволюция» наработок без отдельного лога.
3. **Повтор шага не создаёт копию.** Отпечаток `fingerprint(title, summary)`
   ловится по миру: дубль возвращает `['duplicate' => TRUE]` и не тратит место.
4. **Связи только внутри мира.** `depends_on` чужого мира отбрасывается: ссылка
   на артефакт другого мира была бы фантазией.
5. **Публичность — у артефактов.** Дашборд, миры, запуски и переключатель
   публикации закрыты `can('erp222.forge')`; каталог и опубликованные артефакты
   открыты, снятый с публикации отдаёт 404 всем, кроме владельца.
6. **Один вызов модели на шаг.** Никаких скрытых циклов «до идеала»: иначе цикл
   из 6 шагов превращается в 20 вызовов и владелец не понимает, за что ждал.
   Единственное исключение — одна доработка по проверке документа.
7. **Прогресс идёт из воркера.** Воркер пишет этап через `/forge/api/progress`,
   сайт только показывает; строка счётчиков считается сервером
   (`counters_text`), JS её не собирает.

## Таблицы (полное владение)

- `erp_222_worlds` — миры: code, title, brief, protocol, goal, domain, status
  (active/paused), model, steps_done, artifacts_done, value_total, owner_id.
- `erp_222_roles` — роли мира: code, title, focus, types («spec,schema»), sort, enabled.
- `erp_222_artifacts` — артефакты: type, title, summary, body, metadata/scores
  (JSON), depends_on/sources (JSON), value_score 0..100, critique, novelty_hash,
  published BOOLEAN NOT NULL DEFAULT TRUE.
- `erp_222_links` — связи (refines, depends_on, contradicts, implements).
- `erp_222_runs` — циклы: status (new/running/done/fail), stage, stage_note,
  steps_planned/done, role_code, artifacts_new, stats (JSON), finished_at.
- `erp_222_events` — лента: kind (run/step/artifact/critique/note/error), message.

## Маршруты и API

- `GET /forge` — дашборд владельца (счётчики, ход цикла, свежие артефакты, лента).
- `GET /forge/progress` — JSON хода цикла (поллит JS, вид тот же, что у страницы).
- `POST /forge/step` — запуск цикла или одного шага (AJAX → JSON, иначе 303).
- `GET/POST /forge/worlds`, `GET /forge/world/<code>`, `POST …/status` — миры.
- `GET /forge/artifacts` — ПУБЛИЧНЫЙ каталог (q, type, per, page).
- `GET /forge/artifact/<id>` — ПУБЛИЧНАЯ страница артефакта.
- `POST /forge/artifact/<id>/publish` — публикация (владелец, «взведённая» кнопка).
- `POST /forge/api/{step,artifact,progress,finish,tick}` — приёмная воркера
  (`X-Worker-Token`; пустой токен = закрыто вне `KOHANA_ENV=development`).

## Очередь

- Канал: `erp222.forge` (постановка `Service_Nj120_JobQueue::push`, `timeout_sec`
  2700, `max_attempts` 2).
- Обработчик: `workers/n2j_workers/handlers/erp222_forge.py` (HANDLERS).
- Манифест: `'worker' => ['channels' => ['erp222.forge' => …]]` в
  `config/nj_module.php` — reconcile: цикл закрыт ИЛИ уже выпустил артефакт.
- Порог «воркер молчит» поднят в `nj120_jobs.silent_stop_channels` (3000 с):
  шаг — вызов LLM, пауза на локальной модели бывает длинной.
- Расписания нет: цикл — осознанное действие владельца. `POST /forge/api/tick`
  живёт для автоматизации (crontab), но по умолчанию не пинается.

## Env

- `NJ120_API_BASE` / `WORKER_SITE_TOKEN` — общие (адрес сайта и токен воркера).
- `ERP222_FORGE_API_BASE` / `_SITE_TOKEN` — если канал живёт на другом сайте.
- `ERP222_FORGE_MODEL` — «провайдер::модель» для шагов (пусто = умолчание воркера).
- `ERP222_FORGE_CONTEXT` — контекст модели в токенах (срезы промпта, бюджет ответа).
- `ERP222_FORGE_MAX_TOKENS`, `ERP222_FORGE_POLISH`, `ERP222_FORGE_BUDGET`,
  `ERP222_FORGE_STEP_TIMEOUT` — тонкая настройка (всё в `workers/.env.example`).
- Сайт: `ERP222_FORGE_MODEL`, `ERP222_FORGE_STEPS_MAX` (config/erp222_forge.php).

## Зависимости

- От модулей: nj120_jobs (очередь), nj661_airadar (база знаний: факты и идеи
  подмешиваются в вводную шага), erp100_base (Controller_Erp100_Base),
  nj602_content (sitemap.xml — адреса каталога и артефактов), nj110_catalog

- Для других: `Service_Erp222_Forge` и `Service_Erp222_Artifact` могут читать

## Правила, которые нельзя нарушать

1. Не считать novelty у воркера: новизна зависит от уже выпущенного мира и
   пересчитывается на сайте при каждом приёме.
2. Не публиковать артефакт с `value_score`, посчитанным только самооценкой
   модели: если осей нет, они берутся нейтральными (0.5), а не нулём — но и в
   каталоге такой артефакт стоит ниже разобранного Критиком.
3. Не трогать `erp_222_artifacts.published` напрямую из SQL мимо
   `set_published()`: событие «снят с публикации» — часть истории мира.
4. Тело артефакта режется на 24 000 знаках (`BODY_MAX`) — документ, а не лог
   агента; воркер режет раньше (20 000).
5. Никакого `window.confirm` в интерфейсе: два клика по «взведённой» кнопке.
6. CDN-графики из наработок (D3/three/fa) не переносить: платформа собирает CSS
   сама, а визуализация без пользы — шум.

## Не трогать / подводные камни

- `source_data/erp222_aeterna_forge/` — ТОЛЬКО источник вдохновения. Это
  Koseven-проект с `Route::set`, ACL `saas_forge.*`, `public.vector(1024)` и
  моделями, которых нет в n2j (`Erp222_Market`, `Service_Erp222_SaasForge`).
  Копировать оттуда код нельзя; осмысленные идеи — в этом модуле.
- `Request::post($key, $default)` в Kohana — второй аргумент ЗАПИСЬ, а не
  значение по умолчанию: только `Arr::get($_POST, …)`.
- `is_ajax()` понимает только заголовок `X-Requested-With: XMLHttpRequest`.
- Ловушка маршрутов: статический `/forge/worlds` объявлен ВЫШЕ
  `/forge/world/<code>`, иначе `worlds` попадает в `<code>`.
- Не использовать `pgvector`: он есть только в наработках. Новизна считается
  словами (nj115 умеет и так, и так — здесь даже это не требуется).

## Как тестировать

```bash
bash bin/test                                     # mini_runner: tests/Unit + Smoke
php .tools/erp222_forge_stand.php                 # чистые функции сервиса и вёрстка
npm run test:forge:ui                             # поведение страницы в jsdom
cd workers && python -m pytest tests/test_erp222_forge.py -q   # чистые функции воркера
bash .tools/php_check_all.sh application          # линтеры проекта
npm run build:css                                 # после правок вёрстки (классы Tailwind)
```

Стенд с `--dump-ui=<каталог>` отдаёт HTML страниц модуля (живой цикл,
завершённый, пустой, карточка артефакта) — их и берёт jsdom-проверка
`.tools/erp222_forge_ui.mjs`. Порядок тот же, что у `/similar`: php-стенд
рисует настоящую вёрстку, JS-проверка двигает таймеры и подменяет fetch.

Прогон вживую (песочница): `bash bin/setup-sandbox.sh --skip-build`, затем
`PORT=8080 bash bin/serve`; дашборд `/forge` — под админом, каталог
`/forge/artifacts` виден без входа. Цикл без воркера можно изобразить curl-ом:
`POST /forge/api/step` → `POST /forge/api/artifact` → `POST /forge/api/finish`
(см. раздел «Состояние работ»).
