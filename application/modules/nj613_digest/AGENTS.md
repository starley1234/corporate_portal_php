# Дайджест руководителю (nj613_digest) — памятка для агентов

Раз в неделю — короткая человеческая сводка по вашим данным:

- что нашёл радар заказов и сколько новых лидов;
- что произошло во входящих и сколько касаний отправлено;
- сколько статей опубликовано.

LLM собирает это в пару абзацев, а не в сухую таблицу. Доставка — на страницу
`/digest`, в уведомления и на почту (если она указана).

Если за неделю ничего не произошло — дайджест не приходит, чтобы не шуметь.

## Как это устроено

```
пиналка (ежедневно) → счётчики недели → задача nj120 (nj613.digest) →
LLM-резюме → страница /digest + уведомление + письмо
```

Настройки подписки (день недели, вкл/выкл) — на `/digest`.

## Админка

`/nj613/admin` — последние сводки и подписки (роль admin).

## Правила для агента

## Состояние
- **Сервис** «Дайджест руководителю» (`/digest`, `hidden: TRUE` — аккаунтная
  страница): раз в неделю короткая человеческая сводка по данным пользователя —
  находки радара (nj605), лиды (nj606), новые входящие (nj610), отправленные
  касания (nj612), опубликованные статьи (nj602).
- LLM пишет резюме; доставка — на страницу + колокольчик nj597 + письмо (SMTP),
  если у пользователя указан email.
- Подписка создаётся лениво при первом заходе; период `PERIOD_DAYS = 7`.

## Конвейер (не в HTTP)
- Пиналка nj603 раз в день → `POST /digest/api/tick`: для созревших подписок
  сайт считает счётчики недели (`week_stats`) и ставит задачу nj120 канала
  **`nj613.digest`** → воркер пишет резюме → `POST /digest/api/item` → сайт
  сохраняет, уведомляет, шлёт письмо.
- Неделя **без событий** — дайджест не ставится (просто переносится срок), чтобы
  не спамить пустышками.

## Классы и файлы
- `Service_Nj613_Digest` — подписки, счётчики, tick, save_item, admin.
- `Controller_Nj613_Digest` — `/digest` (мои дайджесты + настройки).
- `Controller_Nj613_Api`    — `tick` (пиналка), `item` (приём резюме).
- `Controller_Nj613_Admin`  — `/nj613/admin`.
- `views/613/{index,admin}.php`.
- `migrations_pg/pgMigration_Nj_613_001_Digest.php`.
- `config/nj_module.php` — манифест.

## Таблицы
| Таблица | Назначение |
|---|---|
| `nj_613_subs`   | подписка (user_id, weekday, enabled, last_sent) |
| `nj_613_digests` | сводки (user_id, date_from, date_to, stats JSONB, summary, status new/ready) |

## API
```
POST /digest/api/tick   пиналка nj603 → {ok, queued}
POST /digest/api/item   приём резюме от воркера (X-Worker-Token) → {ok}
```

## Безопасность и конвенции
- `week_stats` читает чужие таблицы через **пустой try/catch** (модуль может
  отсутствовать) — осознанное исключение из «не лезь в чужие таблицы»: сводка
  по собственной неделе пользователя, только счётчики.
- Почта — `Service_Nj597_Mail`, уведомление — `Service_Nj597_Notify`
  (не дублировать транспорт).
- API наследует `Controller_Nj120_Api` (токен воркера проверяется родителем).

## env (в хвост .env.example)
```
NJ613_DIGEST_API_BASE=http://127.0.0.1/digest/api
NJ613_DIGEST_SITE_TOKEN=CHANGE_ME   # токен в окружении воркера
NJ613_DIGEST_MODEL=
```

## Ограничения
- Без воркера `nj613.digest` резюме не появляются (сводки застревают в `new`).
- Читает счётчики nj605/606/610/612/602 — падение любого модуля не валит сбор
  (возвращается 0).
