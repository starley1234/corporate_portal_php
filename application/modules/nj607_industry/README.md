# Карта отрасли (nj607_industry)

Два способа разобраться в отрасли:

- **Авто-карта** — задайте отрасль и регион: за минуты получите отчёт, кто
  производит, что и как, сегменты, цены (где видны), каналы продаж и
  возможности входа. Сбор платный (кредит nj601).
- **Разведка под запрос** — закажите ручной отчёт: владелец подготовит
  развёрнутую разведку и закроет заказ готовым документом.

Готовый отчёт открывается по ссылке вида `/industry/<code>` (Markdown-представление).

## Как это устроено

```
форма → задача nj120 (nj607.industry) → python-воркер (открытые источники + LLM)
→ отчёт Markdown → страница /industry/<code>
```

Для зарегистрированных пользователей (отчёты привязаны к аккаунту); ручная
разведка доступна и гостям по visitor_id.

## Админка

`/nj607/admin` — заказы разведки и авто-сборы: статусы, закрытие заказов,
перезапуск, удаление (роль admin).

Подписи статусов отчёта в интерфейсе переводятся через i18n-ключи
`nj607.industry.report.status.*`. Машинные значения в БД и API (`new`,
`running`, `done`, `error`, `closed`) не меняются.

## Онтология: сущности отчёта и связи с другими модулями (26.09.2026)

Владелец: «отчёт хороший — его оставь, но и сделай из него сущности, которые
надо будет связать с другими модулями. Наша цель — связанная онтология».
Отчёт остаётся текстом; дополнительно из него делается словарь сущностей.

```
отчёт Markdown → разбор (без LLM, детерминированно) → nj_607_entities
                → поиск совпадений в нашей базе → nj_607_links → /industry/entity/<slug>
```

* **Виды сущностей** (`kind`): `company` (игроки рынка с сайтами), `region`
  (регион отчёта + узнанные регионы РФ), `segment` (сегменты/продукты из
  разделов отчёта). Одна сущность — одна запись на `kind + slug`, сколько бы
  отчётов её ни упомянули: это и есть онтология («одна компания — одна запись»).
* **Разбор без выдумок**: берём только то, что написано в отчёте (строки
  раздела «Кто на рынке», списки разделов про сегменты, домены и регионы из
  текста). Строки «нет данных» пропускаем.
* **Связи (`nj_607_links`) — только реально найденное в базе**: профиль компании
  по домену (`/company/<code>`), организация по названию (`/orgs/<ogrn>`),
  досье/документы через общий поиск, отчёты по тому же слову (`/industry/<code>`).
  Нет совпадения — нет связи (ничего не додумываем).
* **Страница сущности** `/industry/entity/<slug>`: что известно, в каких отчётах
  встречается, связанные объекты других модулей и кнопки «продолжить» —
  `/radar?query=…` (спрос по продукту), `/leads?industry=…` (поток поставщиков),
  `/company?q=<домен>`.
* Разбор идемпотентен: повторный прогон ничего не дублирует. Отчёт, собранный до
  появления разбора, обрабатывается лениво при первом открытии страницы.

## Автозаполнение браузера не используем

Владелец: «не используй автозаполнение браузером». Поля отрасли и региона:
`autocomplete="off" autocapitalize="off" autocorrect="off" spellcheck="false"`,
а подсказки даёт **наша база** («Часто спрашивают» — отрасли и регионы из
`nj_607_reports`, по частоте и свежести). Поля предзаполняются ссылкой
(`/industry?industry=…&region=…`) — так сюда приходят связи из других модулей.
