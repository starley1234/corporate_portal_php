# nj590_design — «Дизайн страницы»

Сервис выбора дизайна: пользователь присылает URL страницы (+ необязательные
пожелания), воркер скачивает страницу, LLM разбирает её и готовит N (по
умолчанию 3, максимум 5) вариантов улучшенного дизайна. Каждый вариант —
самодостаточный HTML-файл (инлайн-CSS, без внешних ресурсов и скриптов).
Пользователь сравнивает варианты в iframe-превью и выбирает лучший —
выбор сохраняется в `nj_590_runs.chosen`.

## Адреса

- `/design` — форма создания + мои прогоны (создание — для зарегистрированных);
- `/design/<code>` — прогон: статус, варианты, выбор;
- `/design/<code>/file/<id>` — HTML-вариант (inline, для iframe);
- `/design/api/status/<code>` — статус + варианты (JSON);
- `/design/api/progress`, `/design/api/upload` — для воркера (X-Worker-Token);
- `/nj590/admin` — админка (роль admin): все прогоны, удаление/возврат.

## Данные

- `nj_590_runs` — прогоны (url, host, wishes, variants_count, status, error,
  progress, title/summary — разбор страницы от ИИ, chosen, job_id, usage);
- `nj_590_variants` — варианты (run_id, no, title, concept, path, size).
- Файлы: `DOCROOT/storage/nj590/ГГММ/<rand>.html` — СВОЯ папка модуля (файлы
  разных модулей не смешиваются), вне public_html. Каталог создаёт пинок
  (`bin/deploy.sh` → DEPLOY_MODULE_STORAGE, по умолчанию `storage/nj580 storage/nj590 storage/nj651`);
  писать может php-fpm. Путь `/home/n2j/…` не используем: php-fpm туда не пишет
  (бой 2026-09-20: HTTP 400 «Не удалось записать файл»).
- DDL: миграция 001 == идемпотентный `Service_Nj590_Design::ensure_tables()`;
  колонки model/model_used — миграции 002/003 (применённые не редактируются).
- Модель: в прогоне видно ЗАПРОШЕННУЮ и ФАКТИЧЕСКУЮ (`model_used` — сообщает
  воркер). Если LLM-слой обошёл модель (нет у провайдера / HTTP 400 →
  DEFAULT_MODEL) — в UI фактическая, а подмена видна строкой
  «(запрашивали …)» и в прогрессе/ошибке.

## Воркер

- канал `nj590.design` → `workers/n2j_workers/handlers/nj590_design.py`;
- env: `NJ590_API_BASE` (https://n2j.ru/design/api), `NJ590_SITE_TOKEN`
  (или общий `WORKER_API_TOKEN`), `NJ590_DESIGN_MODEL` (спека
  «провайдер::модель», по умолчанию — дефолтный провайдер),
  `NJ590_MAX_PAGE_BYTES`, `NJ590_FETCH_TIMEOUT`;
- скачивание страницы — только публичные адреса (private/loopback/link-local
  запрещены, лимит 3 МБ, 25 с); HTML вычищается (script/svg/base64/on*),
  LLM получает ≤48k символов + палитру из CSS;
- по варианту — отдельный LLM-вызов (строгий JSON {title, concept, html}),
  выгрузка на сайт с ретраем; прогресс — через /design/api/progress;
- затраты LLM — в `job.result.usage`, сайт дозаписывает в `nj_590_runs.usage`
  при reconcile.

## Безопасность

- HTML-вариант чистится на сервере: `<script>` и `on*`-атрибуты вырезаются
  при `add_variant()`; в UI вариант показывается в `<iframe sandbox>`;
- доступ к файлу варианта — по коду прогона в URL, владельцу или админу;
- админ-раздел — только роль admin; создание прогона — только вход.

## Выбор модели (админ)

Под полем URL — поле «Модель» (видит только администратор): спека
«провайдер::модель» или просто «модель» (провайдер по умолчанию). Пусто —
воркер берёт модель из `NJ590_DESIGN_MODEL`. Выбор запоминается в куках
`nj590_model` (180 дней), уезжает в payload задачи (`model`) и применяется
к генерациям вариантов (анализ страницы — всегда на дефолтной модели).

## Устойчивость к малым моделям

- `NJ590_DESIGN_INPUT_CAP` (по умолчанию 24000 знаков) — сколько вычищенного
  HTML уходит в промпт варианта;
- ответ модели разбирается каскадом: строгий JSON → ремонт (хвостовые запятые,
  «сырые» переводы строк внутри строк) → salvage-достаётся title/concept/html
  из обрезанного ответа; журнал: «вариант N восстановлен из нестрогого JSON»;
- в UI статуса видны повторные попытки очереди: «Повтор №2: Готовлю вариант…».
