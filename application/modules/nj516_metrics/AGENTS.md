# nj516_metrics — Метрики витрины — памятка для агента

Внутренний инструмент владельца: обезличенные просмотры публичных страниц сервисов,
популярные услуги/группы, источники переходов и доля гостевых/авторизованных просмотров.
Внешних счётчиков нет.

- Админка: `/nj516/admin` (только право `nj516.admin`, роль `admin`)
- Hit endpoint: `POST /nj516/api/hit` `{path:"/vat"}` — вызывается `window.N2J.trackPageView()` из `public_html/assets/js/app.js`
- Публичного API статистики нет; дашборд доступен только администратору
- Таблица: `nj_516_views` — дневные агрегаты; миграция `001_Views_Aggregate`
- Очистка: реестр `Manifest::cleanups()` → `/nj100/cleanup`, хранение 400 дней, порции по 5000
- На меня ссылаются: `docs/PLAN-2026-10-01.md` §4.2; `nj600_prefs` больше не владеет этой идеей

## Правила для агента

- **Список страниц — только из манифестов nj110.** Точный `href` публичного (`audience=public`, не draft) модуля; страницы объекта, API, админки, неизвестные URI, auth-only и query не считаются. `Service_Nj516_Metrics::public_pages()` — кэш внутри запроса.
- **Никаких идентификаторов.** В таблицу идут только `day`, canonical `path`, `group_name`,
  категория источника (`direct|internal|search|external`), аудитория (`guest|logged`), счётчик.
  Не добавлять visitor_id/ubid, IP, user-agent, referer, query-параметры, поисковые фразы.
  User-agent transient-only для отсева роботов; referer transient-only для классификации источника.
- Хранилище — один атомарный UPSERT на показ, не сырые события: конфликтный ключ
  `(day,path,group_name,source,audience)` инкрементирует `views`. Не менять на журнал
  посетителей и не включать уникальных пользователей.
- `app.js` вызывается на всех страницах; только этот сервис решает по манифесту, считать ли путь.
  Hit — POST same-origin, `keepalive`, best-effort. Ни API, ни БД не должны задерживать страницу.
- Добавили публичную услугу/переименовали `href` или группу — реестр подхватит автоматически;
  обновить тест `MetricsServiceTest`. Никакого ручного списка сервисов.
- Новые агрегаты — в закрытой админке; любая будущая выгрузка обязана оставаться агрегированной.

## Точка подключения

- Учёт вызывается из `public_html/assets/js/app.js`, а не копией базового класса
  контроллера: браузер отправляет только `location.pathname` на same-origin POST;
  сервер перепроверяет путь по манифестам. Query/fragment не отправляются.
- Причина: `Controller_Erp100_Base` принадлежит активному `erp100_base`; правило платформы
  требует переопределение в `application/classes`, а копировать его 506 строк ради одного
  хука хуже, чем использовать уже подключённый общий `app.js`. Если когда-нибудь вынесем
  pageview-счётчик в server hook, не править `application/modules/erp100_base` напрямую.
