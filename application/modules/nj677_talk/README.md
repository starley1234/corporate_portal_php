# NJ-677 «Разговор с ИИ голосом» (`/talk`)

Голосовой разговор с моделью: включили режим — говорите. Кнопок на каждую
реплику нет: конец фразы определяет тишина, ответ читается вслух, перебить
можно голосом.

Страница: **`/talk`** (по аккаунту). Публично видно описание сервиса с плашкой
входа — как у `/voice`.

## Что происходит после «Начать разговор»

```
микрофон ──► VAD в браузере ──► MediaRecorder ──► POST /talk/api/hear
                                                        │  текст реплики
                                                        ▼
                                        POST /talk/api/reply (Llm::chat)
                                                        │  ответ + parts[]
                                                        ▼
                   POST /talk/api/say × N (по частям, пока играет предыдущая)
```

1. **Одно нажатие.** `getUserMedia` + анализатор Web Audio включаются один раз.
   Уровень шума комнаты измеряется сам — порог речи подстраивается под него.
2. **Короткий сигнал — «слушаю».** Два тихих тона перед началом слушания, как
   звук активации у Алисы: по нему понятно, что микрофон действительно включён.
   Отключается галочкой «Сигнал перед ответом».
3. **Конец фразы — тишина 0,8 с.** Нажимать «стоп» не нужно; длинная реплика
   обрезается по лимиту `audio_sec` (не диктофон). Реплика короче 300 мс голоса
   не отправляется вовсе: это щелчок или кашель, а не слова.
4. **Микрофон берётся только на реплику.** Записали фразу — устройство сразу
   отпускается, до распознавания и озвучки. Пока страница говорит, микрофона
   у неё нет; после последней фразы — пауза 0,5 с на затухание колонок,
   сигнал и снова слушаем.
5. **Распознавание отдельной точкой.** `hear` возвращает текст, страница сразу
   показывает слова пользователя. Дальше идёт `reply` — модель отвечает.
   Так разговор не выглядит зависшим на одном длинном запросе.
6. **Озвучка по частям.** `reply` приносит `parts[]` — ответ, порезанный по
   границам фраз. Браузер заказывает следующую часть, пока играет текущая:
   первая фраза звучит на секунду-две раньше, чем при синтезе всего ответа.
7. **Перебивание.** Заговорили во время ответа — воспроизведение останавливается
   и начинается новая реплика (галочка «Перебивать голосом»). Перебить может
   только голос громче измеренного эха и длиной около 0,4 с: иначе ответ
   перебивал бы сам себя.

### Почему звук может казаться глухим

Пока браузер держит открытым микрофон, операционная система переводит вывод в
«режим связи»: включается подавление эха и автогромкость, а Bluetooth-гарнитура
переключается с A2DP на HFP — и **весь** звук страницы, включая озвучку ответа,
становится глухим и тихим. Поэтому поток закрывается сразу после записи
(`acquire()` / `release()` в скрипте). Если включить «Перебивать голосом»,
микрофон остаётся открытым на время ответа — это осознанный обмен: перебивание
включается ценой возможного ухудшения звука на гарнитуре.

Если голос всё равно кажется приглушённым, поставьте `NJ677_TTS_FORMAT=wav`:
mp3 у некоторых движков отдаёт мало высоких частот, wav — без потерь.

### Почему на тишине появлялись «субтитры»

Распознаватели семейства Whisper на тишине и шуме не отдают пустую строку — они
дописывают то, на чём учились: титры обучающих видео («Редактор субтитров
А.Семкин Корректор А.Егорова»). Отсюда три защиты: не отправлять тишину
(браузер), не писать во время ответа (браузер) и не пускать известные артефакты
в разговор (`plausible_speech()` на сервере). Правила узкие: живая фраза
«Спасибо за просмотр презентации, теперь к бюджету» проходит — это закреплено
тестом.

## API

| Метод | Адрес | Что делает |
|---|---|---|
| POST | `/talk/api/hear` | multipart `audio` + `voiced_ms` → `{ok,text,ms}`; шум и выдумки распознавателя → `422 {ok:false,noise:true}` |
| POST | `/talk/api/reply` | JSON `{talk,text,stt_ms}` → `{ok,talk,reply,parts,model,llm_ms}` |
| POST | `/talk/api/say` | JSON `{text,voice}` → аудио сырыми байтами (`Content-Type` по формату) |

Все три требуют аккаунт и CSRF (`csrf` в теле или `X-CSRF-Token`). Ошибки — JSON;
`401` содержит `login`, чтобы страница увела человека на вход.

## Данные и приватность

- Таблицы: `nj_677_talks` (код, владелец, тема, модель, голос, число ходов) и
  `nj_677_messages` (роль, текст, длина, время своего шага).
- **Аудио не хранится**: запись уходит на распознавание и удаляется, в базе
  остаётся только текст.
- Чистка: реплики и разговоры старше 30 дней (`/nj100/cleanup`).

## Настройки (`application/modules/nj677_talk/config/nj677_talk.php`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `NJ677_MODEL` | модель платформы | модель разговора |
| `NJ677_VOICE` | голос `nj665` | голос по умолчанию |
| `NJ677_LANGUAGE` | `ru` | язык распознавания и синтеза |
| `NJ677_SPEED` | `1.05` | скорость речи (разговор чуть быстрее нормы) |
| `NJ677_TTS_FORMAT` | `mp3` | формат озвучки ответа; `wav` — если mp3 звучит приглушённо |
| `NJ677_TTS_CHARS` | `200` | символов в одной части озвучки |
| `NJ677_TTS_PARTS` | `10` | частей на один ответ |
| `NJ677_HISTORY_TURNS` | `12` | реплик контекста |
| `NJ677_MAX_TOKENS` | `220` | длина ответа: разговор, а не лекция |
| `NJ677_RATE_PER_MINUTE` / `NJ677_RATE_PER_HOUR` | `20` / `240` | лимит ходов на аккаунт |

Распознавание и синтез идут через модуль `nj665_voice` — он единственный клиент
OmniVoice в проекте. Свой HTTP-клиент здесь не заводится; для ASR добавлены
`Service_Nj665_Voice::transcribe()` и переменные `NJ665_ASR_MODEL`,
`NJ665_ASR_TIMEOUT`, `NJ665_ASR_PATH` (если у шлюза свой путь распознавания).

## Ограничения

- Стриминга нет ни у `Llm::chat()`, ни у синтеза, поэтому «без задержек» — это
  короткие шаги, а не поток: озвучка начинается с первой готовой фразы.
- `getUserMedia` работает только в защищённом контексте: `https://` или
  `localhost`. На http-домене кнопка честно скажет, что микрофон недоступен,
  и предложит текстовую строку — она есть всегда.
- Автозапуск звука может быть запрещён политикой браузера до первого клика;
  страница об этом предупреждает, а не молчит.
- Safari пишет в `audio/mp4`, Chrome и Firefox — в `audio/webm`: формат
  определяется в браузере, а расширение подставляет сервер.
