# nj594_orgregistry — «Справочник организаций»

Единый хаб-справочник организаций и ИП платформы: официальные реквизиты
(ЕГРЮЛ/ЕГРИП, данные ФНС) + привязка материалов всех модулей к организации.
Модули «про организацию» (nj580 и следующие) привязывают артефакты через
`Service_Nj594_Orgs::link()`, а карточка организации показывает их одним списком.

## Адреса

`/orgs` (поиск: ОГРН/ОГРНИП, ИНН, название; открытые данные — гостям),
`/orgs/<ogrn>` (карточка), `/orgs/admin` (роль admin).
API: `GET /orgs/api/search?q=`, `GET /orgs/api/card/<ogrn>` (открыто),
`POST /orgs/api/refresh/<ogrn>` и `POST /orgs/api/import` — `X-Worker-Token`.
MCP: `nj594_org_search`, `nj594_org_card`.

## Данные

`nj_594_orgs` (ogrn UNIQUE, inn, kpp, form, short/full_name, address, okved,
okved_name, status, reg_date, director, source, raw JSONB, fetched_at),
`nj_594_links` (org_id → module + item_code UNIQUE, item_url, title, kind),
`nj_594_fns_calls` (client_ip, query, kind, status — журнал запросов к ФНС).
DDL: миграции 001/002 == `ensure_tables()`. Файлов нет — только БД.

## Лимит запросов к ФНС

Реестр не любит частых обращений и отвечает отказами при перегрузке, поэтому
каждый выход в egrul.nalog.ru проходит через мягкий лимит (`fns_quota()`):

* окна по IP: `NJ594_FNS_PER_MINUTE` (5) и `NJ594_FNS_PER_HOUR` (30);
* общий кап платформы: `NJ594_FNS_TOTAL_PER_HOUR` (120) запросов в час;
* перерыв на повтор: если по этому же номеру/названию ФНС только что ничего не
  нашла, повторно не спрашиваем `NJ594_FNS_COOLDOWN` секунд (120; 0 — выключить);
* таймаут запроса: `NJ594_FNS_TIMEOUT` (12 с).

Лимит не ломает сервис: `refresh()` возвращает `['error' => …, 'limited' => TRUE]`,
`fns_search()` — пустой список, а UI (карточка /check, /orgs, админка) показывает
человеческий текст «попробуйте через минуту/час». Все выходы пишутся в
`nj_594_fns_calls`; сводка и журнал — в `/orgs/admin` («Запросы к ФНС»).
Кнопки администратора вызывают `refresh($num, TRUE)` — лимит ПО IP обходится
(человек кликает руками), общий кап платформы действует всегда.

## Источники данных

1. **Точечные карточки — сервис ФНС egrul.nalog.ru** (без ключей): GET `/`
   (cookie) → POST `{query}` → `{"t": token}` → GET `/search-result/{token}`.
   Реализовано: `Service_Nj594_Orgs::fns_card()` (также в nj580 Api).
2. **Полный импорт (перспектива) — открытые данные ФНС**:
   `nalog.gov.ru/opendata/7707329152-egrul/` (ЕГРЮЛ) и `…-7707329152-egrip/`
   (ЕГРИП): ZIP-архивы XML (форматы ЕГРЮЛ 4.07/4.08, ЕГРИП 4.06/4.07),
   полный слепок ≈15 ГБ, далее суточные дельты; доступ после acceptance
   лицензии. Платный сертифицированный канал — `ftp.egrul.nalog.ru`
   (сертификат PKCS#12) — не требуется.
3. **План импорта при малом диске сайта**: скачивание и потоковый разбор
   XML — на воркер-сервере (архив → XMLReader → порции ≤500 карточек →
   `POST /orgs/api/import` с `X-Worker-Token` → на сайте хранится только БД,
   файлы сразу удаляются). Обновление — суточными дельтами тем же конвейером.
4. Демо-посев: `seed_rows()` — 12 организаций из открытых источников
   (Сбербанк, Яндекс, Газпром, РЖД, Лукойл, Магнит, Ростелеком, Вкусвилл,
   Ozon, РВБ, X5, ТБанк); контрольные цифры ОГРН/ИНН проверены `ogrn_valid()`
   / `inn_valid()`. Пустые поля дополнит «Обновить из ФНС».

## Интеграция модулей

* положить/обновить карточку: `Service_Nj594_Orgs::upsert($ogrn, $fields, $source)`;
* привязать материал: `::link($module, $item_code, $org_id, $title, $url, $kind)`;
* организацию по своему артефакту: `::org_for_item($module, $item_code)`;
* nj580 уже подключён: при создании пакета организация регистрируется в
  справочнике и пакет появляется в блоке «Материалы платформы» карточки;
  при отсутствии локального кэша nj580 добирает карточку из справочника.

## Env

Новых переменных нет: ФНС работает без ключей, API воркера использует общий
`WORKER_API_TOKEN`. Появятся при полном импорте — сразу в `workers/.env.example`.

## Каналы воркера

Пока нет. Импорт ЕГРЮЛ будет отдельной задачей воркера (например,
`nj594.import`) — запускать вручную/по расписанию на воркер-сервере.
