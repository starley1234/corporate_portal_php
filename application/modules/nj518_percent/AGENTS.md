# nj518_percent — Калькулятор процентов — памятка для агентов

Публичный сервис N2J (группа «Финансы»): десять режимов — процент от числа,
сколько % составляет, прирост/убыль, увеличить/уменьшить на %, число по части,
наценка, маржа, наценка+маржа по цене, скидка. У каждого — формула с
подстановкой чисел и дополнительные строки (прибыль, экономия, обратный путь).

- Страница: `/percent` (share-ссылки `?m=markup&a=700&b=40`)
- API: `GET|POST /nj518/api/calc` `{mode,a,b}`, `GET /nj518/api/modes` (публичный JSON)
- Таблиц, миграций и воркеров нет; вся математика — `Service_Nj518_Percent::calculate()`
- Зависимости от других модулей: нет

## Правила для агента

- **Stateless:** без БД/очередей. Числа на сервер не сохраняются — только в адресе.
- **Две реализации одной формулы:** PHP (`Service_Nj518_Percent`) — истина,
  JS-зеркало — `views/518/script.php`. Меняешь формулу или текст результата —
  меняй оба и прогоняй `php tests/mini_runner.php PercentService` и
  `BASE=http://localhost:8080 node tests/Js/percent_parity.mjs` (сайт запущен, нужен `npm i --no-save jsdom`;
  жмёт «пример» каждого режима в странице и сверяет с API; без jsdom — SKIP).
- Режим добавляется записью в `modes()` (title, tpl с `{a}`/`{b}`, подписи, пример `ex`)
  + веткой `switch` в PHP и JS; у каждого режима обязан работать собственный пример
  (тест `test_every_mode_has_example_that_works`).
- **Наценка ≠ маржа:** наценка — от себестоимости, маржа — от цены продажи.
  Не смешивать в подписях.
- Округление «от нуля» до 4 знаков, нули срезаются; пробел-разделитель — NBSP.
