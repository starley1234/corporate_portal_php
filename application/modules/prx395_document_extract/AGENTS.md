# prx395_document_extract — PDF → текст (асинхронно)

Машинный API для СЭД/ERP не зависит от сессий, HR, LLM или `docflow`.
`/prx395_document_extract` — отдельный административный UI: сессия + CSRF и
своё пространство владельца, недоступное машинным ключам. Пробный PDF проходит
тот же конвейер; стадии видны в `/prx120/monitor`.

**Разделение с `prx450`.** `prx395` — асинхронный: пачки PDF, очередь `prx120`
и Tesseract, ответ `202` + polling, приватные артефакты `prx212` с TTL 24 ч.
`prx450` — синхронный: один документ, внешний OCR-шлюз, ответ сразу, файл
не хранится. Оба модуля остаются: это разные задачи.

- Доступ — ключ `prx150` + scope `prx395.extract`. Своей карты токенов нет:
  `Service_Prx395_Clients` и `PRX395_DOCUMENT_EXTRACT_CLIENTS` удалены.
  Ключ, лимит и отзыв — в `/prx150_api_hub`.
- `POST /api/v1/document-extractions`: Bearer-ключ + `Idempotency-Key` +
  multipart `file`. Ответ `202` `{job_id, status_url}`. Идемпотентность —
  платформенная (`Prx_Idempotency`): тот же ключ и тот же файл → тот же
  `job_id`; другой файл → `409 idempotency_conflict`; истёкший TTL →
  `409 idempotency_key_expired`. `prx120::push` и ссылка на задание лежат
  в одной транзакции с ключом.
- `GET /api/v1/document-extractions/<id>`: проверка владельца **до** чтения
  очереди, `Cache-Control: no-store`. Состояние и попытка берутся из prx120.
- Владелец задания — целочисленный ID ключа (`api_client_id`), поэтому чужое
  задание не видно даже по угаданному ID. Админка использует отрицательный ID
  пользователя: положительные заняты ключами prx150.
- `/prx395/worker/health`: проверяет тот же токен и сообщает, загружен ли
  старый контур для каналов `doc.*`; `--check-site` не ставит задач.
- `/prx395/worker/<id>/file|result`: `X-Worker-Token` переносится и в PG,
  и в HTTP-режим; `X-PRX-Worker-Attempt` соответствует взятой попытке.
  Результат публичен для владельца только после `complete` той же попытки
  с квитанцией. Сохранение для одной попытки идемпотентно.
- Исходник и текст — приватные артефакты `prx212` с `module=prx395`, без имён
  от пользователя. В очереди ни текста, ни PDF, ни ключей, только ID задачи,
  метки стадий, код отказа/квитанция. В модуле только связь ID и метаданные.
- Владеет `prx_395_extractions` и `prx_395_results`; читает очередь и файлы
  только через публичные сервисы. При ошибке не логировать тело HTTP/документ.
- После 24 ч результат недоступен. `prx395:purge` запускать таймером: удаляет
  исходники/результаты, подчищает старые файлы без ссылок после аварий.

## Состояние

Каркас переведён на контур prx150: ключи, scope, идемпотентность и целочисленный
владелец задания. Не проверено на PHP-стенде: миграция `prx_395_002`, 401/403/429,
конфликт и истечение ключа, админка. Worker-контур не менялся.

Запуск, ошибки, проверки и лимиты — в [инструкции](../../../docs/integrations/document-extractions.md).

## Граница HTTP (23.11.2026)

Worker-контроллер наследует обычный `Controller`, без сессий и UI-bootstrap. Общий `respond()` проверяет worker-токен до действия, формирует JSON ошибок и no-store. Контракты: `make test-contracts`.
