# Навыки Алисы (NJ-657)

`/alice` — голосовые навыки для Яндекс.Алисы с ответами ИИ. Сайт принимает
запросы платформы Яндекс.Диалогов на вебхуке, отвечает модель через общий
шлюз LLM платформы и ведёт память разговора. Несколько навыков — отдельные
диалоги из консоли, у каждого своя роль, модель и характер.

Сделано на основе наработок `source_data/` (контроллер `Dialogs.php` и вьюхи
старого сайта): вебхук, ответы ChatGPT-совместимой модели, настройки промпта,
история, публикация ответа на MQTT-дисплей.

## Быстрый старт

1. **Миграция:** `bin/console db:migrate` — создаст таблицы и навык по
   умолчанию «Мой диалог».
2. **Консоль Яндекса:** dialogs.yandex.ru → создать навык (можно приватный),
  Backend: «Webhook URL» → вписать
   `https://n2j.ru/alice/webhook`
   (адрес с персональным токеном навыка — в панели управления).
3. **Панель управления:** `/alice/admin` — выбрать роль пресетом (врач,
   юрист, детский аниматор…), задать приветствие, память и кнопки.
4. **Проверка:** `/alice/admin/test` — прогон фразы через весь пайплайн
   без колонки; `curl`:

   ```bash
   curl -s -X POST https://n2j.ru/alice/webhook -H 'Content-Type: application/json' -d '{
     "version": "1.0",
     "session": {"new": true, "message_id": 0, "session_id": "test-1", "skill_id": "", "user_id": "u1"},
     "request": {"command": "", "original_utterance": "", "type": "SimpleUtterance", "markup": {"dangerous_context": false}, "payload": {}}
   }'
   ```

## Как это работает

- **Выбор навыка.** Запрос ищет навык по токену из адреса, затем по
  `session.skill_id` из консоли Диалогов, затем берёт навык «по умолчанию».
  Неверный токен не проваливается на умолчание — это защита от чужих запросов.
- **Сценарии.** «помощь», «выход», приветствие новой сессии и маркировка
  опасного контента отвечаются без модели. Остальное — вопрос ИИ.
- **Память.** Последние N реплик этого же пользователя в пределах окна
  времени уходят в контекст модели (N и окно — настройки навыка). Журнал
  старше 180 дней чистит штатная чистка платформы.
- **Ретраи Яндекса.** Повторный запрос с тем же `session_id + message_id`
  не вызывает модель повторно — отдаётся сохранённый ответ.
- **Речь и экран.** Текст ответа чистится от markdown и ссылок для
  озвучивания; на экранных устройствах показываются кнопки быстрых ответов.
- **MQTT.** Ответ навыка можно публиковать в топик (например, дисплей
  ESP32): `NJ657_MQTT_ENABLED=1` + `NJ657_MQTT_HOST` в `.env`, топик — в
  настройках навыка. Реализация QoS 0 встроенная, без библиотек.

## Переменные окружения (`.env`)

| Переменная | Назначение |
|---|---|
| `NJ657_WEBHOOK_BASE` | адрес сайта для показа вебхука (по умолчанию `https://n2j.ru`) |
| `NJ657_MQTT_ENABLED` | `1` — публиковать ответы в MQTT |
| `NJ657_MQTT_HOST`, `NJ657_MQTT_PORT` | брокер (по умолчанию `1883`) |
| `NJ657_MQTT_USER`, `NJ657_MQTT_PASSWORD` | авторизация брокера (опционально) |
| `NJ657_MQTT_TIMEOUT_SEC` | таймаут подключения/записи (по умолчанию `2`) |

## Данные и адреса

- `nj_657_skills` — навыки и их настройки; `nj_657_dialogs` — журнал
  разговоров (память).
- `/alice` — публичная инструкция; `/alice/admin` — управление (админ);
  `/alice/admin/history` — журнал; `/alice/admin/test` — тестовая консоль;
  `POST /alice/webhook(/<токен>)` — вебхук.
