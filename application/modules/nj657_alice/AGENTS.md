## Назначение
POST `/alice/webhook(/<токен>)` — точка входа протокола Алисы 1.0. Ответ
генерирует LLM через фасад `Llm::` (модуль llm): одиночный быстрый вызов в
HTTP-запросе — осознанное исключение из правила «долгое — в очередь», потому
что Алиса ждёт ответ вебхука синхронно. Долгие батчи сюда заводить нельзя.

## Ключевые классы
| Класс | Роль |
|---|---|
| `Service_Nj657_Alice` | весь пайплайн: разбор протокола, выбор навыка, маршрутизация команд, память, вызов LLM, сборка ответа, журнал |

| `Controller_Nj657_Alice` | публичная страница `/alice` (инструкция подключения) |

## Таблицы
- `nj_657_skills` — настройки навыков (промпт, модель, температура, память,
  кнопки, тексты сценариев, привязка `yandex_skill_id`, `webhook_token`,
  `mqtt_topic`, `is_default`).
- `nj_657_dialogs` — журнал «вопрос → ответ» (он же память: последние реплики
  `intent='llm'` уходят в контекст). Уникальный индекс
  `(yandex_session_id, message_id)` — ретрай Яндекса не дёргает модель повторно.

## Маршруты
```
POST /alice/webhook(/<token>)   вебхук для консоли Диалогов
GET  /alice                     публичная страница
GET  /alice/admin               список навыков (admin)
GET  /alice/admin/skill(/code)  форма навыка; POST /save, /toggle, /delete
GET  /alice/admin/history       журнал (фильтры: навык, сценарий, источник)
GET|POST /alice/admin/test      тестовая консоль (тот же пайплайн, source=test)
```

## Выбор навыка и безопасность
Приоритет: токен из адреса → `session.skill_id` → навык `is_default`.
Неверный токен НЕ проваливается на навык по умолчанию. Идентификатор
пользователя Яндекса хранится как `sha1`-хеш (32 символа).

## Инварианты
- Модель навыка (`nj_657_skills.model`, форма «провайдер::модель») уходит в
  `Llm::chat($messages, ['model' => ...])` и ДОЕЗЖАЕТ до провайдера: пустое
  поле — модель платформы (`llm.default_model`). 08.10.2026 модель из формы
  молча игнорировалась: `Llm_Factory` клала default_model в «явный выбор
  вызывающего» (см. памятку модуля llm, раздел «Выбор модели»). Проверяет
  `.tools/llm_options_stand.php` (23 проверки, включая ask_llm() навыка) и
  показывает «Модель» в /alice/admin/test (meta.model).
- Вебхук не имеет права падать: любой сбой внутри — валидный JSON-ответ
  Алисы с запасным текстом; отказ — со строкой в `n2j-site.log`
  (`Log_Plain::event`).
- `dangerous_context=true` (маркировка Яндекса) — вежливый отказ без вызова
  модели.
- Ответ для речи чистится от markdown/ссылок (`clean_for_tts`); текст
  обрезается по `answer_max_chars` по границе слова.
- Кнопки показываются только экранным устройствам (`meta.interfaces.screen`).
- MQTT-публикация — только для `source='yandex'`, ошибки не роняют вебхук.
- Булевы поля навыка (is_active/is_default/end_session) приходят из
  PostgreSQL строками 't'/'f': пустой каст `(bool)` даёт TRUE даже для
  'f' — читать их только через `Service_Nj657_Alice::truthy()`, строки
  навыка нормализует `_bools()` (баг «навык закрывал сессию после первого
  ответа», 06.10.2026). «Врущая» форма успела ЗАПИСАТЬ end_session=TRUE
  против воли владельца — починка данных миграцией
  pgMigration_Nj_657_002 (end_session=FALSE всем навыкам; вернуть
  авто-закрытие можно честной галкой в /alice/admin).
- Конфиг `config/nj657_alice.php`: пресеты, словари команд, тексты по
  умолчанию, лимиты, секция `mqtt` (env `NJ657_*`). Секреты — только `.env`.
