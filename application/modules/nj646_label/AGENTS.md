## Назначение

«Разбор состава» (`/label`) — сервис для покупателя: человек вставляет состав с
этикетки еды или косметики (или фотографирует её), а сервис разбирает позиции по
своей базе веществ, показывает вред/пользу, предупреждает о рисках под личный
профиль (аллергии, кожа, диета) и накапливает знания: незнакомые вещества
уходят на изучение моделью и после модерации становятся карточками базы.

## Таблицы (полное владение)

- `nj_646_ingredients` — карточки веществ: `slug` UNIQUE, `kind`, `risk` 0..4, `verdict`, `e_code`, JSONB `synonyms/avoid/sources`, `source`, `status`, `hits`.
- `nj_646_analyses` — анонимная история разборов: текст, скоринг, найденные вещества, профиль, `product_kind`, `title_auto`. Товар несёт `product_kind/name_auto/last_score/last_verdict/analyses_count`, пищевую ценность `nutrition` (jsonb: `basis`, `portion`, `values`) и `nutrition_source` (`label|manual`), прежние ключи `key_aliases` (jsonb-массив, GIN); снимок разбора — ключ `nutrition` в `nj_646_analyses.about`. Индексы и поздние колонки — `Store::_indexes_ddl()` (миграции 003–006).
- `nj_646_unknowns` — незнакомые вещества (`seen_count`, `status`: new|queued|studied|ignored) — очередь обучения.
- `nj_646_runs` — прогоны: фото этикетки (`mode=photo`), изучение вещества (`mode=study`) и имя товара (`mode=title`), статусы `queued|running|done|error`, `result` JSONB, `error`, `client_ip`, `job_id`.
- `nj_646_votes` — голоса «согласен/спорно» по карточкам (`ingredient_id` + `visitor` UNIQUE).
- `nj_646_profiles` — профиль посетителя (кожа, диета, состояния) для персональных советов.

## Маршруты и API

- `GET /label/ingredient/<slug>` — ПУБЛИЧНАЯ страница вещества (только `published`; админу — и черновики с пометкой). Адрес постоянный, без параметров: в карту сайта, в переписку, в поиск; ссылки — из разбора и базы знаний.
- `GET /label` — ЛЁГКАЯ страница ВХОДА: фото этикетки (слева) и/или состав текстом, одна кнопка «Разобрать» → страница разбора; кнопок-примеров и выбора «еда/косметика» нет. Свои страницы: `GET /label/knowledge` (список слева, карточка справа, `?slug=`), `/label/my_analysis` (прежний `/label/history` — 301), `/label/profile` (аллергии, диета, кожа).
- `GET /label/compare(/<a>(/<b>))` — СРАВНЕНИЕ двух товаров: общие вещества, различия, средний риск и число позиций высокого риска (`Label::compare()`, оценки по АКТУАЛЬНОЙ базе); без пары — выбор «с кем сравнить» ссылками.
- `GET /label/analysis/<id>` — СТРАНИЦА РАЗБОРА: состав по актуальным карточкам (снимок `items` — только для удалённых), судьба незнакомцев, совет по профилю, строки этикетки, пищевая ценность. Видит владелец (метка браузера или вход) и админ, остальным 404. `POST /label/replay/<id>` (CSRF) — «разобрать заново» без текста в адресе.
- `POST /label/api/analyze` `{text, run_id?}` — разбор состава (без ИИ): вид состава и тип продукта сервер определяет сам, `run_id` подтягивает строки этикетки и товар с фото.
- `POST /label/api/photo` `{image (base64/data-url), kind?}` — постановка задачи в очередь, отдаёт `run_id`.
- `POST /label/api/status` `{id}` — статус прогона (опрос из страницы).
- `POST /label/api/ingredient` `{slug|id}`, `POST /label/api/search` `{q}`, `POST /label/api/vote` `{ingredient_id, value}`, `POST /label/api/profile` `{skin, diet, conditions}`, `POST /label/api/study` `{unknown_id}` — база, голоса, профиль, изучение.
- `POST /label/api/forget` `{csrf}` — «удалить мои данные»: стирает профиль, разборы, прогоны и голоса посетителя (`Store::forget_visitor()`); общая база не трогается, у живого прогона снимается метка.
- `POST /label/api/studies` `{runs: [id]}` — состояние своих прогонов изучения (опрос из страницы в развёрнутом режиме); чужой прогон в ответ не попадёт, админ видит все.
- `POST /label/api/worker_result` — воркер, заголовок `X-Worker-Token`.
- `POST /label/api/photo_file` `{run_id}` → `{image_b64, media_type, kb}` — кадр прогона для воркера (`X-Worker-Token`); `Store::photo_save|photo_bytes|photo_drop|photo_gc` работают с файлом в `application/cache/nj646_photo`.
- `/nj646/admin` — админ: `index` (дашборд), `moderation` (черновики и незнакомцы — рабочая страница), `ingredient_status|ingredient_save|ingredient_delete|ingredient_restudy|study|ignore|states|bulk`, `history` и `catalog` (листание/дерево, `limit`/`offset` в теле POST), `import`+`import_check|import_apply|import_cancel` (CSV-словарь), `merge`/`goods_merge` (дубли: пары с причиной, `keep` — главная, одной транзакцией), `goods`/`goods_filter`/`goods_save`/`goods_backfill`/`goods_nutrition_backfill` (товары, производители, пищевая ценность). Всё, кроме `history` и `catalog`, — POST + CSRF.
- `POST /nj646/admin/tree` `{mode, path[], q, offset, flat}` — уровень дерева: ветви со счётчиками или листья постранично. Уровни — SQL-выражения `Store::catalog_modes()`; `q` ищет в текущей ветке, `flat` отдаёт список сразу по пути, счётчики — `Store::catalog_counts()`.
- `POST /nj646/admin/ingredient_delete/<id>` — удалить карточку (незнакомец возвращается в очередь); `ingredient_restudy/<id>` — переизучить (прогон с `refresh`).
- `POST /label/api/study_pending` `{names[]}` — что из незнакомых уже разобрано (опрос полного ответа).
- `POST /nj646/admin/bulk` `{entity, action, scope, ids[]}` — массовая операция: карточки (`publish|hide|draft`) и очередь незнакомцев (`study|ignore`); `scope=selected` — по галочкам, `scope=all` — по всей очереди (до 200). Ответ: JSON при fetch (`ok`, `code`, `message`, `count`, `runs`, `queued`), иначе 303 + flash; коды — из `study_push_ids()`.
- `GET /sitemap.xml` (nj602) страницы веществ НЕ отдаёт: выдача `ingredients_public_slugs()` удалена 03.10.2026. От модуля в карте — только манифестный `/label`.
- **У админки нет GET-параметров вовсе**: сообщения — только из сессии (`nj646_admin_flash`), фильтры и состояние — из тела POST. `POST /nj646/admin/study/<id>` при `X-Requested-With`/поле `ajax` отвечает JSON (`code`, `message`, `run_id`, `state`, `queue`), без них — 303 + flash; `POST /nj646/admin/states` `{runs: [id]}` — ход прогонов и состояние очереди.

## Очередь

- Каналы: `nj646.label` (фото этикетки → vision-модель), `nj646.study` (незнакомое вещество → карточка знаний). Постановка: `Service_Nj120_JobQueue::push(..., ['timeout_sec' => 300, 'max_attempts' => 2, 'module' => 'nj646_label'])`.
- Обработчик: `workers/n2j_workers/handlers/nj646_label.py` (`handle` — фото, `handle_study` — изучение).
- Reconcile: задача считается закрытой, когда `nj_646_runs.status IN ('done','error','cancelled')`.
- Массовое изучение: `Store::study_push_ids($ids, [...])` — ядро (позиция идёт через `study_push()`, дублей нет; лимит называет себя и останавливает пачку); `study_push_all(['limit' => N])` — «по всей очереди»; `unknowns_pending_count()` даёт подпись кнопки, `unknowns_todo_ids()` — список.
- Изучение ставится при разборе: вещество, встреченное `NJ646_UNKNOWN_MIN_SEEN` раз, уходит в очередь (не больше `NJ646_UNKNOWN_PER_RUN` за разбор); в развёрнутом режиме порог — первая встреча, пачка — `NJ646_DETAILED_STUDIES`. `study_push()` проверяет модель, лимит и идущий прогон — дублей нет.

## Правила, которые нельзя нарушать

1. **Без ИИ сервис живёт.** Разбор текста, база, профиль и советы работают на своей БД; фото и автоизучение честно отвечают «модель не подключена», а не падают.
2. **Фото читается в два прохода.** Переписывание строк и сборка состава из текста — разные задачи: та же модель в роли переписчика ошибается заметно реже. Состав собирается из строк (моделью или локально), а не из пикселей; переписанные строки видны владельцу на странице.
3. **Модель не додумывает состав.** Vision-промпт требует дословный текст этикетки и разрешает пустой ответ, если текст не читается, — пустое честнее выдуманного. Цикл и дубли режет воркер, однотипный список уезжает с пометкой «сверьте с этикеткой», оборванный по токенам — с пометкой в `result.note`; остаток не приписываем.
4. **Всё, что вернула модель, — черновик.** Карточки `source=llm` попадают в базу черновиком (`published` — только после модерации в `/nj646/admin`); правки человека (`source=user|admin|csv`) не перетираются ни посевом, ни моделью. В разборе такая позиция помечена «изучено ИИ · не проверено», в карточке — «черновик · ждёт проверки».
5. **Совет — не диагноз.** Формулировки риска осторожные («обсуждается», «может»), рядом с разбором — оговорка, что сервис не заменяет врача.
6. **Долгие операции — только через очередь** `nj120_jobs`; страница не ждёт модель, а опрашивает статус прогона.
7. **Никаких внешних хостов в вёрстке**; всё своё в `public_html/assets/`.
8. **Вся запись — через `Service_Nj646_Store`**; контроллеры не пишут в БД сами.
9. **Новые env-ключи — в хвост `.env.example`** (ключи сайта) и `workers/.env.example` (ключи воркера), имена с полным слагом (`NJ646_…`).
10. **Изменил таблицу/манифест/лимиты — обнови** `tests/Unit/ManifestRegistryTest.php` (если менялись реестры каналов/чисток), этот файл и юнит-тест.
11. **Статусы человеку — по-русски, в базе — латиницей.** Перевод только через `i18n/ru.php` модуля и `Label::status_label($status, $group)` (группы `job|run|unknown|card`); ключи обязаны начинаться с `nj646.` — `I18n::load()` сливает файлы всех модулей, и `done`/`new`/`running`/`error` уже заняты nj598. Для JS — `status_labels($group)` + `JSON_UNESCAPED_UNICODE`.
12. **Цифры пищевой ценности не выдумываются и не перетираются.** Парсер читает таблицу только рядом с якорем и отбрасывает невозможное (755 г белка в 100 г); разбор этикетки ДОПОЛНЯЕТ пустые поля, а введённое руками (`nutrition_source = manual`) не трогает. Пометки нейтральные, с порогом в самом тексте («много сахаров: 45 г на 100 г, ориентир — от 22,5 г»), и только при `basis = 100g/100ml`. Никаких «дневных норм» — это уже медицинский совет.
13. **Ключ товара меняется вместе с названием — но только через `product_rekey_set()`.** Прежний ключ обязан уехать в `key_aliases`, иначе следующий разбор той же этикетки заведёт дубль. Занят новый ключ — ничего не трогаем: это случай для «слияния дублей».
14. **Лимиты/чистки:** история разборов и прогоны старше 90/180 дней удаляются своим `cleanup`-разделом манифеста; статистика веществ остаётся в карточках (`hits`).

## Не трогать / подводные камни

_Коротко — правило в строку. Причина, история и примеры: `docs/nj646_label-pitfalls.md`
(читать перед правкой соответствующей части)._

- `INSERT … RETURNING` — это `Database::SELECT`, не `INSERT` (иначе `current()` на массиве).
- jsonb в `DB::update()->set()` — только через `DB::expr(self::_json())`; `_json()` уже закавычен.
- Ответ модели разбирает `webread.json_from_text` + `_salvage_composition()`, а не свой `json.loads`.
- Приёмка `worker_result` пишет КАЖДЫЙ исход через `Log_Plain::event()` (не `Kohana::$log->add()`).
- `result.note` (обрыв, блик, мелкое фото) обязана доезжать до страницы.
- Полос прогресса нет нигде: спиннер, секундомер, числа, точки.
- Оборванный ответ допрашивается `_continue_composition()` — но не при цикле и не при подозрении на выдумку.
- Фото только УМЕНЬШАЕТСЯ (до 1400 px); кадр меньше 800 px — пометка в `result.note`.
- Цикл и повторы модели режет воркер (`_loop_cut`, `_dedupe_items`, `_suspicion_note`).
- `trim()` с набором символов ломает UTF-8 — резать `preg_replace('/…/u')`.
- Иконка товара в `product_kinds.*.icon` хранится только как глиф (`fa-jar`); в `views/646/list_row.php` перед ним обязателен `fas`, иначе у `<i>` нет семейства шрифта.
- `/label/my_analysis` и `/label/profile` используют полную внешнюю обёртку как `/label`; не возвращать внутрь `mx-auto max-w-6xl`.
- Навигация между страницами Label задаётся один раз через `set_module_nav()`; не добавлять в вьюхи дублирующий `646/nav`.
- Tailwind-классы в `views/646/js/*.php` — целиком, строками; после правок `npm run build:css`.
- Ожидания JS по API (сверять при правках): `analyze` → `score/verdict/verdict_label/score_label/counts/items[]/unknown[]/advice[]/title/product{…}`; `ingredient`, `search`, `vote`, `status`, `photo`, `forget` — см. вынос.
- `Store.php` — трейты `Store/*.php`: помощники в классе, новый метод — в свой раздел.
- Сопоставление позиций — по нормализованному тексту и синонимам (`Label::find`).
- Лимиты — по `client_ip`, кроме `study_per_day` (по посетителю).
- **`AND`/`OR` слабее `=`, `=>` и `?:`** — условие в присваивании и тернарнике всегда в скобках (`.tools/php_ternary_lint.py`).
- Страница разбора показывает СЕГОДНЯШНЮЮ базу (снимок — только для удалённых карточек); доступ — владелец или админ.
- Справочник админки открывается на чтение; правка — по карандашу, переобучение — отдельной кнопкой.
- Модель перезаписывает карточку только по «переизучить» и только при `source = llm`.
- Дерево справочника: уровни — SQL-выражения `catalog_modes()`, не колонки.
- В списках админки формы не вкладываются: панель — пустая форма + атрибут `form="…"`.
- Сообщения админки — через сессию, не `?flash=`.
- `php -S` не перечитывает `.env` — перезапускайте `bin/serve`.
- Пределы записи (`raw_text_kb` 64, `result_kb` 256) режут по байтам и помечают обрезку.
- `_list_sql(array $extra)` — добавочные колонки только аргументом.
- Трейты видны `php_method_lint` — без этого были ложные «метода нет».
- Фото не едет в payload: файл в `application/cache/nj646_photo`, воркер берёт через API.
- **Пищевая ценность — одна дверь:** `About::nutrition_sanitize()` на входе, `Store::nutrition_of()` на чтении, `_nutrition_json()` на записи (пусто = `{}`).
- **Промпты требуют алфавит оригинала, но ответ ещё и проверяется** `_latin_drift()` — перевод откатывается на сборку из строк.
- **На вещества идёт `Label::composition_block($text)`, а не весь текст** (иначе «ГОСТ …» уходит в оплачиваемую очередь изучения).
- **Товар ищется `product_by_key()`** (ключ → `key_aliases`), ключ меняется только через `product_rekey_set()`; название от модели — `product_name_from_model()`.
- **`false` из PostgreSQL приезжает строкой «f»** — булев столбец читать только `Store::flag()`, `empty()`/`! empty()` на нём врут.
- **Пересчёт порции на 100 г (`nutrition_per100()`) в базу не пишется** и всегда помечен.
- **Чистка очереди удаляет насовсем:** правила — `Label::looks_like_service()`, удаление — после показанного списка, `studied` не трогаем.
- Таблицы создают и миграция, и `Store::ensure_tables()` (модуль поднимается одним pull).

## Как тестировать

- `php tests/mini_runner.php Nj646` / `Label` — логика разбора (парсинг, E-коды, скоринг, советы), блок состава (`composition_block`), пищевая ценность (разбор таблицы, единицы, пороги пометок) и русские статусы.
- `cd workers && python3 -m pytest -q tests/test_nj646_label_parse.py tests/test_nj646_label_image.py` — ответы модели (обрыв по токенам, markdown, проза, цикл повторов, дописывание, ЯЗЫК ОТВЕТА и `_latin_drift`) и подготовка фото. `-k transcrib` — двухпроходный режим и откат при сбое.
- `php tests/mini_runner.php LabelGoods` — живая БД: переименование товара не плодит дубль (псевдонимы ключа), рабочее имя сменяется настоящим без потери статистики, ручная пищевая ценность не перетирается этикеткой, чистка очереди убирает мусор и щадит вещества.
- `php tests/mini_runner.php LabelRun` — живая БД: запись `result` в jsonb, дожим из очереди, отказ задачи, подсказка про невзятую задачу, доезд `result.note`.
- `php tests/mini_runner.php LabelDetailed` — развёрнутый режим и админка: `study_push` (коды `queued/already/limit/no_llm`, дубль не плодит задач), пачка «изучить всё», `study_state` не отдаёт чужие прогоны, `study_queue_state` не считает свежую задачу зависшей. Без модели поток `skipped`.
- `php tests/mini_runner.php LabelAdmin` — массовые операции и история на живой БД: модерация меняет ровно выбранные карточки, мусорные `ids` игнорируются, `study_push_ids` не плодит прогонов, «мои разборы» — только своего посетителя и листаются `offset`.
- `php tests/mini_runner.php LogPlain` — плоский лог сайта (строка на событие, ротация, «падать нельзя, если писать некуда»); `cd workers && python3 -m pytest -q tests/test_logging.py` — лог воркера.
- `php tests/mini_runner.php Manifest` — каналы `nj646.label`/`nj646.study` и чистки в реестре.
- `bash .tools/nj646_label_e2e.sh` — сквозной прогон фото (сайт + PG + мок LLM + воркер): печатает `run_id`, опрос статуса, строки `nj_646_runs`/`nj_120_jobs`. Нужны `PORT=8080 bash bin/serve`, мок и воркер с каналом `nj646.label`.
- Развёрнутый режим в песочнице: воркер с ДВУМЯ каналами (`WORKER_CHANNELS=nj646.label,nj646.study`), ответы мока — по промпту (`MOCK_LLM_ROUTES="/tmp/study.json=справочник по ингредиентам;/tmp/compose.json=редактор состава;/tmp/lines.json=OCR"`); общая очередь `MOCK_LLM_REPLY_FILES` не годится.
- Глазами: `/label` (фото слева, состав справа), `/label/knowledge`, `/label/my_analysis`, `/label/profile`, `/label/product/<id>` (пищевая ценность), `/nj646/admin`, `/nj646/admin/moderation`, `/nj646/admin/catalog`, `/nj646/admin/goods` (чтение → карандаш).
- Живой дым (`PORT=8080 bash bin/serve`): `POST /label/api/analyze` `{"text":"Состав: сахар, соль, E211."}` → `ok:true`, `score`, `items[]`; `/label/api/search`, `/label/api/ingredient`, `/label/api/vote`; `/label/api/photo` без ключей → честное «vision не подключена», не 500. Пищевая ценность: текст с таблицей → `nj_646_products.nutrition`, правка руками в `/nj646/admin/goods`, пустая форма чистит.
- В БД после разборов: `nj_646_analyses` + рост `hits` у найденных веществ; незнакомцы растут в `nj_646_unknowns.seen_count`. `/nj646/admin` — только админ (иначе 403).
