# nj593_trends — «Тренды GitHub»

Ежедневный обзор трендов и новинок GitHub с публичной страницей обзора.
Воркер ищет **свежие** репозитории (GitHub Search API: `created:>дата`,
`stars>=N`, опц. язык), читает их README, LLM отбирает самое интересное
и пишет по-русски: заголовок, «что это», «почему в обзоре», «кому пригодится».
Факты (звёзды, форки, язык, даты, темы) — только из GitHub API, без выдумок.

- Страница обзора — **публичный дайджест**: `/trends/<code>` (например `/trends/trd1a2b3c4d`).
- `/trends` — **открытый каталог опубликованных обзоров** (главная модуля):
  читаемый список для людей и СЕО (свежие сверху, поиск `?q=`, пагинация),
  без входа и без служебных колонок. Обзор публикуется по умолчанию; владелец
  может снять его с публикации — тогда обзор пропадает из каталога, а его
  страница отдаёт 404 всем, кроме владельца и администратора.
- `/trends/mine` — **мои обзоры** карточками: дата, статус, тема, лид,
  настройки сборки, действия (открыть, снять/вернуть публикацию, удалить
  в два клика), поиск и пагинация. Отдельного адреса `/trends/catalog` больше
  нет (владелец, 16.10.2026).
- `/trends/new` — **форма нового обзора** отдельной страницей (дата, период,
  число позиций, минимум звёзд, язык, «что считать интересным»). Параметры
  можно передать в адресе (`?period=3&count=10&min_stars=30&language=rust&
  focus=...`) — так «Собрать заново» открывает форму уже заполненной;
  значения проверяются в контроллере (границы, список языков, длина фокуса).
- POST на `/trends` сохранён для старых закладок и внешних форм и делает то же
  самое, что POST на `/trends/new`; отказ в обоих случаях возвращает на форму.
- Админ: `/nj593/admin` — все обзоры + кнопка «Создать обзор дня».
- Статус в живую: спиннер + секундомер + прогресс (AJAX `/trends/api/status/<code>`).
- **Прерывание сборки**: кнопка «Прервать» в статус-ряде (только владелец или
  админ) — два клика по одной кнопке, без window.confirm. POST
  `/trends/api/cancel` с `code` + `csrf` снимает задачу в очереди **с force**
  (в т.ч. уже выполняющуюся) и переводит обзор в `cancelled`. Собранные позиции
  сохраняются, страница показывает «Сборка остановлена» и «Собрать заново».
  Воркер замечает отмену по отказу heartbeat (два подряд, ≤ ~1 минуты) и
  прерывает работу — включая текущий LLM-вызов.
- Долгий LLM-вызов («ИИ отбирает интересное и пишет тексты…») обновляет этап:
  «…: модель думает N с (лимит 300 с)…» каждые 20 с, чтобы процесс не выглядел
  зависшим — видно и что процесс жив, и сколько ещё ждать максимум.
- Если задачу сняли без нас (авто-стоп молчащего воркера, уборка сирот при
  рестарте), `Service_Nj593_Trends::reconcile()` сам переводит обзор в
  `cancelled` при чтении статуса — ряд не крутится вечно.
- Ошибки — полный текст причины в красном баннере (и на сайте, и от воркера).

## Финалы сборки: «висеть» нечему (26.09.2026)

Владелец про обзор `trda72ff421`: «завис — в работе, ИИ отбирает…, 0 из 8;
может не нашлось ничего, а может LLM не отработала — непонятно. Нужно это
отрабатывать логично, чтобы не висели». Теперь у каждого сбор есть финал:

| Ситуация | Что видит пользователь |
|---|---|
| ИИ вернул «подходящего нет» по фокусу | **Готово** + объяснение в сводке, позиций 0, без выдумок |
| ИИ не ответила (таймаут/ошибка) | **Готово** + «⚠ ИИ-разбор не удался: причина» и позиции по фактам GitHub |
| GitHub не дал кандидатов вообще | **Ошибка** + причина и совет (расширить период / снизить звёзды) |
| Воркер молчит > 4 мин | **Остановлено** (авто-стоп) + найденное сохранено, «Собрать заново» |
| Никто не взял задачу 15 мин | **Ошибка**: «Воркер не взял задачу за 15 мин…» |
| Сборка идёт > 25 мин без результата | **Остановлено** автоматически + «Запустите заново» |
| Воркер молчит > 10 мин, а пульс идёт | **Остановлено**: «Воркер не выходил на связь N мин…» |
| Владелец нажал «Прервать сборку» | **Остановлено** + позиции сохранены |

Ключевое: страница обзора (`/trends/<code>`), её статус-API и список «Мои
обзоры» САМИ зовут авто-остановку молчащего воркера (`auto_stop_silent`) —
как `/radar` и `/leads`. Раньше этого не было, и задача, чей воркер умер,
оставалась «в работе» неограниченно долго.

Сверка идёт не только на странице обзора: «Мои обзоры» (`/trends`) и таблица
админки прогоняют `reconcile_list()` по видимым строкам — незавершённые сборки
получают финал и в списках, а не только при открытии обзора.

Пороги настраиваются окружением сайта: `NJ593_TRENDS_STALE_SEC` (25 мин —
потолок работы), `NJ593_TRENDS_CLAIM_SEC` (15 мин — ожидание в очереди),
`NJ593_TRENDS_SILENCE_SEC` (10 мин — тишина в отчётах о ходе). Тишину считает
БД (`now() - updated_at`), а не PHP: часовой пояс сервера тут ни при чём.
Бюджеты ИИ-этапов — на стороне воркера: `NJ593_LLM_CURATE_TIMEOUT` (300 c),
`NJ593_LLM_CURATE_RETRY_TIMEOUT` (150 c), `NJ593_LLM_TAKEAWAYS_TIMEOUT` (150 c).

### Обзор читается как статья (26.09.2026)

Владелец: «страница обзора должна быть ближе к статье, чтобы удобно было
читать». Готовый обзор — ОДНА карточка-статья (`p-4 sm:p-7`), а не набор
мелких карточек:

* мета-строка статьи: позиций · ~N мин чтения · «обзор за сутки»;
* лид — вступление обзора крупным текстом (`text-base sm:text-lg
  leading-relaxed`), а не подпись под заголовком;
* «Что взять в работу» — врезка `rounded-xl` (emerald, как «Правило
  неразрывного статуса» в эталоне);
* позиция — РАЗДЕЛ статьи с якорем `id="pos-N"` (`scroll-mt-24`):
  номер + репозиторий + метрики строкой факта → человеческий заголовок
  `h2` (`text-lg sm:text-xl`) → абзац «что это» → два пояснения карточками
  `sm:grid-cols-2` («Почему в обзоре» / «Кому пригодится») → врезка «Как
  применить» → теги;
* правая колонка — «Содержание» со ссылками на якоря (статейная навигация).

### «Как применить» — нейтральным серым

Владелец: «Как применить: — слишком выделяется, сделать gray». Врезка блока
позиции — `border-gray-100 bg-gray-50/70`, иконка `text-gray-400`, подпись
`font-semibold text-gray-900`. Зелёный оставлен только там, где это именно
действие-итог обзора («Что взять в работу»).

### Служебное — только админу (модель)

В сводке обзора строку **«Модель»** видит только администратор
(`Auth::instance()->logged_in('admin')` → `is_admin` во вьюхе). Для гостей и
обычных пользователей модели в разметке нет вовсе (проверено: страница
`/trends/<code>` отдаёт модель только админскому сеансу). Правило из эталона:
служебные данные генерации не показываем пользователю.

### Навигация раздела — в верхнем header шаблона

Владелец: «nav Ежедневный обзор / Мои обзоры / Админка должны быть в чипах
верхней header шаблона». Все три пункта задаются через `set_module_nav()`
(`Controller_Nj593_Trends::before()` и `Controller_Nj593_Admin::before()`),
активный Base помечает сам по текущему URL; «Админка» — только администратору.
В контенте страниц этих чипов больше нет.

Чипы шапки самого обзора лаконичны — только про обзор: дата, «за сутки»,
статус и корзина (удалить). Всё навигационное (новый обзор, админка) — вверху.

### Поиск и пагинация (список и админка)

* `Service_Nj593_Trends::search_user()/count_user()` и
  `search_admin()/count_admin()` — поиск по коду, названию, фокусу и названиям
  позиций (частый вопрос: «в каком обзоре был этот репозиторий»);
  LIKE-метасимволы (`%`, `_`) обезвреживаются, подстановка — через `quote()`.
* Общая вьюха `views/partials/pagination.php` (платформенная, по эталону): «Показано X–Y из Z»,
  кнопки `h-8 w-8 rounded-lg`, текущая — синяя, «…» для длинных списков.
  Ссылки — обычные `<a href>` с сохранением `q` и якоря `#my`: работают без JS.
* «Мои обзоры» — 20 строк на страницу, админка — 50. Форма поиска — GET.
* Шапка админки показывает сводку: всего / готово / в работе (`stats_admin()`).

### Удаление — иконкой и в два клика

* На странице обзора и в списке «Мои обзоры» удаление — маленькая
  **кнопка-иконка** (`h-8 w-8 rounded-lg text-gray-400`, `fa-trash-can`,
  hover `bg-red-50 text-red-600`) рядом с «Новый обзор» / «Открыть», как в
  таблице эталона. Большой кнопки «Удалить» больше нет — случайно не нажмут.
* Защита — общий app.js: удаление обзора спрашивает окном (`data-n2j-confirm`,
  «Удалить обзор?» и код обзора в тексте), переключатель публикации — двойным
  нажатием (`data-n2j-arm`: «Точно снять?» / «Точно вернуть?», пояснение — в
  подсказке кнопки). Своего JS для этого в модуле нет.
* Пустой обзор («ничего не нашлось») получает ниже объяснения
  **полнозенную кнопку «Удалить обзор»** — чтобы мусор убирался одним
  движением.
* Рабочая область — сетка **2/3 + 1/3**: слева процесс/выводы/позиции, справа
  блок-компаньон `hidden md:block` (сводка обзора, «Поделиться», «Как отбираем»,
  «Это ваш обзор») — правило анти-пустоты.
* Статус-ряд «спиннер + название + секундомер» неделимый (без `justify-between`),
  действие («Прервать сборку») — отдельной строкой внутри карточки.
* Общий инлайн-скрипт (`views/593/script.php`) подключается и на `/trends`, и на
  страницу обзора: части, не зависящие от страницы (флеш, двухшаговое удаление,
  копирование ссылки), идут ДО раннего выхода — иначе на списке «Мои обзоры»
  не работали ни удаление в два шага, ни кнопки.

Канал очереди: `nj593.trends` (обработчик `workers/n2j_workers/handlers/nj593_trends.py`).
После обновления: `git pull && systemctl restart n2j-worker`.

## Ежедневный автозапуск («обзор дня»)

На сервере воркера — systemd timer (пример, от root):

`/etc/systemd/system/n2j-trends.service`
```ini
[Unit]
Description=N2J: ежедневный обзор трендов GitHub

[Service]
Type=oneshot
EnvironmentFile=/opt/n2j/workers/.env
ExecStart=/usr/bin/curl -fsS -X POST -H "X-Worker-Token: ${WORKER_API_TOKEN}" -d period=1 -d count=8 https://n2j.ru/trends/api/create
```

`/etc/systemd/system/n2j-trends.timer`
```ini
[Unit]
Description=N2J: тренды GitHub раз в сутки

[Timer]
OnCalendar=*-*-* 06:00:00 UTC
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
systemctl daemon-reload && systemctl enable --now n2j-trends.timer
```

`/trends/api/create` создаёт обзор (владелец — первый администратор сайта)
и ставит задачу в очередь; воркер подхватит её сам. Те же действия — кнопкой
«Создать обзор дня» в `/nj593/admin` или формой на `/trends/new`.

## База

- `nj_593_reviews` — обзоры (дата, фильтры, статус, заголовок/вступление, модель).
- `nj_593_items` — позиции (факты GitHub + тексты ИИ, UNIQUE(review_id, rank)).
- Миграция: `pgMigration_Nj_593_001_Trends_Tables` (накатывается деплоем);
  идемпотентная страховка — `Service_Nj593_Trends::ensure_tables()`.

## API (токен воркера — заголовок `X-Worker-Token`)

| Метод | Путь | Назначение |
|---|---|---|
| GET  | `/trends/api/status/<code>` | публичный статус + позиции (поллинг) |

## Строк на странице и таблицы (26.09.2026)

Владелец: «Строк: при загрузке показывай фактически (а не выбор из браузера, а то
нелогично и не перещёлкнуть). Шрифт в таблице сделай больше».

* Селект «Строк» больше не подменяется памятью браузера (`data-n2j-forget`): в нём
  всегда то число, которое реально показано. Выбор пользователя запоминается
  (`n2j:per:<путь>`), но применяется **честным переходом**: если в адресе нет
  `per`, а в браузере он сохранён — один раз переходим на сохранённое значение,
  и селект снова совпадает с таблицей. Явный `per` в ссылке сильнее памяти.
