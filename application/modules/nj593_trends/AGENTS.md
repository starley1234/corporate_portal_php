## Состояние

**16.10.2026 — сборка и управление только администратору.** Право `nj593.admin`
в `application/config/acl.php`: форма, POST `/trends` и `/trends/new`, личный
список, публикация, удаление и отмена сборки закрыты остальным (403).
Читатели, включая прежнего владельца, видят только `done` + `published`;
страница и API статуса используют `can_read()`. Кнопок сборки у читателей нет.
Проверка: `.tools/nj593_views_stand.php` (вьюхи, контроллеры, права и API).

GitHub-тренды: воркер `workers/n2j_workers/handlers/nj593_trends.py` собирает
трендовые репозитории (GitHub API, `NJ593_GITHUB_TOKEN`), LLM пишет русское
описание. Таблица `nj_593_*` (миграция 001). Очередь: `nj593.trends`
(label в `channels_ui` → `/trends/<code>`).

**08.10.2026 — открытый каталог обзоров и публикация.** Владелец: «отдельная
страница каталога опубликованных обзоров — для людей и СЕО: читаемый список,
свежие сверху, пагинация, поиск; обзор публикуется по умолчанию, но я могу снять
его с публикации». Сделано:

* Открытый каталог: сначала `/trends/catalog` (`action_catalog`, вид
  `views/593/catalog.php`), с 16.10.2026 — главная модуля `/trends`
  (`action_index`, вид `views/593/index.php`); отдельного адреса каталога
  больше нет. В каталог попадают только `status='done' AND published`, свежие
  сверху (`rdate DESC, id DESC`), поиск `?q=` (код, тема, название репозитория —
  та же механика, что у «Моих обзоров»), пагинация общим партиалом
  `partials/pagination` (10/20/50/100). В строке: дата, охват, язык, звёзды, код
  обзора и названия первых трёх репозиториев (`top_names`).
* Публикация: колонка `published BOOLEAN NOT NULL DEFAULT TRUE` (миграция 003);
  `Service_Nj593_Trends::set_published()`, `is_published()`, `count_public()`,
  `search_public()`, `latest_public()`. Снятый обзор исчезает из каталога, а
  `/trends/<code>` отдаёт 404 всем, кроме владельца и администратора.
* Переключатель публикации — POST `/trends/<code>/publish`, только в два клика
  (armed, тон «amber»); стоит на странице обзора и в «Моих обзорах», состояние
  видно точкой-статусом (эталон, правило 4) и пометкой «снят с публикации».
* Каталог добавлен в карту сайта (`sitemap` в манифесте + ручной список
  `Nj602_Api::action_sitemap`): с 16.10.2026 это `/trends` (приоритет 0.8).
* Схема и код едут на прод разными шагами: `_has_published()` спрашивает колонку
  в `information_schema` — пока миграции нет, каталог читает это как «всё
  опубликовано» (умолчание колонки) вместо 500; `set_published()` добавляет
  колонку лениво, только на явном действии владельца.

**15.10.2026 — список и форма разъехались по страницам.** Владелец: «/trends —
пускай будет перечень обзоров хорошо оформленный, а страницу — форму для нового
обзора сделай другую». Сделано:

* `/trends` (`action_index`, вид `views/593/index.php`) — перечень обзоров
  КАРТОЧКАМИ: дата, статус, код, заголовок, лид, настройки сборки, причина
  отказа, плашка «снят с публикации»; действия (открыть, публикация, удаление)
  в два клика; поиск, «строк на странице» и пагинация — общие. Формы сборки на
  странице НЕТ: её поля (`rdate`, `period`, `count`, `min_stars`, `language`,
  `focus`) здесь появляться не должны.
  (С 16.10.2026 этот перечень переехал на `/trends/mine` — см. следующий блок.)
* `/trends/new` (маршрут `nj593_new`, `action_new`, вид `views/593/new.php`) —
  форма нового обзора; маршрут объявлен ВЫШЕ `trends/<code>`, иначе «new»
  читается как код обзора (та же ловушка, что у `trends/catalog`).
* Параметры формы можно передать в адресе: `_form_defaults()` проверяет их
  (период из списка 1/2/3/7, позиции 3–12, звёзды ≥ минимума, язык из конфига,
  фокус обрезается по `max_focus_len`) и подставляет в поля. Так «Собрать
  заново» на странице обзора (`$again_url`, период/позиции/звёзды/язык/фокус
  прошлого обзора) открывает форму уже заполненной.
* POST на `/trends` сохранён ради старых закладок и внешних форм: он делает то
  же, что POST на `/trends/new`. Отказ (нет входа, плохой CSRF, ошибка create)
  уводит на `trends/new?flash=...` — возврат на форму, а не в список.
* Дизайн: крошки, h1, 2/3 форма + 1/3 компаньон, карточки `rounded-xl`.
* Проверка: `.tools/nj593_views_stand.php` — рендер вьюх без предупреждений PHP,
  отсутствие полей сборки на списке, подстановка и экранирование параметров,
  порядок маршрутов, разбор адреса и защита.

**16.10.2026 — каталог на главной, личный список на своём адресе.** Владелец:
«вместо /trends показывай содержимое /trends/catalog. /trends/catalog — убери».
Сделано:

* `/trends` — открытый каталог опубликованных обзоров (`action_index`, вид
  `views/593/index.php`, бывший `catalog.php`): поиск, пагинация и все ссылки
  ведут на `/trends`, для вошедших рядом кнопка «Мои обзоры».
* `/trends/mine` (маршрут `nj593_mine` ВЫШЕ `trends/<code>`, `action_mine`,
  вид `views/593/mine.php`) — личный перечень: статус сборки, публикация,
  удаление в два клика, поиск и пагинация. Ссылка на каталог — крошкой и
  блоком дайджеста.
* Маршрут `nj593_catalog` и `action_catalog()` УДАЛЕНЫ: `/trends/catalog`
  теперь обычная 404, редиректа нет (решение владельца).
* POST на `/trends` по-прежнему создаёт обзор; отказ уводит на `/trends/new`.

**16.10.2026 — уведомления об обзорах (задача «уведомления из модулей»).**
Модуль не отправляет ничего сам: объявляет события в манифесте и зовёт
`Service_Nj597_Notify::emit()`.

* `notify.events` в `config/nj_module.php`: `nj593.review.done`
  (in_app,email,telegram,max, digest) и `nj593.review.error` (in_app,email);
  рядом `notify.templates` — тексты «из коробки» на 4 и 1 канал.
  Подстановки: `{{title}}`, `{{items}}`, `{{error}}`, `{{href}}`,
  `{{user_name}}`, `{{site_url}}`, `{{settings_url}}`; в письме обязателен
  `{{href}}` — иначе человек не найдёт обзор.
* `Trends::_notify_owner($user_id, $alias, $payload)` — тихий выход, если класса
  уведомлений нет (модуль живёт без ядра); `catch Throwable` вокруг emit.
* `complete()` пишет `nj593.review.done` только на ПЕРВОМ переходе в done
  (`$already_done`), `fail()` — `nj593.review.error` только когда прежний статус
  не error. Иначе повтор воркера слал бы второе письмо. Дедупликация
  `dedup_key = nj593.review.done|error:<id>`.
* `href` = `/trends/<code>`; ядро пропускает его через `Notify::safe_href()`.
* Тексты правятся в `/nj597/admin?tab=templates`; `Registry::sync_manifests()`
  заводит только отсутствующие пары «событие × канал» и не затирает правки
  администратора.
* Проверка контракта — `.tools/nj597_notify_contract_cases.php` (в движковом
  стенде nj597).

## Правила модуля

* Бережный DDG/лимиты — не ужесточать без владельца.
* LLM-текст — только по содержимому README/метаданных, без домыслов.
* Удаление своих артефактов — two-click (armed), без window.confirm; кнопка —
  иконка-корзина `h-8 w-8` (текстовой «Удалить» рядом с основными действиями нет).
* Навигация раздела — ТОЛЬКО через `set_module_nav()` (чипы верхнего header
  шаблона): «Тренды GitHub» и «Управление» (админу). Служебные ссылки раздела
  в контенте не дублируем; допустимы ДЕЙСТВИЯ страницы — кнопки «Собрать обзор»
  (на `/trends` и в пустом каталоге) и «Мои обзоры» на `/trends` → `/trends/mine`,
  а также блок дайджеста каталога на `/trends/mine` (просьбы владельца
  08.10.2026, 15.10.2026 и 16.10.2026).
* Сборка и управление — только `nj593.admin`; остальные читают готовые опубликованные обзоры.
* Служебное (модель генерации) — только администратору (`is_admin`).
* Списки — с серверным поиском (`?q=`) и пагинацией (`views/partials/pagination.php` — общая, переехала из модуля 08.10.2026,
  по 20/50 строк); поиск ищет и по названиям позиций.
