**Один источник правды** для: меню сайдбара, карточек главной, чипов раздела
в шапке, быстрого поиска и подсказок иконок в /prl118_links.

## Как добавить сервис на главную/в меню (без правки чужого кода)

1. В модуле сервиса создайте `config/prl_module.php`:

```php
<?php defined('SYSPATH') or die('No direct script access.');
return [
    'id'        => 503,                      // номер модуля
    'slug'      => 'ndfl',
    'title'     => 'Калькулятор НДФЛ',
    'short'     => 'НДФЛ 13/15%: расчёт удержания и «на руки»',
    'icon'      => 'fas fa-file-invoice',
    'href'      => '/ndfl',
    'group'      => 'Финансы',
    'sort'       => 503,
    'created_at' => '2026-10-23', // дата первого появления модуля в репозитории
    'updated_at' => '2026-10-23', // обновлять при изменении сервиса/манифеста
    'keywords'  => 'ндфл 13 подоходный налог зарплата на руки',
    'api'       => ['/prl503/api/calc'],
    'card_view' => 'prl503/card',             // views/prl503/card.php — виджет главной
];
```

2. Подключите модуль в `application/bootstrap.php`.
3. Готово: модуль сам появится в сайдбаре (группа «Финансы»), на главной
   (карточка из `card_view`), в поиске панели, в чипах шапки своих страниц.
4. В каждом новом манифесте указывайте `created_at` и `updated_at` в формате
   `YYYY-MM-DD`: первое — дата создания модуля, второе — дата последнего
   изменения сервиса. При изменении поведения или контента сервиса обновляйте
   `updated_at`; не используйте дату checkout/mtime файлов.

## API класса

- `Service_Prl110_Catalog::modules()` — манифесты (sort asc);
- `::get($slug)` — манифест по slug/названию модуля/id;
- `::home_cards($ctx, $limit)` — модули с `card_view`, видимые пользователю;
  при лимите стабильные идут первыми (разгрузка главной);
- `::menu_items()` — постоянные пункты: Все сервисы, Тренды GitHub,
  Поиск вакансий, Графовый 3D-конструктор (с учётом видимости манифестов).
  Остальные сервисы — в каталоге и персональном «Избранном»; `pin` не расширяет меню.
- `::header_nav()` — чипы раздела для шапки текущей страницы (NULL вне каталога);
- `::picker_icons()` — иконки для пикера /prl118_links;
- `::visible_modules($ctx)` — манифесты, видимые пользователю (status/audience);
- `::search_json($ctx)` — JSON для палитры «Все сервисы» (кнопка в сайдбаре) и 3D-карты (`/prl110/api/catalog`);
  у item есть title/short/href/group/status и `api`: только относительные API-маршруты
  из манифеста (внешние и `//…` намеренно отбрасываются).
- `::groups_summary($ctx)` / `::group_modules($slug, $ctx)` — для страницы /services;
- `::user_context()` — guest/logged/roles/admin/agent текущего запроса;
- `::resolve_status($m)` / `::resolve_audience($m)` — статус/аудитория с фолбэками
  (badge/hidden → prl218 → дефолты); `::can_see($m,$ctx)` — матрица видимости.

## Жизненный цикл и аудитория (новые поля манифеста, опциональны)

```php
'status'   => 'beta',     // draft|beta|stable|deprecated (beta — фолбэк из badge)
'audience' => 'public',   // public|auth|admin|agent (auth — фолбэк для hidden)
'pin'      => TRUE,       // устаревшее поле; короткое меню не расширяет
```

- `sitemap` => ['/calendar/2026', …] — необязательный список ДОПОЛНИТЕЛЬНЫХ адресов
  модуля для `sitemap.xml` (страницы годов, разделов). Сам `href` попадает в карту
  автоматически, если модуль публичный (audience=public) и не draft. Собирает
  `Service_Prl602_Sitemap` (prl602_content); адрес — только `/путь` без query и `{шаблонов}`.
- `status='draft'` и `audience='agent'` — сервис «сырой»: агент/админ (роль `agent`
  или `?agent_preview=1`) работает с ним включённым, пользователям он не виден
  ни в меню, ни в поиске, ни в каталоге, ни в sitemap.
- `hidden` остаётся алиасом `audience='auth'` (аккаунтные страницы).
- Статус берётся в порядке: явный `status` → `badge='beta'` → prl218
  (`prl_218_modules.system_name`, `is_published`/`status`) → `stable`.
  prl218 влияет на видимость только когда там явное решение: published=1
  (маппинг текста статуса) или published=0 у не-alpha (снятие публикации).
  Автосозданные сканером записи `alpha+unpublished` = «решения нет» → stable.

## Страницы и маршруты модуля

- `GET /services` — SSR-каталог по группам (контроллер `Prl110_Catalog::action_index`);
- `GET /services/<slug>` — хаб группы (`action_group`, slug = group_slug);
- `GET /prl110/api/catalog` — JSON реестра видимых сервисов для палитры «Все сервисы» и `/orbit`.

## Контроллер сервиса при этом

```php
$this->set_menu(class_exists('Service_Prl110_Catalog')
    ? Service_Prl110_Catalog::menu_items()
    : []);
```

## Не делать

- Не редактировать `modules/`, `system/`.
- Не загружать манифесты через `Kohana::$config->load('prl_module')` — конфиг-каскад
  смёржил бы манифесты всех модулей в один массив. Только явное сканирование каталогов.
