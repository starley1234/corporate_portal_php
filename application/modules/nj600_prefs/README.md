# nj600_prefs — «Аккумулятор предпочтений»

Пассивный сбор контекста пользователя: **откуда пришёл** (referrer-хост, utm,
поисковая фраза внешнего поисковика), **что искал** (глобальный поиск), **какие и
сколько разделов смотрел**. Цель — переход от реактивного ИИ к проактивному
(задел под «Детектор контекста и намерений»).

## Экономия БД (требование владельца)

| Таблица | Что хранит | Рост |
|---|---|---|
| `nj_600_events` | сырое: страницы/фразы/referrer/utm | TTL `NJ600_RAW_TTL_DAYS` (21 дн.), чистится ~1% запросов + кнопка в админке |
| `nj_600_profile` | суммаризация на владельца: JSONB-счётчики разделов (кап 40), фраз (20), источников (10) | НЕ растёт: инкрементальный upsert по `owner_key` (`u:<id>` / `g:<ubid>`) |
| `nj_600_reco_rules` | правила администратора: советовать/не советовать href (всем, интересующимся разделом или одному владельцу) | единицы строк |
| `nj_600_reco_log` | показы/клики/отказы рекомендаций с причиной | 1 строка на владелец+href за 24 ч; чистка 90 дн. (/nj100/cleanup) |

## Точки сбора (пассивно, без JS, каждая в try/catch)

* `Erp100_Base::before()` — GET-страницы: раздел = первый сегмент URI;
* `Nj100_Api::action_search` — фразы глобального поиска.

## Точки выдачи

* `GET /prefs/api/profile` — свой компактный профиль (JSON);
* `GET /prefs/api/recommend` — свои рекомендации (JSON, с причинами); `GET /prefs/api/go?id=` —
  переход с учётом клика; `POST /prefs/api/dismiss` — «не предлагать»;
* `/nj600/admin` — админ (право `nj600.admin`): KPI, размеры, топ разделов/фраз, ручная очистка;
* `/nj600/admin/owner/<key>` — карточка владельца: предпочтения, последние действия
  (события, задачи воркеров, входы), что система ему предложит и почему; закрепить /
  запретить / отправить уведомлением. Вход — иконка-мозг у пользователя на `/nj595/admin`;
* `/nj600/admin/reco` — рекомендации под надзором: правила, CTR по источникам и сервисам, журнал;
* виджет «Вам может пригодиться» в кабинете `/dashboard` (`Service_Nj600_Reco::widget()`);
* MCP (nj160): `nj600_platform_top`, `nj600_profile_by_key`, `nj600_module_stats`, `nj600_recommend`.

## Как ранжируются рекомендации

1. **Правила администратора** (1000 + вес): адресные (владельцу) и общие («интересующимся
   разделом X → предложить Y»). Единственный источник, который может советовать уже
   посещённое и страницы вне каталога (с собственным заголовком).
2. **Похожие посетители** (100–200): среди владельцев с теми же топ-разделами — какие ещё
   разделы они смотрят (по числу владельцев, считается по компактным профилям).
3. **Тот же раздел каталога** (до 50): сервисы из группы топ-разделов владельца.

Не предлагается: посещённое, `block`-правила, отклонённое владельцем (60 дн.), скрытое из
каталога nj110 для его аудитории. Каждый показ пишется с причиной — администратор видит,
что сработало, и правит правила.

## Env

`NJ600_RAW_TTL_DAYS` — дни хранения сырья (по умолчанию 21, см. `.env.example`).
