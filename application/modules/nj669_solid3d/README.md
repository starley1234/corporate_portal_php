# 3D-детали — `/solid3d`

Один проект — одна параметрическая OpenSCAD-деталь, **не граф и не сборка**.
Любой вошедший может генерировать, уточнять с ИИ и пересчитывать код в рамках
квоты. Каталог и файлы опубликованной версии доступны без входа.

## Как пользоваться

1. «Создать»: описание детали (назначение, размеры в миллиметрах) и необязательное
   фото JPEG/PNG/WebP до 5 МБ и 24 Мп. Фото остаётся приватным. Название
   необязательно: без него берётся начало описания (или «Новая деталь» /
   «Деталь по фото»). Карточку каталога (название, описание, теги) подбирает ИИ
   сам после первой удачной сборки.
2. Если есть фото, VLM описывает его один раз. LLM пишет самодостаточный SCAD,
   воркер собирает STL, GLB и три ракурса OpenSCAD. Один запуск — одна сборка.
3. Автоисправление (0–2, настраивается) повторяет только ошибку сборки OpenSCAD:
   модель получает текущий код и текст ошибки. VLM на повторах не вызывается.
   Ошибка сборки не затирает прошлый результат.
   Проверку ракурсов ИИ запускает **администратор** отдельной кнопкой на странице
   детали: это отдельная задача `nj669.verify`, она не входит в генерацию,
   не тратит квоту владельца и не меняет геометрию или текущую версию. Пока
   проверки нет, карточка честно показывает «не запускалась», а не «проверено».
4. Вращайте GLB, включите размерную сетку/полноэкранный режим; скачайте STL,
   GLB или SCAD. Три ракурса доступны в раскрывающейся галерее: по ним администратор
   может запустить ИИ-проверку соответствия описанию.
   Уточняйте деталь запросом, числовыми полями или редактированием кода.
5. Размеры под свою печать: любой вошедший двигает ползунки (или вводит число,
   текст, выбирает пункт списка или ставит флажок) и нажимает «Собрать STL».
   Это временная выгрузка (`nj669.export`): файл живёт час по Москве, не попадает
   в историю версий, каталог и квоту, а версия и её JSON не меняются. Гость видит
   опубликованные размеры, но собирает STL только после входа.
   Владелец на черновой версии меняет её JSON кнопкой «Пересчитать» (без квоты).
5. История хранит каждую попытку. Готовую версию можно просмотреть, назвать, отметить контрольной точкой и восстановить.
   История листается страницами по 100 попыток, а не обрезается первыми 100.
   Каталог хранит отдельно утверждённую версию: приватные правки её не меняют.
6. «На модерацию» отправляет **текущую версию проекта**. Только модератор
   публикует/отклоняет её с комментарием. Вместе с версией фиксируются название,
   описание и теги: последующая правка черновика не меняет ни заявку, ни каталог.
   Владелец может снять публикацию.
7. «Использовать как шаблон» копирует опубликованный исходник в личный проект;
   его первое пересчитывание также расходует квоту. Чужие фото не копируются.

Фото не даёт точных размеров. VLM не измеряет допуски, прочность или
печатность. Проверьте миллиметры и сетку в слайсере перед изготовлением.
Цвет хранится в GLB, если OpenSCAD отдаёт VRML; STL цвета не хранит.

## Квоты и права

`nj669.start` — login/vip/admin; `nj669.moderate` — admin через общий ACL.
По умолчанию 20 активных проектов, 5 запусков за день по часовому поясу БД.
Генерация, ИИ-правка, ИИ-карточка и идеи делят квоту: это запуски с языковой моделью.
Карточку владельцу подбирает ИИ автоматически после первой удачной сборки (одна попытка),
администратор перегенерирует её своей квотой. Идеи модератора тратят квоту модератора. Пересчёт размеров и ручной пересчёт кода модели не вызывают и квоту не тратят. Неудачные попытки учитываются.
ИИ-проверка ракурсов (только администратор) квоту не тратит.
Копия шаблона (`job_id=0`) не считается запуском, её пересчёт — считается.
Автоисправления входят в один запуск. Администратор меняет общие значения
на `/solid3d/settings`, индивидуальные — на `/solid3d/limits?user=ID`.
Пустой индивидуальный лимит наследуется, ноль запрещает операцию; поля формы
изначально содержат действующие квоты конкретного пользователя.

Проект и квота блокируются транзакцией: одновременные запросы не расходуют
последний слот дважды. На проект возможна одна незавершённая сборка и одна рекомендация карточки.
После 35 минут незавершённая попытка закрывается ошибкой, старый callback
не может её воскресить. Живой статус получает этап и пульс через публичный
`JobQueue::status_of`, без SQL в таблицы очереди. Терминальная очередь закрывает
непринятую версию сразу; владелец может отменить свою сборку. Отмена закрывает
приёмную и удаляет частичные файлы, поздний ответ не заменит текущую версию.
Квота не возвращается; принудительная остановка процесса движка зависит от
общего воркерного механизма отмены. Удаление — с подтверждением вторым нажатием.

## Рабочее место, параметры и помощники

* Карточка каталога (название/описание/теги) пишется в черновик: владелец её не
  редактирует, администратор перегенерирует иконкой. Каталог, поиск и создание из
  шаблона читают утверждённый `published_meta`; модератор видит `review_meta`,
  захваченный вместе с `review_revision_id`.
* Размеры — карточка «Размеры» по образцу «Из чего печатаем» nj667. Типы полей
  берутся из размеченного заголовка SCAD:
  * `@param МИН МАКС ШАГ подпись` — ползунок и поле точного числа рядом;
  * `@bool подпись` — переключатель (`true`/`false`);
  * `@choice подпись | 1:Вариант | 2:Вариант` — выпадающий список; значение — число из списка;
  * `@text подпись` — строка до 40 знаков: буквы, цифры, пробел, `. _ -`. Строка не
    влияет на геометрию, потому что `text()` запрещён.
  Слоты значений хранятся в браузере (localStorage). Первая кнопка «По умолчанию»
  возвращает значения из исходника версии; «1», «2», «3» загружают, дискетка
  рядом сохраняет текущий набор.

  ```scad
  // @param 1 100 0.5 Толщина, мм
  wall=4;
  cube([30,20,wall]);
  ```

  До 24 полей. Конечные числа в границах ±1e6; min < max, шаг положительный.
  Шаг задаёт удобную сетку браузерного поля; сервер строго проверяет числовой
  литерал и диапазон. Имена и позиции берутся только из серверного исходника.
  Выражения, `$fn`, повторные присваивания заголовка и тело геометрии не
  редактируются формой. Старый код без меток доступен только модератору в служебном блоке.
  Новая сборка берёт исходник **выбранной версии**; текущую не заменяет до успеха.
* **Ползунки не создают новую версию.** Значения сохраняются JSON в колонке
  `params` той же версии (миграция 004; `pending_params` ждёт сборки). Пересборка
  идёт по этой же строке ревизии с тем же `revision.id`: новая строка истории не
  появляется, а `source`/`files` меняются только при успехе. Пересборка квоту
  не тратит: модель не вызывается. Версии в каталоге или на
  модерации размеры не меняются: сначала снимите с публикации.
* **Видимость.** Пользователю не показываются модели LLM/VLM, код SCAD, журнал
  сборки (`build_log`), ссылка на исходник и проверка ракурсов. Модератор видит
  код, модели, журнал, запускает проверку и удаляет чужие проекты. Файл `scad`
  отдаёт 404 не-модератору. Слово OpenSCAD в пользовательских текстах не
  используется.
* **Удаление.** Версию может удалить владелец или модератор, со вторым
  подтверждением. Нельзя удалить текущую, опубликованную, находящуюся на проверке
  версию, а также версию в очереди или в работе. Проект удаляют владелец или
  модератор: стираются все версии и файлы.
* Ответ помощника карточки пишет черновик сразу; публикацию не меняет. Перегенерация
  администратором заменяет поля черновика и расходует его квоту.
* `/solid3d/ideas`: модератор задаёт тему для пачки до 30 идей, добавляет,
  редактирует и двухшагово удаляет пресеты. Они появляются в форме создания
  у всех вошедших; чужие приватные проекты помощнику не передаются.
* Проверка ракурсов: канал `nj669.verify`, таймаут `verify_timeout_sec` (600 с),
  одна попытка. Зависшая проверка закрывается через 15 минут со статусом «ошибка».
* Помощники: каналы `nj669.ideas`/`nj669.caption`, один запуск очереди,
  максимум две попытки исправить JSON, общий бюджет 480 секунд, timeout задачи
  540 секунд. Сайт закрывает незавершённый помощник после 10 минут при следующем
  обращении, callback также проверяет возраст и terminal-состояние.
* `/solid3d/usage`: поиск по детали/запросу, фильтр состояния, превью и страницы
  по 24 сборки. У обычного пользователя только свои; у модератора все.
  Расходы и токены — в общей очереди; рекомендации видны в рабочем месте проекта.
* Принятый результат и callback ошибки сборки отправляют события
  `nj669.build.done/error` в центр уведомлений. Повтор callback не шлёт повторно.
  Доставка/каналы зависят от настроек центра и получателя; сбой уведомлений
  логируется и не отменяет принятую модель. Отмена/закрытие по дедлайну не
  отправляют отдельного модульного уведомления.

Графовые инструменты, спецификации сборок и отдельная ИИ-премодерация Graph3D
не перенесены: источник правды здесь — код одной детали, публикация ручная.

## Изоляция таблиц и исправление конфликта `project_id`

На действующей БД обнаружена другая `public.nj_669_revisions` со столбцами
`spot_id`, `scene_json`, `author_id`. Это история сцен, а не версия SCAD.
`CREATE TABLE IF NOT EXISTS` не меняет её структуру, поэтому прежняя `001`
падала при создании индекса по `project_id`. Не добавлять в неё фиктивный
`project_id`, не очищать и не удалять таблицу.

Solid3D теперь использует **`nj_669_solid3d_*`**: все семь таблиц, DDL/FK,
запросы сервиса, дожим очереди и очистка переведены на изолированные имена.
URL, ID проектов/версий, файлы `storage/nj669` и каналы воркера не меняются.

* После неудачной `001`: обновить код и повторить штатный накат миграций.
  Новая `000_Solid3dNamespace` выполняется перед `001`; с таблицей сцен она
  ничего не делает. Исправленные `001/002` создают только изолированные таблицы.
* Если ранние `001` или `001+002` Solid3D уже успешно применены: новая `000`
  опознаёт старую схему по полному набору столбцов **обоих** projects/revisions,
  проверяет остальные имеющиеся таблицы и переносит их через `ALTER TABLE RENAME`.
  Существующие данные, OID, ID, FK, токены задач и последовательности сохраняются.
  Записи о применении `001/002` не сбрасываются; повторять их вручную не нужно.
* Одновременные старые/новые таблицы или несовместимая вспомогательная таблица
  при опознанной ранней установке — явная остановка, не автоматическое слияние.
* `down` действует только на `nj_669_solid3d_*`. `000.down` намеренно пустой:
  обратно в потенциально занятые короткие имена ничего не переименовывается.

Подготовка `000` имеет номер ниже старых миграций намеренно: штатный мигратор
сортирует файлы и выполняет все неприменённые, а не только номера выше последней.
Схема старых `001/002` не расширена заново: исправлены только имена объектов
для ещё не применённых установок; перенос уже установленной базы — отдельная `000`.
После обновления кода перед миграцией, как обычно, сделать резервную копию БД.

## Развёртывание

Модуль включён в `application/bootstrap.php`, миграции `000`, `001` и `002` идемпотентны.
`002` дополняет существующую базу, не меняя `001`: backfill карточек берёт
имеющиеся название/описание, затем повторный up не затирает снимки.
Применить штатным `bin/console db:migrate`; перезапустить Python-воркер и
включить `nj669.generate`, `nj669.verify`, `nj669.ideas`, `nj669.caption`, если у него настроен ограниченный список каналов.
Манифест регистрирует сервис в каталоге, каналы в мониторе и события уведомлений, **не закрепляет**
сервис в левом меню.

Нужен OpenSCAD со встроенными примитивами, Pillow, headless OpenGL и Xvfb
(`xvfb-run`, как у существующего локального рендера). BOSL2 не требуется.
Общие таймауты сборки (1650 секунд), помощников (480 секунд) и проверки ракурсов (540 секунд) реализованы
через `asyncio.wait_for`, как в `BaseWorker`, а не через `asyncio.timeout`,
который появился только в Python 3.11. При истечении времени корутина конвейера
отменяется, сайт получает callback ошибки; внешний сигнал отмены не глушится.
После обновления Python-файлов нужен перезапуск процесса воркера. Уже закрытую
ошибкой версию не возобновлять повтором её job: создайте новый запуск в проекте.

`NJ669_OPENSCAD_BIN` → `NJ570_OPENSCAD_BIN` → штатный автопоиск/PATH.
На Linux `prlimit` ограничивает память, CPU и размер файлов дочернего движка;
таймаут каждого экспорта и общий бюджет действуют независимо.

`NJ669_API_BASE=https://n2j.ru/solid3d/w` — полный путь приёмной; воркер сам
добавляет `/context`, `/upload`, `/result` и т. д. Пустое значение берёт общий
`NJ120_API_BASE=https://n2j.ru` (только корень). Не записывать `/solid3d/w`
в общую переменную: иначе путь удвоится. Если уже задан `NJ120_API_URL`,
можно вообще не задавать отдельный адрес Solid3D.

HTTP 404 с HTML означает, что запрос не дошёл до нужного действия приёмной.
Общий HTTP-клиент теперь показывает фактический адрес без userinfo/query/fragment,
а не начало HTML. Проверить именно получившийся `/solid3d/w/context`, наличие
обновлённого модуля на сайте и кеш PHP/opcache. Приёмная имеет отдельный класс
`Controller_Nj669_Solid3dWorker` и имена маршрутов `nj669_solid3d_*`, чтобы
существующий `Controller_Nj669_Worker` другого сервиса не перекрывал её в CFS.
Это защита от конфликта имён, не доказательство причины конкретного серверного 404.
Без токена доступный маршрут отвечает **403 JSON**, не 404 HTML. Проверка без
секретов и изменения данных (выполнять на машине, где работает воркер):

```sh
curl -i -X POST -H 'Content-Type: application/json' \
  -d '{}' https://n2j.ru/solid3d/w/context
```

После обновления PHP-кода сайта и Python-кода/перезапуска воркера создать
новую задачу; миграций БД это изменение не требует.
`NJ669_SITE_TOKEN` — тот же секрет, что `WORKER_API_TOKEN` на сайте; обычно
достаточно общего `WORKER_SITE_TOKEN`. Никакого development-обхода авторизации.
Модели: `NJ669_MODEL`, `NJ669_VISION_MODEL` (последняя → общая `VLM_MODEL`).
Модель кода может быть текстовой: фотографии сначала интерпретирует VLM.
`NJ669_LIGHT_MODEL` — текстовая модель идей и карточек (пусто — дефолт LLM).
Модели и число починок можно переопределить через страницу настроек.

Хранилище — **`storage/nj669` вне public_html**, права 0700/0600, веб-процесс
должен уметь туда писать. Дефолты deploy/backup включают этот каталог;
при своём `DEPLOY_MODULE_STORAGE` добавить его явно. Файлы выдаются только
через контроллер с проверкой конкретной версии (владелец/модератор/публикация).
Выходной файл до 24 МБ. Файлы доставляются по одному через multipart, без base64-копий.
Для полного лимита 24 МБ нужны `upload_max_filesize=24M`, `post_max_size=32M`
и лимит тела HTTP не ниже 32 МБ (как у других крупных 3D-экспортов).
Токены в URL не принимаются; журнал не содержит тела запросов и фото.

После обновления проверить на рабочем окружении полный путь на простой
детали: описание → SCAD → OpenSCAD/Xvfb → GLB → STL → три ракурса. Отдельно,
по запросу администратора: VLM-проверка ракурсов (`nj669.verify`, таймаут 600 с).
Локальные тесты подменяют движок и AI: они не доказывают качество реальной
модели или наличие OpenSCAD на production.

## Повторное использование и границы

* `n2j_workers/glb.py`: общий STL/VRML → GLB, мм/Z-up, нормализация ASCII STL.
* `n2j_workers/scad.py`: общий headless-запуск, таймауты, семафор рендеров.
* `n2j_workers/solid.py`: безопасный встроенный SCAD и три ракурса.
* `assets/js/nj667-stl.js`: локальный проверенный просмотрщик Graph3D. Собственная
  вьюха NJ669 реализует его DOM-контракт (`#nj667-stl`, `data-src`, `data-kind`,
  `data-state=done`, **пустой data-status**); чужие контроллеры, таблицы,
  очередь сборки и view-файлы не используются. Сетка и Z-up → Y-up те же.
* `site.py`, `vlm.py`, `LlmClient`, `BaseWorker`/`usage.py`: общая доставка,
  изображения, токены/стоимость и этапы — без собственного параллельного учёта.

## Данные и API

Семь таблиц с префиксом `nj_669_solid3d_`: `projects`, `revisions`, `events`,
`settings`, `quotas`, `tasks`, `ideas`. Короткие `nj_669_*` сервис не читает.
Источник — SCAD в ревизии, файлы производные и привязаны к её ID.
Публичный ID и ID отправленной на модерацию версии не совпадают с указателем
на текущий черновик; это намеренная защита от утечки приватных правок.

`POST /solid3d/w/context|upload|result|fail`: `X-Worker-Token` и уникальный `run_token`
версии из payload. Повтор успешной приёмки идемпотентен. Сайт проверяет исходник,
подписи/размеры файлов и состояние версии до публикации указателя.
`POST /solid3d/w/assist_context|assist_result|assist_fail` использует тот же
worker-заголовок и отдельный токен задачи, без файлов.
`POST /solid3d/w/export_context|export_upload|export_result|export_fail` — приёмка
временного STL (`nj669.export`): токен выгрузки сравнивается через `hash_equals`,
файл пишется в `dir/x{eid}.stl` с правами 0600. Выдача: `GET /solid3d/x/<code>/<export>`,
только пока `expires_at > now()`, с `Content-Disposition: attachment`, создателю и
модератору. Просроченные файлы и строки чистит `purge()` при постановке и открытии страницы.
Веб-POST требует сессию, ACL и CSRF. Чужой приватный проект/файл отвечает 404.
Реестр cleanup чистит завершённые помощники и журнал и каскадно удалённые проекты старше 180 дней; удаление проекта сразу закрывает доступ и удаляет
файлы, сохраняя факт запуска для суточной квоты. Успешные версии не удаляются
по возрасту автоматически: они могут быть текущими или опубликованными.

Сохранённые идеи остаются после очистки задач (`ON DELETE SET NULL`),
удаляются модератором вручную. Никаких SQL к таблицам чужих модулей.
