## Что это

Личный инструмент владельца (audience admin): конвейер следит за прогрессом ИИ
и смежным — открытые модели и веса, фреймворки, окна возможностей (бесплатные
токены хороших моделей, щедрые лимиты, ранний доступ), прорывы с практической
применимостью, недооценённые ниши. Копит **базу знаний из фактов** (не воду),
использует её в конвейере (не делает работу заново и учитывает сделанное ранее),
присылает **письма** с отчётом и идеями, что реализовать на n2j (с пользой и
местом применения).

**Витрина для людей и поисковиков**: каталог опубликованных отчётов
`/airadar/catalog` (свежие сверху, поиск, пагинация) и страница отчёта
`/airadar/report/<id>` — они ПУБЛИЧНЫЕ, как у трендов. Отчёт публикуется по
умолчанию; владелец может снять его с публикации (тогда страница отдаёт 404
всем, кроме владельца и администратора). Всё остальное в модуле (прогоны,
материалы, база знаний, идеи, переключатель публикации) — под замком
`can('nj661.airadar')`.

Использованные наработки: nj593_trends и nj605_radar (конвейер воркера: ddgs +
webread + один LLM-вызов со строгой JSON-схемой, дедуп, живые этапы),
nj602_content (постановка задач по расписанию), nj654_similar (RAG-паттерн:
эмбеддинги + косинус для семантического дедупа фактов), nj613_digest (письмо
через nj597 + троттлинг).

## Конвейер

```
cron → /airadar/api/tick (токен) → tick(): пора? → run + JobQueue 'nj661.airadar'
  ↓ python-воркер nj661_airadar.handle(ctx, {run_id, limits})
  1. Источники (каждый в своём try): HuggingFace API (свежие/лайки),
     OpenRouter /api/v1/models (бесплатные = «окна», новые, 128k+), RSS
     гигантов (HF/OpenAI/DeepMind/Meta/Mistral/Qwen/Phoronix), ddgs-поиск
     («утка го»), lmarena.ai/leaderboard;
  2. POST /airadar/api/items → сайт дедупит по url_hash (готовое не возвращается,
     необработанные `new` повторяются; лимит после дедупа) + отдаёт контекст базы знаний;
  3. webread новых страниц (кап, бюджет, паузы);
  4. LLM-анализ батчами (строгий JSON): relevant/category/score/why,
     facts[{text,tags}] (не вода, с числами), ideas[{title,body,benefit,fit}];
  5. POST /airadar/api/analysis → факты/идеи в базу знаний (дедуп по хешу:
     факт повторился → sightings++, дубль не создаётся);
  6. POST /airadar/api/report_input → LLM пишет {title,summary,highlights} →
     POST /airadar/api/report → nj_661_reports + решение о письме
     (mail_due: троттлинг + порог скор/идеи) → Nj597_Mail;
  7. POST /airadar/api/finish.
```

## Правила модуля

- **Аудитория**: admin (личный инструмент). Страницы — `can('nj661.airadar')`
  (admin проходит всегда); API — токен воркера; cron дёргает `/airadar/api/tick`.
- **LLM и сеть** — только в python-воркере (канал `nj661.airadar`), не в HTTP.
  Модель — env `NJ661_AIRADAR_MODEL`, иначе дефолт воркера.
- **База знаний**: факт = нормализованный текст (fact_hash) + эмбеддинг
  (ctx.embed в воркере, хранение JSON-текстом) для семантического дедупа
  (косинус ≥ knowledge.dup_cosine → «уже известно»); недавние факты и частые
  теги — контекст промпта анализа («учитывать сделанное ранее»).
- **Письмо**: не чаще mail.every_days и только если есть находка ≥
  mail.min_score ИЛИ новая идея; адрес — mail.to_email (пусто = не слать,
  админка показывает подсказку). Кнопка «Прислать письмо» игнорирует троттлинг.
- **Дедуп работы**: материалы — по url_hash за всё время; идеи — по
  нормализованному заголовку (повтор поднимает скор, не создаёт дубль).
- **Публичные страницы — только по списку**: `_public_actions` в
  `Controller_Nj661_Airadar` (`catalog`, `report`); всё прочее падает 403
  гостю. Для гостя чипы модуля сужаются до «Отчёты», а в отчёте нет форм
  «прислать письмом» и переключателя публикации.
- **Публикация** — колонка `published` (миграция 002, DEFAULT TRUE) + POST
  `/airadar/report/<id>/publish` (два клика, янтарный тон). Снятый отчёт
  остаётся по прямому адресу у владельца и исчезает из каталога и карты сайта.
  Схема могла отстать от кода: `Service_Nj661_Airadar::_has_published()`
  спрашивает `information_schema`, а отсутствие колонки читается как
  «всё опубликовано» (умолчание) — каталог не падает 500-й.
- **Живой ход сбора** — правило 4 эталона: спиннер + этап + секундомер одним
  неразрывным рядом, полос хода нет, «сколько» — числом (текст счётчиков
  считает `counters_text()`, чтобы правило не дублировалось в JS).
  `run_progress()` отдаёт одну и ту же форму и разметке, и `/airadar/progress`:
  сам дашборд, `nj661-airadar.js` и JSON не расходятся.
- **PHP-ловушки**, которые здесь уже учтены (не возвращать): `$a = $x AND $y`
  присваивает ДО сравнения — только скобки или `&&`; `query()` у Request —
  вторым аргументом ПИШЕТ (сеттер) — читать одним аргументом.

## Расширение

- Новый источник: функция `_source_*` в воркере (try/except, пауза `_delay()`)
  + строка в списке источников `handle()`; для лент/запросов — env
  `NJ661_AIRADAR_RSS` / `NJ661_AIRADAR_QUERIES` («|»-список), кода не нужно.
- Новая категория анализа: ключ в `Service_Nj661_Airadar::$categories` +
  `_CATEGORIES` в воркере + порядок секций в `report_sections()`.
- Пороги/расписание/лимиты — `config/nj661_airadar.php` (воркер получает
  limits в payload задачи).

## Состояние работ

- **21.10.2026 (прогон #12: «остановлен» при готовом отчёте):** 284 кандидата,
  120 принято, 114 проанализировано, отчёт собран — а прогон закрылся `fail`
  из-за одного `ValueError: LLM не вернула items`. Причины и лечение:
  * разбор ответа чинит разнобой полей (`_normalize_row`: `relevant: "true"`,
    `score: "85"`, нет `ideas`, факт без `tags`) и спасает целые объекты из
    оборванного батча (`webread.json_objects`), а не выбрасывает всю пачку;
  * `strict`-повтор пачки просит «только JSON» явно в конце промпта;
  * серия сбоев считается только по сетевым/HTTP ошибкам
    (`NJ661_AIRADAR_MAX_FAILS`, 5), а не по неразобранному JSON;
  * неполный прогон закрывается `done`, если потеряно не больше 10% (минимум 3)
    материалов: число необработанных остаётся в `error`/сводке отчёта, на панели
    это жёлтая заметка, а не красная ошибка; `fail` — при большой потере или
    нуле разобранного;
  * в stats: `aborted` (`deadline` | `provider`), `last_analysis_raw`
    (первые 400 символов ответа модели) и `last_analysis_model`.
  **Правило:** «не обработано N из M» при готовом отчёте — не провал прогона;
  провал — когда терять уже нечего показывать.

- **15.10.2026 (вечер, рассуждающая модель):** живой прогон #10 упал с «LLM не
  проанализировала ни одного материала», в логе модели `finish_reason=length`,

  (`NJ661_AIRADAR_THINK`: auto | 0 | 1, конфиг `limits.think`). Провайдер,
