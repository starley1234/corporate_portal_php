## Контракт

- Страницы: `GET /meal` (съёмка + профиль), `GET /meal/<id>` (разбор).
  Профиль передаётся в query: `sex` (m|f), `weight`, `height`, `age`,
  `activity` (low|light|medium|high), `goal` (loss|keep|gain). Чужой разбор
  не показывается: аккаунтная запись требует тот же `user_id`, а анонимная —
  тот же непустой `visitor`. История показывает последние доступные записи;
  `POST /meal/<id>/delete` удаляет свой терминальный разбор с CSRF.
- API (`Controller_Nj651_Api extends Controller_Vision_Base`):
  `POST /meal/api/photo` → `{ok, run_id}`; от гостя — 401 + `login`
  (ключ `auth`, 06.10.2026); `GET /meal/api/status?id=`; приватный
  `GET /meal/api/preview?id=` (проверка владельца);
  `POST /meal/api/photo_file` и `POST /meal/api/worker_result` — для воркера.
- Сервис `Service_Nj651_Meal`: `shape`, `balance`, `profile`, `norm`, `share`,
  `verdict`, `num`, `pct`, `dishes_word`; константы `KCAL_PROTEIN/FAT/CARBS`
  (4/9/4), `ACTIVITY`, `GOALS`, `DEFAULT_PROFILE`.
- Таблица `nj_651_runs` (миграция `pgMigration_Nj_651_001_Meal_Runs`).
- Конфиг `config/nj651_meal.php`: `limits.photo_mb`, `limits.per_hour`.

## Правила для агента

- **Калории считает сайт, а не модель.** `shape()` пересчитывает ккал по БЖУ
  (4/9/4) и, если ответ модели расходится больше чем на треть, берёт свой
  счёт. Модели свойственно называть круглые числа «из памяти»; БЖУ она
  оценивает заметно честнее.
- **Профиль не сохраняем.** Пол, вес, рост и возраст — чувствительные данные;
  они живут в адресе страницы и в базу не попадают. Не заводить таблицу
  профилей и cookie «мой вес».
- **Честность важнее красивой цифры.** На странице обязана оставаться оговорка
  про ±20–30 % и про то, что масло в сковороде по фото не видно, а блюда с
  низкой уверенностью помечаются словом «под вопросом».
- Это не медицинский сервис: формулировок «вам нужно съесть», «норма для
  диабетиков» и любых диагнозов быть не должно.
- Оригинал кадра удаляется после разбора; маленькое JPEG-превью истории
  хранится вне docroot до 90 дней и доступно только владельцу через API.
  Каталог превью — 0700, файл — 0600; setup/deploy закрывают весь `storage`
  owner-only. Не добавлять публичный URL или исходное фото в БД.
- Вся запись в БД — через `Vision`/сервис модуля; таблица только `nj_651_*`.
- Полос прогресса нет: пока идёт разбор, работает общий статус-ряд
  (`partials/live_status`).
- Общий слой делят nj650, nj651 и nj652: правка там затрагивает все три.

## Как тестировать

- Чистая логика: `php tests/mini_runner.php MealService`.
- Владение API превью, gate и рендер VLM-страниц:
  `N2J_ROOT=<repo> node /tmp/phpwasm/phpwasm_stand.mjs .tools/nj650_vision_gate_stand.php`.
- JPEG, права preview и уборка временных файлов:
  `N2J_ROOT=<repo> node /tmp/phpwasm/phpwasm_stand.mjs .tools/nj651_preview_stand.php`.
- Режимы runtime/storage и закрытый backup:
  `bash .tools/nj651_storage_stand.sh`.

## Куда развивать

- Поправка веса порции руками с пересчётом БЖУ.
- Подсказка «чего не хватает»: белка мало, углеводов много.
