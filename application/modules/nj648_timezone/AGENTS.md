# Созвон по часовым поясам (модуль 648) — памятка для агентов

Публичный сервис N2J (группа «Даты и время»): текущее время участников из
разных поясов и сетка суток, в которой видно, какой час попадает в рабочий
день сразу у всех. Опорный город — первый участник, по его времени строится
таблица.

## Контракт

- Страница: `/timezones?p[]=moscow&p[]=berlin&p[]=newyork&date=2026-10-05&from=9&to=18`
- API: `GET /nj648/api/now` (время сейчас), `GET /nj648/api/slots` (сетка и
  общие окна), `GET /nj648/api/cities` (коды городов). Параметр `p[]` — код
  города из конфига или зона IANA (`Asia/Tokyo`).
- Сервис: `Service_Nj648_Timezone` (`cities`, `grouped`, `resolve`, `people`,
  `now`, `grid`, `offset_text`, `diff_text`, `hour`, `date`, `weekday`,
  `is_weekend`, `max_people`).
- Справочник городов, рабочий день по умолчанию и потолок участников —
  `config/nj648_timezone.php`. Таблиц, миграций и очередей нет.

## Правила для агента

- **Смещения не хранить.** В конфиге только названия зон IANA; «UTC+3»
  считает PHP на дату встречи. Иначе каждое решение о переводе стрелок (а они
  случаются: Казахстан 2024, Волгоград 2020) придётся догонять руками.
- **Сетка идёт по отметкам времени, а не по «+1 час» к локальной дате.**
  В ночь перевода стрелок локальный час повторяется или пропадает — отсчёт от
  `getTimestamp()` это переживает, наивное сложение дат — нет.
- Один `tz` у нескольких городов — норма (Москва и Санкт-Петербург). Ключ
  справочника — код города, а не зона: человеку показываем город.
- Участники разводятся по повторам и обрезаются по `max_people`: 24 строки ×
  девять колонок на телефоне не читаются.
- Рабочий день «через полночь» (с 22 до 6) намеренно не поддержан: `grid()`
  приводит `to` к `from + 1`. Понадобится — делать отдельной веткой с тестом.
- Полос прогресса на странице нет (корневой AGENTS.md, п. 10): рабочее время
  отмечается цветом строки и галочкой, не шкалой.
