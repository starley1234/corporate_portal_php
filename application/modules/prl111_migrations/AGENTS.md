# AGENTS.md — prl111_migrations (миграции БД)

> Памятка агенту. Общие правила платформы — в корневом /AGENTS.md.

## Назначение
Система миграций PostgreSQL: накат/откат/статус миграций всех модулей
(`migrations_pg/pgMigration_*.php`), CLI-задача `db:migrate`.

## Состояние
- Готовность: рабочий; это ядро работы со схемой БД.

## Ключевые классы
| Класс | Роль |
|---|---|
| `Service_Prl111_Migrator` | сканирование модулей, накат/откат, таблица учёта `migrations_pg` |
| `Model_Prl111_Migration` (abstract, alias `pgMigration`) | база миграций: `run_query()`, `run_script()` (многооператорный SQL), `select_query()`, `create_table()` |
| `Task_Db_Migrate` | CLI: `bin/console db:migrate [--status|--dry-run|--down=класс]` |
| `Controller_Prl111_Migrate` / `_Api` | веб-запуск: только DEVELOPMENT или по токену `MIGRATIONS_TOKEN` |

## Таблицы
- `migrations_pg` — журнал применённых миграций (класс, модуль, время).

## Соглашения (критично!)
- Файл и класс миграции совпадают: `pgMigration_Prl_<id>_<NNN>_<Название>.php`.
- Порядок применения = порядок модулей в `application/bootstrap.php`,
  внутри модуля — по имени файла.
- Миграции идемпотентны (`IF NOT EXISTS`); **применённые не редактируются**.
- DDL в транзакции (PostgreSQL умеет) — одна миграция = одна транзакция.
- Многооператорный SQL (heredoc, дампы .sql) — только через
  `run_script($sql)`: разрез по «;» учитывает строковые литералы и «-- …».
  Ручной `explode(';', …)` запрещён — «;» внутри `COMMENT … IS '…; …'`
  роняет накат «незавершённая строка в кавычках» (prl661/001, 06.10.2026);
  ловит `php_migration_lint`. Стенд механизма — `.tools/prl111_migrations_stand.php`.

## Не трогать / подводные камни
- Не менять порядок модулей в bootstrap.php бездумно — это порядок миграций.
- Драйвер PostgreSQL (`application/modules/PostgreSQL/`) не биндит параметры —
  в миграциях значения интерполируются/квотируются вручную.

## 2026-09-22 — починка db:migrate (CLI)

- `Task_Db_Migrate` вызывал несуществующий `$this->_flag()` — фатал при любом
  запуске `bin/console db:migrate` (и на проде: deploy-пинок писал «ОШИБКА»).
  Миграции применялись только через веб-консоль `/migrate_pg`.
- Добавлен хелпер `_flag()`. **Нюанс Minion:** голый `--status` = NULL,
  `--status=1` = '1'; семантика — NULL/('1','true','yes','on') = TRUE.
- Бонус после починки: на свежей БД найдены и исправлены проблемы порядка
  миграций (см. bootstrap.php — prl208_events подключён ДО prl120_jobs;
  миграция prl120/006 выравнивает sequence после 004 с явными id).
