# NJ-640 · Камеры цеха

Контроль видеонаблюдения цеха/офиса на VLM: **трудовая дисциплина**,
**средства защиты (СИЗ)** и **загрузка оборудования**.

Кадр камеры снимается по триггеру (таймер через cron `nj603`, webhook от
датчика/ПЛК, ручной тест), анализируется vision-моделью и проверяется
выходной JSON-схемой сценария. Нарушения попадают в журнал событий с
дедупликацией и cooldown, уведомлениями через `nj597` и подтверждением
оператора («подтверждено» / «ложная тревога»).

Страница сервиса: `/cameras`. JSON API: `/cameras/api/…` (см. `AGENTS.md`).

## Быстрый старт
1. `make migrate` — применить миграцию `pgMigration_Nj_640_001_Cameras`.
2. Запустить воркер с каналом `nj640.analyze`
   (см. `workers/.env.example`, блок `NJ640_*`).
3. На `/cameras` создать сценарий (пресет темы или свой текст/схему) и
   привязать камеру (snapshot/rtsp/onvif/http + триггер + часы работы).
4. Добавить расписание `cameras` (nj603_kicker) — уже предустановлено.

## Локальные камеры
По умолчанию захват закрыт для локальных/петлевых адресов (SSRF-защита).
Для камер в заводской сети установите `NJ640_ALLOW_LAN=1` у ВОРКЕРА.

## Безопасность
Rate limit, SSRF-запреты на воркере, валидация схемы без eval, секреты только
из `.env`, пароли камер не отдаются в UI. Подробности — `AGENTS.md`.
