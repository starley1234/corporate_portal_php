## Назначение
Фундамент приложения: базовый контроллер всех страниц (шаблон, меню, ACL),
аутентификация (Kohana Auth + OAuth Яндекса), модели пользователей и ролей.

## Состояние
- **17.11.2026:** `after()` только для HTML вошедшего пользователя получает
  видимое Избранное через публичный `Service_Prx110_Favorites` и передаёт его
  шаблону и карточкам до рендера; ответ не кэшируется. Сбой БД логируется и
  показывается в sidebar, но не блокирует страницу миграций. API без шаблона
  не выполняет эту выборку. Принудительный выход прерывает запрос редиректом,
  который нельзя поглощать общим `catch`; API каталога отвечает при этом 401 JSON.
- **07.10.2026:** серверная подсветка пунктов sidebar понимает `active_paths`;
  шаблон сохраняет и восстанавливает `scrollTop` навигации между переходами
  по ссылкам, чтобы длинное меню не прыгало к началу.
- Готовность: рабочий костяк, используется всеми модулями.
- ВАЖНО: таблицы users/roles/user_* БЕЗ префикса — legacy ядра; переименование
  согласовывать отдельно (затрагивает Kohana Auth).

## Ключевые классы
| Класс | Роль |
|---|---|
| `Controller_Prx102_Base` | база всех страничных контроллеров: шаблон, title/styles/scripts, меню, ACL, `can()`, `has_role()`, `is_owner()`, глобальные view-переменные (current_user и др.) |
| `Controller_Prx102_Auth` | вход/выход/регистрация/OAuth |
| `Model_Prx102_User`, `_Role`, `_User_Profile`, `_User_Setting`, `_User_Oauth` | ORM-модели (таблицы `users`, `roles`, `user_*`) |

## Таблицы
- `users`, `roles`, `roles_users`, `user_tokens` (Kohana Auth ORM), `users_oauth`,
  `user_profiles`, `users_settings` — без префикса (см. выше). Не добавлять сюда
  новые сущности без обсуждения: бизнес-данным место в модулях `prxXXX_*`.

## Маршруты и API
- `/auth/*` — вход, выход, регистрация, OAuth-колбэки.
- Базовый контроллер задаёт контракт для ВСЕХ страниц: наследоваться от
  `Controller_Prx102_Base` (или `Controller_Base`).

## События
- Публикует/потребляет: логин/логаут — через шину prx208 (см. init/код).

## Не трогать / подводные камни
- Не менять контракт `before()` базового контроллера «между делом» — от него
  зависят все модули.
- Проверка прав: централизованно `$this->can($ability, $object)`; не писать
  свои разрозненные проверки ролей в контроллерах.
- Пароли: только через Kohana Auth (`AUTH_HASH_KEY` из .env).

## 2026-09-22 — CLI-создание пользователя (Task_Auth_User)

- Добавлена Minion-задача `Task_Auth_User` (`classes/Task/Auth/User.php`):
  `bin/console auth:user --email=... --password=... --username=... --admin`.
  Команда упомянута в README/Makefile/restore-env.sh, но класса не было —
  «not a valid minion task» (make seed не работал никогда).
- Создание — как в prx595 (ORM Auth хэширует пароль, роли login+admin).
- `email_confirmed = 1` ставится сразу: CLI-сид без письма-подтверждения,
  иначе логин блокируется «подтвердите ваш email».
- **Урок по Minion:** голый флаг `--admin` приходит в задачу как NULL
  (не TRUE!); отсутствующий — FALSE (дефолт $_options). Булевы флаги
  проверять через `=== NULL || in_array((string)$v, ['1','true','yes','on'])`.

## Граница HTTP (23.11.2026)

Общий HTTP-контроллер не обслуживает очередь и не пишет диагностический кэш
классов. Обслуживание — `portal:maintain` по таймеру.

UI требует CSRF независимо от Authorization/X-Worker-Token. Базовый `machine_request()` возвращает FALSE; исключение разрешено только endpoint с обязательной собственной аутентификацией.
