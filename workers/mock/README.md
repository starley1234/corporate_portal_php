# Мок-серверы AI для локальной разработки

Полноценная проверка конвейера LLM/эмбеддингов **без GPU и внешних API**:

```bash
python3 workers/mock/mock_llm_server.py     # OpenAI-совместимый чат, :1234
python3 workers/mock/mock_embed_server.py   # OpenAI-совместимые эмбеддинги, :1235
```

В `workers/.env`:

```
TOOLFORGE_API_URL=http://127.0.0.1:1234/v1
EMBEDDING_API_URL=http://127.0.0.1:1235/v1
```

Ответы детерминированные (хэш текста → вектор; пересказ сообщения → чат),
поэтому тесты повторяемы. В проде эти URL указывают на настоящие сервисы.

## Строгие JSON-схемы и оффлайн-веб: сквозные прогоны конвейеров

Конвейеры prx598/prx591/prx592/prx602 ждут от модели строгий JSON, а эхо-ответ
мока их ломает. Два крючка для полного e2e без сети:

**1. `MOCK_LLM_REPLY_FILE=/path/reply.json`** — мок-LLM отвечает содержимым
файла verbatim (обёртка OpenAI сохраняется). Для каждого конвейера — свой
файл ответа (запуск: свой инстанс мока с нужным портом/файлом).

**2. `PRX_WEBREAD_MOCK=/path/web.json`** — оффлайн-поиск и страницы
(`workers/prx_workers/webread.py`):

```json
{
  "search": [{"q": "подстрока запроса", "results": [{"title": "...", "url": "...", "body": "..."]}],
  "pages": {"https://example.com/page": "<html>…"}
}
```

Поиск матчится нормализованно (без кавычек «»/" и лишних пробелов), первый
совпавший блок побеждает; страницы — точный URL, отдаются до любого DNS/сети.
URL фикстуры должны быть публичными хостами (assert_public_host всё равно
проверяет их для поисковых результатов). В проде обе переменные не задаются.

Проверенный оффлайн-сценарий «Разведка контрагента» (22.09): prx598 досье →
prx591 профиль по домену → prx592 письмо по профилю — все три `done` за ~15 с.
